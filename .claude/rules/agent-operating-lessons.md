- [Freshness is relative to the SUBJECT, not the clock](.) — 2026-09-09, `bin/cc-classify` gaining a `blocked-on-permission` cause (landed b1897fdb8): a store with a liveness heartbeat lets a consumer tell "nothing pending" from "the producer never ran", and the obvious reading of that heartbeat — *is it recent?* — is the wrong one. What a consumer actually needs is whether the observer was running **at the moment its SUBJECT could have produced a record**, so the comparison is `heartbeat_mtime >= subject's last activity`, never `now - heartbeat_mtime < some_bound`. An absolute bound answers a question about the BOX and gets read as an answer about the SESSION: on a quiet machine every heartbeat goes stale while the fleet is perfectly healthy, and on a busy one a heartbeat written by some OTHER session one second ago "proves" an all-clear for a session that went silent an hour earlier under a dead hook. The subject-relative form is immune to both because it is a statement about one timeline. Generalises to every absence-is-evidence read: a poller's last-run stamp, a sweeper's cursor, a watcher's mtime — ask *"was it observing when the thing I care about would have happened?"*, not *"did it run lately?"*.
