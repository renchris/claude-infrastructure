README hero banner — medium comparison

Three prototypes, one composition. Measured 2026-07-29 · rendered exactly as GitHub does, <img> with the SVG as an image.

A

Vector starburst

9,365 bytes

Hand-authored CSS keyframes over eleven tapered rays. Resolution-independent; composites at the browser's own frame rate.

assets/banner/proto-a-vector.svg
B

Moving ASCII — fine grid (45×25)

12,322 bytes

The same choreography with the mark drawn as a monospace character field, plus a per-character density flash on each beat. Reads as a mark; the characters do not resolve as characters at this size.

assets/banner/proto-b-ascii.svg
B2

Moving ASCII — coarse grid (25×15)

10,260 bytes

The same thing with glyphs large enough to read AS glyphs. The characters resolve; the mark stops holding together. This is the ASCII trade-off, not a tuning miss.

Notes

Nothing loops. Each banner plays its 8 s story once and holds. The resting frame is the deliverable; the animation is a bonus for a reader who happens to be looking.
Reduced motion. Under prefers-reduced-motion: reduce every prototype freezes into that same resting frame — verified pixel-identical, not a degraded fallback.
One committed look. These are dark plates rather than a <picture> theme split, because prefers-color-scheme follows the reader's OS, not GitHub's theme toggle — a reader on OS-light with GitHub-dark would get a light plate on a dark page. Use the theme toggle above to judge both.
