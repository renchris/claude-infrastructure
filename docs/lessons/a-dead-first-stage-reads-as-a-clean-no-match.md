# A dead first stage reads as a clean "no match"

[A dead first stage reads as a clean "no match"](.) — 2026-09-11, found twice in one day in land-gate ratchet lints (test-walltime-lint's future_dates, utc-stamp-lint's lying_stamps): under pipefail a pipeline reports its RIGHTMOST non-zero stage, so when stage 1 of `grep X "$f" | grep -v Y | …` cannot run (rc 2) it hands the next grep an empty input, that grep answers an honest rc 1 ("no lines"), and the pipeline reports 1 — which a caller reading 1 as "answered, nothing found" turns into a PASS for a file the scan never read. walltime even had an rc-3 could-not-run contract that this made unreachable. The mirror of the grep -q SIGPIPE inversion (there a consumer kills a producer; here a producer dies and a consumer's honest "empty" covers for it). ⇒ read `PIPESTATUS` right after any multi-grep pipeline whose rc 1 is a verdict (`for s in "${PIPESTATUS[@]}"; do [ "$s" -le 1 ] || rc=3; done`), or capture stage 1 alone and check it; the control that separates the cases is a shim failing ONLY stage 1 for one file.
