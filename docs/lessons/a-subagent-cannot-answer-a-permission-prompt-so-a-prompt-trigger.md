# A subagent cannot answer a permission prompt, so a prompt-triggering command in a brief is a silent deadlock

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A subagent cannot answer a permission prompt, so a prompt-triggering command in a brief is a silent deadlock](.) — 2026-09-16, kitty drag research (workflow wf_88c74054-db1): three of twelve research agents issued a Bash command opening with `rm -rf <scratch dir>` — an ordinary, correct cleanup — and this box's PreToolUse hook escalates `rm -r` on a non-build-artifact target to an ASK. **A subagent has nobody to answer an ask**, so the tool call never returns: the agents sat 35+ minutes with their last transcript record a pending `tool_use`, no child process, no directory created, and no error anywhere. Because those three were stages of a `pipeline()`, the barrier before synthesis could never resolve, so the synthesis agent never spawned and the whole wave read as "still running" — 12 of 12 artifacts written and sitting on disk while the run produced nothing. 🚨 **The diagnosis is cheap and the wrong diagnosis is expensive**: a hung agent and a working one look identical from the outside (transcript size frozen, parent shell accruing no CPU — see [A driver shell's own CPU is not its pipeline's progress]), so the discriminator is to SAMPLE FOR THE WORK ITSELF — `ps` for a compiler/tar/go child, and `ls` the directory the command claims to create. Zero children across repeated samples plus an absent output directory is a wedge, not slow work; one sample of either proves nothing. ⇒ **Ban prompt-triggering commands IN THE BRIEF, in words, at the top** — `rm -r`, `git clean`, `kill`, `pkill`, and anything the local hook layer escalates — and say WHY, because an agent told only "don't" will reach for the same idiom under a different spelling. Recovery, if it happens anyway: the per-agent artifacts are already on disk and the structured returns are in the workflow's `journal.jsonl` (`{"type":"result"}` rows), so `TaskStop` the run, harvest both, and re-run ONLY the downstream stage — nothing is lost but the wall-clock. Same family as [Fire verdict ≠ peer state] and [A gate refusal is not a gate result]: an orchestrator observing a subject indirectly reports its own failure to observe as the subject's failure to finish.
