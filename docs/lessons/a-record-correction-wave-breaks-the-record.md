# A record-correction wave breaks the record

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A record-correction wave breaks the record](.) — 2026-09-16, kitty-drag W1 (`fe1d82342`), caught by its own adversarial verifier: the wave whose entire purpose was *"fix the record before anything is posted or landed"* inserted 49 comment lines into `config/kitty.conf` and re-pinned **not one** `file:NNN` citation into it — so 37 citations across 12 files silently moved, **three of them inside W1's own newly-written correction prose.** The verifier's sentence is the whole finding: *a record-correction wave that broke the record.* ⇒ **Inserting lines into a file invalidates every line-number citation INTO that file, and the wave least likely to check is the one whose subject is citation accuracy** — because its attention is on whether each cited FACT is true, which is a different question from whether each cited ADDRESS still resolves. After any insertion into a cited file, compute the old→new map from the real diff hunks (`git diff -U0 <base> -- <file>`, then accumulate `new_len - old_len` per hunk) and re-pin; do not eyeball it. Three separable companions, each paid for the same hour: **(a) the fix's own documentation can cause the next round of rot** — a "line numbers shifted, here is the map" note belongs at **EOF**, because a note at the top shifts every line below it and invalidates the very map it carries. **(b) Scope the re-pin by LIVENESS, not by count.** A citation in a *dated* research document was correct when written and is a record; a citation in a live plan, a script or a test is an address someone will follow. Re-pin the live corpus, leave the dated records, and publish the map so the records stay translatable — rewriting eight historical documents for pointer hygiene is scope metastasis wearing diligence's clothes. **(c) Check whether the stale citations are EXECUTED before pricing the urgency.** All 37 here turned out to be prose in comments, so nothing could break and no land was at risk; had any been a real lookup in a test or a deploy script it would have been a land-blocking defect rather than a bad pointer. One grep separates those two worlds, and the difference in response is total. ⇒ The durable prevention, not just the cure: **prefer a stable anchor — a unique string, a section heading, an option name — over a line number in anything meant to outlive a single commit.** A line number is a PERISHABLE POINTER into a living file, and this repo's own corpus already knows the shape (`[Stale test inverts]`, `[Ref may be pre-fix]`, the ship-policy table that names no repo); citations into config files are the same class and had no rule.
