# Re-run the probe on the OLD binary too

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Re-run the probe on the OLD binary too](.) — 2026-09-09, cc-backlog `1ea55b6ad9f3` (landed 07ffe97f1): a negative measured ONCE can be an **instrument error**, and the only cheap thing that separates that from a real version change is re-running the same probe on **the binary the original was measured against**. `docs/research/recycle-100p-2026-08-22.md` §2.4 recorded *"Neither Ctrl-U nor Esc clears the composer — there is NO safe programmatic scrub"* (probe P2, 2.1.220). Re-measured on 2.1.260 it was false; had I stopped there, the natural write-up is *"a later release fixed it"* — a plausible-sounding repair that leaves the original instrument uninspected and teaches the wrong lesson. Running the 2.1.220 arm as well returned a **byte-identical** column: Ctrl-U CLEARS on both, so the claim was wrong when it was written. ⇒ **a disagreement between an old negative and a new positive is not evidence about VERSIONS until you have run both arms** (this file's own headline entry makes the same correction twice, first generalising a negative to the SURFACE and then to a VERSION RANGE — the third instance is above). Three companions, each separable: **(a) A probe with no negative arm proves nothing when it says yes.** Esc reproduced as INERT in the same run, which is what makes "Ctrl-U CLEARS" a reading rather than a stub returning success; the original had no such control, and that is the likeliest reason it went wrong. Ship the instrument (`docs/research/composer-scrub-2026-09-09/`) so the claim is re-derivable rather than quotable — the same reason the ship-policy table names no repo. **(b) A clause derived from a false negative COMPOUNDS into architecture, and the tell is a guard that can only ever refuse.** "No safe scrub" became "on any mismatch, touch nothing and escalate", which became a composer gate with no accepting path — measured at 4h+ of dead drain chain whose only symptom was absence, misdiagnosed as a slow link because the session kept accruing CPU (an idle-at-prompt session does too, so CPU cannot separate working from blocked). ⇒ when you meet a gate that has no path to yes, audit the measurement under it before building around it. **(c) A cure needs an ATTRIBUTION axis, not just a capability.** Knowing Ctrl-U clears does not license clearing: an operator's draft must still defer. Attribution came free at one call site (the pre-paste gate had just proven the composer empty, so the residue is ours by construction) and needed a content-keyed receipt at the other — content-keyed precisely so a stale receipt cannot authorise clearing text that no longer matches it, which is why it needs no TTL and cannot rot into a licence.
