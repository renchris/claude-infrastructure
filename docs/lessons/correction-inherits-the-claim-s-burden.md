[Correction inherits the claim's burden](.) — 2026-09-08, backlog `170a3b38f8c9` (closed REFUTED; ruled DROP as decision `a90e1ac2597e`), the third cycle of one idea: **refuting one OBJECTION to a claim establishes ¬objection, never the claim — and the measurement taken in service of that objection outlives it.** `9737a84c` ran the gating experiment properly, with a positive control: a minted `setup-token` got **HTTP 403** at `/api/oauth/usage` where a full-scope keychain bearer got **200**. It concluded "Method A is dead" because a 403 there would blind `/accounts`. `dd02f7df` refuted that conclusion and was RIGHT to — `claude-accounts` bearers the credential it read from the Keychain, never the env var — but then published *"ADDITIVE … at no cost to quota or routing"*, which the backlog row compressed to **"at zero cost"**, and a fresh worker was dispatched 36 days later to act on it. The 403 was never an argument about quota: it was direct evidence the token is **scope-narrowed at the server**, and it survived the correction fully intact while being demoted to a footnote about one untested scope, because the objection it had been ATTACHED to had fallen. Nobody then asked what the other three scopes cost. ⇒ when a correction rescues a claim, **re-file every surviving measurement under its own heading before closing it**, and state explicitly which objections remain untested — a correction that names only what it refuted reads as an all-clear. (Opposite direction, landed the same week: *cause refuted ≠ effect discharged*, line above — there the cause died and the effect lived; here the objection died and the evidence lived.) **Second half, mechanically separate and equally reusable: a credential source that TAKES PRECEDENCE is not a fallback.** Both prior sessions modelled env token and keychain as *"separate stores that never touch"* — true of the external reader and merely ASSUMED of every other consumer. In-session the resolver opens `if (CLAUDE_CODE_OAUTH_TOKEN) return {…}` and the keychain read below is unreachable, so the "insurance" engages on EVERY launch and the primary becomes unreachable, rather than engaging when the primary fails. ⇒ before calling any supplementary token/config/env source "insurance" or "a fallback", read the resolver's **return order**; and a grant narrowed by the AUTHORIZE request (`inferenceOnly ⇒ scope=[user:inference]`) cannot be widened by a client-side scopes env var, which only changes what the client BELIEVES and converts clean local disables into server 401s.
