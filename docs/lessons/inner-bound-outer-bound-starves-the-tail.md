# Inner bound > outer bound starves the tail

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Inner bound > outer bound starves the tail](.) — 2026-09-09, GUARDRAIL_HOOKS_V2 AC2' (landed): when a serial pipeline has BOTH a per-arm bound and a whole-pass bound, an arm bounded at X inside a pass that ends itself at Y < X can consume the entire pass, and every phase below it is then unreachable BY CONSTRUCTION — no re-measurement of the arms above can fix it, because both bounds are individually CORRECT. `autonomy-sweep.sh`: §0a's cloud-return is bounded at 900 s (correct — a smaller bound convicts a healthy land, its own 240 s incident) inside a tick self-bounded at 400 s (correct — cc-reaper is the job's only watchdog and may not be exempted), so from the day the self-bound landed (`a7e5a609e`, 09-07) the pass's whole lower half went from ~20 runs/day to **0**: §2, §2b(+i..vi), §2c, §2e, §2f and §3 — including §3, the summary and desk NOTIFY. **The tell is the yield checkpoint's own histogram, and it is cheap:** over 49 self-bound rows `stopped_before` was one of the two EARLIEST checkpoints 49/49 times and no other value ever appeared; elapsed at yield min 422 s / median 1009 s / max 4883 s against a 400 s bound. A distribution with no mass past the first checkpoints is arithmetic, not load — a busy box would spread it. The sweep's own note already prescribed "re-measure the arms above", which is the right instinct and the wrong remedy here: **only ORDER reconciles 900 with 400.** ⇒ whenever you add a whole-pass bound to a pipeline that already bounds its parts, assert `max(per-arm bound) < pass bound` or accept that the pass is now a prefix; and read a `stopped_before`/`phase` histogram before re-measuring anything. Companion (same session, mechanically separate): **a rebase conflict where BOTH sides appended blocks at EOF has a shared trailing delimiter** — the `}` after the `>>>>>>>` marker closes only the LATER side's final block, so a correct-looking "keep both" resolution leaves the EARLIER side's last block unterminated. bats reports that as `not ok 1 bats-gather-tests` (a parse failure of the whole file, `1..1`), never as a failing test, so a filtered TAP read shows one unrelated-looking red over a suite that ran nothing — assert the plan line equals the test count after ANY append-vs-append resolution, in bats, JS object literals, Go funcs or anything else brace-delimited.
