# A synthetic input event has no sandbox — the screen is global

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A synthetic input event has no sandbox — the screen is global](.) — 2026-09-16, kitty-drag phase 3, and this is the SECOND time in one phase that a verification probe reached the operator's live terminal. W6 verified its v0.48.2 backport by posting real CGEvents at computed screen coordinates, gated on a front-to-back `CGWindowList` hit test for its own sandbox window — careful, and still one press+release landed at screen (900,560) in whatever pane the operator had there (a click, not a drag: it could have moved a text cursor or cleared a selection; it typed and submitted nothing). The earlier instance was a skeptic running `kitty @ action test_dragging`, which dropped kitty's own literal payload string into a live Claude Code composer and blocked a pane succession. ⇒ **A sandbox contains PROCESSES, FILES and SOCKETS. It does not contain the POINTER, the keyboard focus, or the screen** — those are machine-global singletons, so "I launched my own instance with its own config dir and socket" buys nothing at all against a synthetic input event, and the isolation you can see makes the isolation you lack easy to forget. ⇒ Before any probe that posts an event: prefer the headless lever if one exists (here `dnd_test_set_mouse_pos` writes `w->mouse_pos` directly and touches no `drag_source` field, which is the whole reason it is carved out of the twelve OSC hooks that are off-limits); if a real event is unavoidable, hand the probe to the operator rather than firing it, or bound it to a moment the operator is not at the machine AND state the residual in the close. **A hit test is a necessary and NOT sufficient guard** — it proves the coordinate is over your window *at the instant you sampled*, which is a claim about geometry, not a claim about whose focus the event will land in. Companion, mechanically separate and hit while cleaning up after the same wave: **a `ps | awk` census CANNOT be made self-clean when the pattern must also appear in your own command, because this harness wraps every tool call in `zsh -c 'eval "…"'` and `ps` prints that whole script text.** Moving the pattern into the ENVIRONMENT (the documented cure for awk's own argv) does not fix it — the wrapper still carries the literal. Measured: exact-substring census returned 22 rows with BOTH negative controls failing (the operator's kitty matched, and a path nothing holds returned 2). What works is matching the command's FIRST FIELD for equality (`awk '$2==ENVIRON["P"]'`) — a wrapper shell's field 2 is `/bin/zsh`, so it can never satisfy it: 5 rows, both negative controls 0, and a positive control proving the instrument can still select the operator's own kitty by ITS path. And the empty-pattern arm is worth running once for calibration — it selected **938 processes**, which is what a mis-built selector actually hands a kill loop. ⇒ **Three controls before any signal: a null pattern must return ZERO, a known-innocent must not match, and a known-target must match. Then signal literal PIDs, re-reading each one's command immediately before the kill** — a pattern can drift between census and act; a pid re-verified at the moment of use cannot.
