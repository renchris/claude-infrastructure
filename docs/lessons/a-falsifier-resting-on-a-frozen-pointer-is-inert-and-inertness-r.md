[A falsifier resting on a FROZEN pointer is inert, and inertness reads exactly like "still live"](.) — 2026-09-17, cc-backlog `8e67a1fa2d40` closed DONE by discharge (cure `2a54f1416`, 53 minutes after the row was filed; the row nonetheless re-dispatched for **9 days**). **A self-retracting work item is only as live as the STORE its falsifier reads, and a store that stops advancing converts a transient premise into a permanent one — silently, in the direction that reads as agreement.** `cc-premise run_derived_postland_falsifier` is a well-built arm: it fails open on every unknown, carries a span clause so a green cannot vouch for a suite it never ran, and its docstring names the exact decay it was built for (*"the remedy landed 6 minutes 40 seconds after the RED was recorded, and a worker was still dispatched onto the item THREE DAYS later"*). Its ONE success state is `is-ancestor(red_sha, last-green)`. Measured: `~/.claude/autonomy/postland/last-green` last moved **2026-09-03** and sits **980 commits** behind trunk; the newest `verdict:"green"` stamp in a 633-stamp store IS that pointer, so **0 full-corpus greens in 14 days** — the pointer is honest, the producer simply cannot feed it. Consequence, checked PER MEMBER rather than generalised from one: **6 of 6** open `source=postland-verify` rows carry a red sha that is NOT an ancestor of the pointer, every one of them filed after it froze. The arm cannot return 0 for any of them, by arithmetic, and never will until a full corpus goes green. ⇒ **when a row keeps coming back, ask what STORE its falsifier reads and when that store last moved** — a frozen pointer is indistinguishable from a live premise at every call site, and the item's own re-dispatch is the only symptom. Same polarity as [[acceptance-gate-must-be-monotone-in-evidence]] (P(pass) must rise with evidence; here it is pinned at 0) and of [[closed-vocabulary-field-swallows-an-unrecognized-value]] (a permissive default converting a terminal state into a permanent one). **Three companions, each separable. (a) The obvious remedy is UNSOUND and one measurement kills it.** The stamps store records per-run `failing[]`, so "a later run containing the red sha did not list this suite" looks like a reachable per-suite predicate that needs no full-corpus green. Tested against all six rows, the FIRST hit for this one was a stamp with **`suites: 0`** — a run that executed nothing, where absence from `failing[]` is vacuously true — i.e. the naive predicate would have FALSELY RETRACTED a row on a run that never ran the suite, which is precisely the fail-open the span clause exists to prevent. `failing[]` records what FAILED and nothing records what EXECUTED, so the span guarantee is absent from the store, not merely unread; 315 of 633 stamps are `verdict:"cut"`. Build the span into the producer before keying anything on the absence. **(b) A finding can be the missing leg of rows that already exist without duplicating any of them** — `37f96d239398` measures the same green collapse but its payload is the DEPLOY gate, `ae20d7a7c1b7` says the premise pass never RUNS, and `228e30f8adce` warns against auto-closing on a sample. Mine is the third: even when the pass runs, this arm is inert for this population. Grep the store before filing, then state which existing rows it abuts and why it is not one of them. **(c) `--falsifier` is absent from postland's plain-RED filing site DELIBERATELY** (`scripts/postland-verify.sh` site B passes `--condition` but no `--falsifier`, while site A does) — the header says so, because a STORED probe would shadow the derived one. A missing field that looks like forgotten wiring can be a documented composition rule; read the header before "fixing" the gap.
