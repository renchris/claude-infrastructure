A sibling ran the SAME population with the control arm — each convicted suite executed at the culprit's tree AND at its PARENT — and got **5 true / 3 false**, i.e. the arm mostly RIGHT, the opposite conclusion. Their own first pass had made the identical error one step earlier (culprit arm only, read 5 unattributable failures as noise, concluded "zero true positives, disarm"); the parent control inverted all five. ⇒ before an asymmetric-evidence search sets a verdict's DIRECTION, name the arm that could refute it and run that too — **a one-armed test cannot attribute, and its silence gets read in the direction the analysis already leans.** Second, separable half from the same item: when a work item poses a BINARY (disarm the actuator, or accept ~30% wrong convictions), the answer is often neither — make the actuator PROVE ITS OWN PREMISE. `git revert` was the only thing writing to trunk and the one measurement it stood on (does the failing test fail AT the culprit) was the only one never re-run, while every other end — tip, floor, tip's parent, the corpus verdict itself — had already been made re-measurable. The sibling's 8-row table then separated 8 of 8 on exactly that predicate.
