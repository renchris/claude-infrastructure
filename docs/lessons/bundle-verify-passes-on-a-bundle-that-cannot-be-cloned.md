# Bundle verify passes on a bundle that cannot be cloned

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Bundle verify passes on a bundle that cannot be cloned](.) — 2026-09-16, packaging github.com/renchris/fde-crossos-devloop-bench: a `git bundle create --all` run inside a `--depth=1` clone produced a 100 KB file that `git bundle verify` called "okay" and said "records a complete history", and `git clone` from it failed with `Failed to traverse parents … remote did not send all necessary objects`. Verify checks the bundle's prerequisites against the repository it is RUN IN, so a shallow-sourced bundle reads complete from inside the shallow clone and is unusable anywhere else; `git bundle create --depth=1` does not exist (git 2.54: "unrecognized argument"). ⇒ **the only test of a bundle is a `git clone` from it into a fresh directory**, then a tree-hash or `diff -r` comparison against the source. To ship a small bundle of a repo whose history carries dead blobs (145 MB of a pnpm store here against a 0.4 MB tree), build an orphan commit of the HEAD tree in a fresh repo and bundle that, labelling the different commit id and citing the identical tree hash. Same family as [Claimed vs checked] and [Actuator decides]: a verifier reading its own context passes an artifact that fails in the consumer's.
