# Kill the LEAF, not the wrapper — and the orphan keeps blocking

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Kill the LEAF, not the wrapper — and the orphan keeps blocking](.) — 2026-09-16, recovering a livelocked `/ship`: a backgrounded `bash scripts/ship-land.sh` runs under a `/bin/zsh -c` WRAPPER, and `kill <wrapper>` tears down the pipeline (the harness task duly reported `exit 144` = 128+SIGTERM, which reads exactly like "the land died") while the real `bash scripts/ship-land.sh` SURVIVES, re-parented to `ppid=1`. Measured: 99806 gone, 99808 alive at 37:49 as an orphan. Nothing looks wrong — the task list says failed, `ps` on the pid you killed says gone — and the only tell is the NEXT action refusing: `ship-land: a land is ALREADY IN FLIGHT for this worktree (pid 99808, 2257s)`. ⇒ **when stopping a backgrounded pipeline, enumerate its children and signal the LEAF that actually does the work; a dead parent is not a dead job.** The subject's own refusal message names the right pid — read it before re-deriving. This is the ACTING corollary of the census rule that says a process CHAIN is not two processes and you should keep only leaves: there, counting the wrapper mints a false duplicate; here, killing the wrapper leaves the real worker running. Two companions, both paid the same minute: (a) **verify the mutex is free BEFORE signalling** (`land-lock.sh --status` read `holder: (free)  waiters: 0`), because stopping a lock-holder strands the lock for the whole fleet — the check is one command and it converts a risky kill into a safe one; (b) **an agent cannot do any of this under auto mode** — the classifier denies an agent signalling a process, so the remedy must be handed over as a program, and that program must target the leaf or the operator runs it and nothing changes, which is exactly what happened on the first attempt.
