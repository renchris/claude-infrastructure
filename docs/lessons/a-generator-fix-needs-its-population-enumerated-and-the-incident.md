# A generator fix needs its POPULATION enumerated, and the incident already ate the evidence of which copy was loaded

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A generator fix needs its POPULATION enumerated, and the incident already ate the evidence of which copy was loaded](.) — 2026-09-17, closing the kitty `autoformat` landmine (`docs/research/kernel-watchdog-panic-2026-09-16.md` § 6.8): I found the generator, wrote the one-word fix, applied it, verified it by content, proved it with a red-proof, landed it, and **fixed the wrong copy.** There are TWO kitty checkouts on this box. `~/kitty-dev` is the one I had been reading all session, so it is the one "the generator" named in my head; `~/kdev` is where the second panic's swarm actually ran, and it kept the original skip tuple while holding 350 MB of vendored headers AND another session's uncommitted patch — i.e. a session that resumes, commits, and runs the declared `pre_commit` hook takes the box down a third time. Every check I ran was sound and every one of them was scoped to the wrong subject. 🚨 **The trap is that the incident DESTROYS the evidence of which instance was loaded, and the destruction reads as safety.** `~/kitty-dev/dependencies` was absent when I looked, which is exactly what made the fix there feel verified — no fuel, nothing to walk, a clean measurement. That absence was the panic's own CONSEQUENCE, not a property of the tree; the loaded one still had its 350 MB because it had not been the one wiped. ⇒ **When the generator is a FILE rather than a service, "fix the generator" is a category error until you have enumerated every copy of it** — one `find` over the plausible roots, printing for each copy both the fix marker and the size of the fuel it can still reach. Do that BEFORE claiming the class is closed, because the per-copy verification you will run afterwards is individually correct and collectively silent. And prefer a sweep SCRIPT over a per-copy edit even when you believe there is one copy: an idempotent sweep that verifies by content is the same cost to write and is the only form whose verdict covers the population. Same family as [Aggregate control cannot see a per-member zero] inverted — there the aggregate hid one blind member, here a per-member fix hid the un-swept population. **Second half, separable, and it cost two debug cycles on the integration test built in the same hour: a fixture that violates a gate's PRECONDITION produces the identical output to a broken subject.** The end-to-end case fed the daemon a pre-storm population entirely below the actuator's 100 MB floor, so the census roster came back EMPTY, the no-baseline guard correctly stood the generic arm down, and the log read `cohort_n=0` — byte-identical to the pre-fix defect the case exists to catch. The second cycle was the same shape one layer down: the tick threshold was REASONED rather than measured, and since the stub's counter is bumped before the census reads `ps`, the fixture handed the census the very storm it was supposed to predate, so the pids were never "new" and the cohort was `0` again. ⇒ **When an integration case goes red with the pre-fix symptom, suspect the fixture's preconditions before the subject** — list every precondition the path depends on (a baseline exists, the floor is cleared, the ordering holds) and assert each one in the fixture, rather than inferring them from a passing unit case. And when a stub's behaviour turns on a counter the harness owns, TRACE the counter once instead of deriving its phase; the derivation was off by exactly one and looked perfectly reasonable.
