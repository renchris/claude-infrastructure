# Green in both arms is an EQUIVALENCE guard, not a red-proof

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Green in both arms is an EQUIVALENCE guard, not a red-proof](.) — 2026-09-09, W3-B2 (`591a82f62`): a red-proof is supposed to fail before the fix and pass after, and the case that matters most can quietly fail to do either. Replacing `cc-decide cmd_list --json`'s per-file `jq` fork loop with ONE pass, the load-bearing risk is that `jq` STOPS AT THE FIRST unparseable input, so a bare one-pass drops every packet AFTER a bad one — a silent under-count of the open class-C packets that decide the `⛔` rung. The fixture built for exactly that (4 packets, the 3rd truncated, bad file in the MIDDLE of glob order — a bad file LAST passes under the broken version and proves nothing) came back **`ok` on the pre-fix binary AND `ok` on the fixed one**, because the OLD per-file loop already tolerated a bad packet. Read as a red-proof that is a null result; read correctly it is an **equivalence guard** — it asserts the rewrite did not LOSE a property the incumbent had, and no pre/post arm can ever exercise it. ⇒ **when a case is green in both arms, ask what mutation it is actually guarding against, then BUILD that mutation and run it.** Here the mutant is the naive one-pass (same diff, fallback deleted — the implementation a future session reaches for): it dies on the mid-glob case and on the reporting case while both controls stay green, which is the only evidence the fixture has any power at all. Distinct from [One mutant per site], which asks whether a suite credits a SITE; this asks whether a GREEN-IN-BOTH-ARMS case tests anything, and the answer is only ever a mutant. Corollary that cost a debug cycle in the same test: bats merges stderr into `$output`, so a case asserting on JSON from a command that DELIBERATELY warns on stderr feeds the warning line to `jq` and dies `exit 5` — the instrument, not the data; redirect the streams separately before indicting the change.
