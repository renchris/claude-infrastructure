# Closure ≠ measured

[Closure ≠ measured](.) — 2026-09-16, kitty ⌘⇧B title bar (landed with this line): **a "there is no fourth option" closure is a claim about its PREMISES, not about its logic — and both premises here were false on the day they were written, which is why three weeks and a decision packet went past them.** `config/kitty.conf` § 3 enumerated three corners (shift · permanent row · no drag) and closed with *"a reservoir must EXIST before it can be spent — top padding is 10pt against a ~16pt cell here, so today there is nothing to hand back."* Two independent errors in one sentence. **(1) The quantum was sized by dividing the deltas of an arbitrary sample.** The probe behind "~16pt" read top padding 0/10/17/25 → 31/30/29/28 rows and differenced them, which measures the SAMPLE SPACING, not the step. Bisecting for the band edge instead — the 30-row band spans total vertical padding 3..25 — gives 23, and the bar measures 45px in a screenshot: the cell is **22.5pt**. The four original points were perfectly consistent with the true band structure; only the figure derived from them was wrong, so nothing looked suspicious. ⇒ **to size a QUANTISED step, bisect for the band edge; never divide the differences of an arbitrary sample.** **(2) The budget declared exhausted had been decomposed along the wrong axis.** Rows depend on TOTAL vertical padding, and `window_padding_width 10 5` is top 10 **plus bottom 10** = 20pt; the reservoir did not need creating, it needed MOVING. The prior attempt lost a row only because it wrote `26 5 10 5`, ADDING the reservoir to a bottom padding nobody asked whether it could spend. ⇒ when a closure says a resource is exhausted, **re-derive what the consumer actually reads** — here the denominator was a sum while every sentence named one term of it. Distinct from [[discovery-critic-premise-goes-stale]] / [[filed-blocker-is-never-revalidated]], where a premise was true when written and rotted. **Three companions, each separable. (a) A change that makes a transient state PERSISTENT inherits every latent interaction that state had, and the ones that were safe only because the state was short-lived are the ones nobody wrote down** — the fix's whole point is that the bars stop vanishing after a drag, which instantly converted a rare double-title collision with the sibling ⌘⌥B chord into a guaranteed one. (b) **A test that encodes a SPELLING where it meant a PROPERTY forbids the fix for the very defect it protects against**: `kitty-conf-bindings.bats` demanded the chord literally end in `toggle_window_title_bars` while its own comment said "the chord must reach real, hit-tested bars" — the built-in was merely the only route when it was written. Third instance in that one file. (c) **Its sibling MUTANT CONTROL went vacuous by the same edit**: it asserts the mutated chord no longer matches a pattern the UN-mutated file had also stopped matching, so it passed whether or not its mutation bit — a control must be proven to fire on the un-mutated input before its verdict on a mutant means anything.
