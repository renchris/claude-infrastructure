[Aggregate control cannot see a per-member zero](.) — 2026-09-10, cc-backlog `40ea16f5821b` (landed 0066d1d50): a positive control whose predicate is a statistic OVER the members — "the corpus resolves something", "the scan is non-empty", "findings > 0" — **can only ever detect a TOTAL zero**, and the healthy members are precisely what keep it green and loud. `scripts/unattended-path-lint.sh` resolved each launchd plist's target by ONE rule (a literal `/(scripts|bin|hooks)/` segment, filtered by existence) and skipped an unresolvable one WITH NO WORD SAID: 26 plists, 24 in-tree targets across 23 plists, THREE resolving zero — two of them real coverage holes (`bin/cc-reaper`, 3,151 lines, invoked by BARE NAME after an inline `export PATH=`, so no path segment existed to extract; and `auth-timeseries`, whose plist names the DEPLOYED spelling `~/.claude/scripts/…` while the repo keeps the file at `tools/auth/…`). The file's own comment records the near-identical ancestor catastrophe — a BRE/sed bug under which the half "scanned NOTHING while reporting a clean corpus" — caught, in its own words, ONLY by that plist positive control, which was then made mandatory. It caught that one because it was a TOTAL zero and could never have caught these two, because 23 of 26 kept it speaking. ⇒ **when a control's predicate is a statistic over a population, ask what it reads when exactly ONE member goes blind; if the answer is "the same thing it reads when all is well", the control is sized to the wrong unit** — add a per-member arm that NAMES the member (the aggregate is not wrong, it is a different question). 🚨 **The corollary that makes this a DESIGN problem, not a one-liner: the per-member report needs a DECLARED residual or it fires on the legitimate case.** A third plist targets a script in a DIFFERENT checkout and is CORRECTLY unresolvable, so "report every unresolvable member" is a false LOUD — and this lint's exit 2 is a NON-VERDICT that blocks the gate. **No property of THIS tree distinguishes "belongs to someone else" from "a rung has just gone blind"**, which is exactly the failure being closed, where two blind rungs looked identical to two out-of-scope jobs; so the residual is a shrink-only declared list carrying its reason, blocking BOTH on an undeclared zero and on a declaration whose member starts resolving. Three companions, each separable: **(a) a filed item's own risk ranking is a hypothesis, and measuring it can invert it** — the item called the bare-name rung "the one most likely to mint false positives" and it was the ONLY candidate reaching the `cc-reaper` case; run over the whole corpus with a DELIBERATELY OVER-GENERATING word set (every word in ProgramArguments, not merely command-position ones) it yields exactly ONE in-repo hit, the intended one, and over-generating on purpose is what makes that a BOUND rather than a hope, since the shipped form scans through the real command-position scanner and is strictly tighter. **(b) A coverage fix makes previously-unexamined fixtures load-bearing and can flip a control's meaning without touching it** — the `mkrunner` selftest fixture named `$HOME/scripts/nightly-regression.sh` and never shipped the file; harmless while nothing looked, but the moment the per-member check landed it reddened a GREEN control for a reason unrelated to what that control tests, and would have left its RED twin passing for the WRONG reason, which is the one thing a paired control exists to prevent. Fix the FIXTURE, not the check. **(c) Widening a scan's population surfaces pre-existing debt, and each row needs its call site READ before its rationale is written** — `timeout`/`gtimeout` in cc-reaper ARE the guard (the loop stores `$(command -v timeout)`'s ABSOLUTE output, `-x`-validates it, falls back to four absolute paths, degrades to unbounded — the CORRECT spelling of the pattern whose INCORRECT spelling, storing the bare NAME, this file records elsewhere), and `bats` is a `selftest)` arm the scheduled job can never reach; ratchet them with those rationales rather than "fixing" them, because what the rows buy is that a NEW bare name in that file is red from now on.
