# Empty selector is a universal selector

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Empty selector is a universal selector](.) — 2026-09-09, the mass application termination (`docs/research/mass-app-termination-2026-09-09.md`): an env-prefix assignment `VAR=value cmd` binds VAR to **that command's** environment and NEVER to the shell, so a `"$VAR"` read from any LATER stage of the same pipeline expands EMPTY — and an empty pattern is not a narrow selector, it is a **universal** one (`awk`'s `index($0,"")` is 1 on every line; `grep ""` likewise). Measured: `count() { LA_PAT='handoff-fire.sh late-arm' ps -axo pid=,command= | awk -v p="$LA_PAT" 'index($0,p)' ; }` selected **875 of 878** processes where the same census with the pattern actually reaching awk selects **2**, and the `kill` loop under it SIGTERMed Kitty, Dia, Discord, Hammerspoon, ~17 Claude Code sessions and most of the user's launchd agents in nine seconds — the kernel logging `zsh(66592) deny(1) signal initproc signum:15`, the loop trying to signal pid 1. 🚨 **The rewrite that caused it was OBEYING a rule of ours**: the previous command used `grep -F <pattern>`, which puts the pattern in its own argv where `ps` prints it, so the census matched itself ([[argv-census-must-not-carry-its-pattern-in-argv]]) — moving it to an env prefix is the natural fix and is the WRONG one. A shell-level assignment (`P=…; … awk -v p="$P"`) satisfies both rules; only the env-prefix form does not. ⇒ **when you move a pattern out of argv, verify it still ARRIVES** — run the census alone and count what it returns before any signal; a census that returns everything and a census that returns two are one keystroke apart and look identical in review. Three companions, each separable: (a) **an absence can be the corroboration** — the fatal command has no entry in `bash-execution.log` while every neighbour recorded its `Exit:` line, because the shell was killed by its own broadcast before the post-hook ran; (b) **a symptom set can be entirely consequence** — `loginwindow`'s `SACShieldWindowShowing` arrived **1.33 s AFTER** the first signal and is drawn by daemons launchd RESPAWNED (pids just above the killer's), `kitty` exited `exit(0)` because a well-behaved app handles SIGTERM cleanly, and `secd`'s "SIGTERM, exiting when clean" names the signal it RECEIVED — so an orderly-logout reading fits every symptom and inverts the causality; order the events before believing a story that explains them all; (c) **count kills, not mentions** — 2,216 `jetsam` and 405 `memorystatus` substring hits in the window resolve to **0** actual kills, and the 4 `EXC_RESOURCE` lines are 15 MB high-watermark NOTICES logged after the wave.
