# A gate refusal is not a gate result

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A gate refusal is not a gate result](.) — 2026-09-08: `cc-bats` refuses a run at 2 concurrent roots + load/core ≥ 2.0 and says so on stdout — *"nothing ran, nothing was verified — this is a DEFERRAL, not a test result"*. Piped through `| grep -E "^(ok|not ok)"` it emits **zero lines and exits 0**, which reads exactly like a suite that passed; three triage runs in a row "came back clean" having executed nothing. Same family as a killed pipeline, but the refusal is DESIGNED and routine, not an accident. Two consequences: (a) always assert the plan line (`1..N`) is present before believing a filtered TAP result — absence of `not ok` is not a pass; (b) **your own long-running gate holds one of the two slots**, so a 5-hour full-suite run in the background will refuse your own targeted re-verification of the fix you just made — kill it with `scripts/gate-cleanup.sh` (worktree-scoped; a bare `pkill -f "bats…"` is denied by the kill-selection gate because argv carries whole briefs and would hit a dozen sibling sessions) and re-run only what you need.
