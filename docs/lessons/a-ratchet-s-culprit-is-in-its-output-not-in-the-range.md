# A ratchet's culprit is in its output, not in the range

[A ratchet's culprit is in its output, not in the range](.) — 2026-09-09, cc-backlog `09f8bb68dbf3` (post-land AUTO-REVERT FAILED, `tests/cc-pane.bats` @ `113d944c8cc7`, landed 81539a417): **a whole-tree RATCHET suite is reached by every commit in the landing range, so reachability-based attribution carries zero information for it — while the failing assertion's own output names the true file.** cc-pane case 27 greps `$REPO/{bin,scripts,hooks}` for a bare `${ITERM_SESSION_ID:-}`; postland named the landing tip `113d944c8`, whose entire diff is `bin/cc-offload` + `tests/cc-offload.bats` and which cannot redden a cc-pane ratchet. `bisect_reach_ok` did not veto and was right not to by its own design (it is one-sided and vetoes only on an `*.md`-only diff, and its header warns that every extension "removes convictions somewhere"). The real introducer, `810ee9be3`, was named *in the TAP output* — `hooks/lead-crash-watchdog.sh:1384` — one line nobody read. ⇒ **on a post-land RED, read the assertion's printed path BEFORE the range walk's verdict**, and treat a named culprit whose diff does not contain that path as unattributed. Not driven into the actuator on purpose: the class is 7 of 626 suites (~1.1%) at n=1 incidents, and a wrong veto and a wrong conviction are not the same size of mistake. **The rc=90 was PROTECTIVE, and that inverts how the alarm reads**: the revert conflicted and applied nothing, so a FAILED auto-revert on a mis-attributed culprit is the good outcome, not the incident — had it applied it would have reverted an unrelated feature and left the red exactly where it was. Second half, separable and about lints: **a per-LINE lint can be tripped by a HOIST that changes no behaviour.** `LEAD_PANE` already preferred `CC_PANE_ID`; the bare read only moved to its own line because bash cannot apply `##*:` to a defaulted expansion inline. The test ships a `cc-pane-id-lint:allow` marker for exactly this and it would have been accepted — but a marker silences that line forever. Prefer making the precedence STRUCTURAL (`_lcw_isid=""; [ -n "${CC_PANE_ID:-}" ] || _lcw_isid="${ITERM_SESSION_ID:-}"`): it satisfies the lint by being right and leaves the line under watch for a genuine bare read added later.
