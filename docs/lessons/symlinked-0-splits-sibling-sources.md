# Symlinked $0 splits sibling sources

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Symlinked $0 splits sibling sources](.) — 2026-09-09, cc-backlog `4b0095d1ee73` (landed e15dcd475): a script invoked THROUGH A SYMLINK resolves every `$0`-relative sibling against the LINK's directory, not its own — and because the live layer is a per-file symlink farm, some of those siblings exist there and some do not, so ONE invocation silently splits into a half that resolves and a half that dies. `session-index-backfill.sh` is `~/.claude/bin/…` -> claude-session-search/scripts/…; its `SCRIPT_DIR=$(dirname "$0")` is `~/.claude/bin`, so `$REPO_DIR/hooks/lib/session-index-helpers.sh` resolved (to a DIFFERENT repo's copy — the one the live layer happens to carry) while `$SCRIPT_DIR/lib/progress-ui.sh` did not exist, and the script exited 1 at line 13 before reaching any phase. Every scheduled run for months; `~/.claude/logs/backfill-scheduled.log` holds that one error and NOTHING else, and the only downstream tell was that the index carried zero rows with `source='history'` — which reads exactly like 'there was no history to index'. ⇒ **before building a producer for an existing consumer, EXECUTE that consumer end-to-end on the path its scheduler actually invokes**; a correct artifact fed to a dead consumer delivers nothing, and the absence of its output is indistinguishable from having had nothing to say. Two corollaries measured the same session: (a) which COPY of a shared library you get is decided by the invocation path, not by the repo you edited — the launchd path sourced claude-infrastructure's helpers while running claude-session-search's script, and that accident is the only reason a fix in one repo reached the other, so verify the resolution rather than reasoning about it; (b) a new tool deploys ONLY if its NAME matches the installer's glob — `install.sh:926` loops over `bin/cc-* bin/desk-* bin/ms365-*`, so a tool named anything else gets no symlink and is landed-but-never-live with no error anywhere.
