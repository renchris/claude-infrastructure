# A whole-tree formatter is sized by the VENDORED tree, not by yours

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A whole-tree formatter is sized by the VENDORED tree, not by yours](.) — 2026-09-16, kitty-drag phase 3: `./autoformat` in a kitty checkout **panicked this machine's kernel twice in one afternoon** (`panic-full-2026-09-16-155400`, `panic-full-2026-09-16-162856`), each panic killing a Claude Code session mid-wave and destroying an in-flight patch plus every scratchpad artifact of two research phases. Both events were read at the time as ordinary reboots and were **self-inflicted by a command on the wave's own acceptance checklist.** MECHANISM: kitty's autoformat walks every top-level dir except `dist`/`build`/`bypy`/`3rdparty`, so it formats the vendored ~300 MB `dependencies/` tree; ten parallel `clang-format` workers over `dependencies/darwin-arm64/include/simde/*.h` (1-3 MB macro headers) each grew to **1-19 GB RSS**, the VM compressor hit 100% of its segment limit, and the watchdog panicked 4-5 min later. Its cache is written only on completion, so an interrupted run re-formats everything — the failure is perfectly repeatable and never gets cheaper. ⇒ **Before running any whole-tree formatter/linter/test-runner in an unfamiliar checkout, read its exclusion list against `du -sh */`.** Here the ratio is 0.4 MB of changed source to 300 MB of vendored headers, and a tool that says "formats the project" means "formats whatever is in the tree", which in a repo that vendors its C dependencies in-tree is a different and much larger thing. Format only the files you changed (`clang-format -i --style=file:.clang-format <one file>`). Three separable companions: **(a) an acceptance checklist is a list of commands somebody else certified on THEIR machine** — this one came from kitty's own contributor docs and is correct upstream, where CI runs it in a container that is thrown away; inheriting it into an agent brief inherits its resource profile too, and nothing in the checklist says how big it is. **(b) A kernel panic is invisible from inside the session it kills** — the transcript simply ends, the next session starts clean, and `last reboot` reports a reboot with no cause, so the natural reading is "the box rebooted" and the natural response is to rebuild and carry on, which is what happened *twice*. The attribution came from a SIBLING session correlating panic files against command logs; if you lose a session to an unexplained restart, check `/Library/Logs/DiagnosticReports/*.panic` against what you were running 5 minutes earlier before writing it off as bad luck. **(c) A claim resting on a run you must never repeat should be STRUCK, not kept** — the PR draft said "`./autoformat` … clean", which was true of the run that panicked the box; a claim nobody may re-verify is worse than an absent one, so it was replaced with what was actually done (per-file formatting) plus the hazard.
