# A crash anchor must be the event that killed the subject, not the most convenient clock

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A crash anchor must be the event that killed the subject, not the most convenient clock](.) — 2026-09-16, `cc-resume-classify` (landed 4fa6d3c80): a recovery tool anchored triage on `kern.boottime`, i.e. it assumed the only thing that kills a fleet of sessions is the BOX going down. A terminal emulator crash kills every pane it hosts and leaves the machine up, so boottime then points at an event HOURS before the one that mattered. Measured: kitty SIGSEGV'd at 01:13:49Z while boottime read 21:28:30Z the previous evening; against boottime the same four sessions classify 3 UNKNOWN + 1 INTERRUPTED, against the true anchor 3 AT-REST + 1 INTERRUPTED — and **the one interrupted session is a DIFFERENT session in each reading**. 🚨 The failure is SILENT in the direction that reads as health, which is why it survived: every `UNKNOWN` defaults to `AT-REST`, so the wrong anchor restores the fleet, nudges nobody, and reports success — the [[fail-safe-default-mimics-the-healthy-state]] shape, one level up. ⇒ **when a tool triages "what was interrupted", ask what EVENT it anchors on and whether that event is the one that did the killing**; recover the anchor from evidence (macOS writes a per-process `.ips` whose FILENAME carries the timestamp, so no unreadable report body can mislead you) and fall back to the clock only when no such evidence exists, so the ordinary case stays byte-identical. And give the anchor its own alarm: a row with NO records before the anchor began AFTER it and cannot be a casualty of it, so a MAJORITY of such rows indicts the anchor, not the fleet. Three companions, each separable: **(a) a safety change that lives only in a SHARED WORKING TREE is not a change, it is a lease.** The chord disarm was reverted twice within an hour — once by a peer's `git checkout -- <file>` — because the shared checkout's HEAD lagged trunk and still carried the armed version, and kitty's `kitten __watch_conf__` reloaded the armed file instantly. Nothing errors and nothing announces it. ⇒ land a safety change, or accept that any checkout/stash/rebase in that tree silently undoes it; and when restoring such a file take it from `origin/main`, never from `HEAD`. **(b) In a checkout shared by N sessions, "the other one did it" has N-1 referents.** Two sessions mis-attributed a dirty file to each other inside one hour, each reasoning from adjacency rather than evidence; a commit's git author is identical for all of them, so attribute by what YOUR session wrote (transcript edit records) or by mtime against your own last write, never by "it was dirty next to my work". **(c) When neither single-variable arm reproduces a fault, the candidate is a CONJUNCTION, and single-variable sweeps will keep returning clean nulls.** A shipped harness read 12/12 green — including a real drag — over a shim that had just killed 55 sessions; one sandbox repro was single-tab-and-minimized (render path unreachable) and another was two-tab-and-visible (no crash). Neither arm alone is evidence of safety, and a green suite over a conjunction fault is the most convincing possible wrong answer.
