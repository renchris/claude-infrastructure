# A 0-byte output file is not a dead process — it is a process that has not emitted yet

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A 0-byte output file is not a dead process — it is a process that has not emitted yet](.) — 2026-09-16, made TWICE in one session, the second time an hour after diagnosing the first. (1) `bash ship-land.sh 2>&1 | tail -30` backgrounded: `tail` cannot emit until its input CLOSES, so the capture file sits at 0 bytes for the entire healthy run and there is no progress to read. (2) Then a watcher `until ! kill -0 <pid>; do sleep 15; done; echo VERDICT` — same shape, it prints only AFTER the wait ends — was declared "died silently at 0 bytes" on the strength of that empty file plus a `pgrep -f` liveness probe whose pattern did not match how the process actually appears in argv. It was alive the whole time and completed correctly, exit 0. ⇒ **for any command whose output is buffered to the end (a `| tail`, a `| sort`, a trailing `echo`, anything that summarises), an empty output file is the EXPECTED state of a healthy run and carries ZERO information about liveness.** Liveness is `kill -0 <pid>` on a pid you read, or repeated child sampling (`pgrep -P <pid>` across several seconds) — never file size, never a single `pgrep -f` whose pattern you have not confirmed matches the live argv. And the cure for the blindness is upstream: redirect a long command to a FILE and read the file, rather than piping it through anything that withholds. Companion measured the same run: a gate can end PARTIAL rather than red — ship-land exhausted a 900s smoke budget after 28 direct suites and printed `GATE-KILLED … exit 124, ZERO 'not ok' … NOT a red and NOT evidence about your tree`, so a killed-by-budget suite must never be read as a failing one (sibling of [A gate refusal is not a gate result]).
