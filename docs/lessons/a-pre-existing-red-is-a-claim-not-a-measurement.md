# A "pre-existing red" is a claim, not a measurement

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[A "pre-existing red" is a claim, not a measurement](.) — 2026-09-11, cc-backlog `120e8054eb98` (re-land `fix/rm-gate-ephemeral-temp`): a branch that could not land carries the previous author's DIAGNOSIS in its commit message, and the re-land item encodes that diagnosis as its stored `run`. Both were wrong here, in the same direction. The permit commit asserted `tests/validate-bash-differential.bats` is *"red 6-of-7 on unmodified trunk by A/B, i.e. pre-existing and not this diff"*; measured one box, one variable — a detached worktree at `origin/main` vs. the branch — trunk is **7/7 ok, harness rc=0** and the branch is **6/7 red, rc=1**, so the red is CAUSED by the diff. ⇒ **re-run BOTH arms, and run the trunk arm at the branch's OWN merge-base as well**: *"a later trunk fix overtook it"* is the plausible-sounding repair that leaves the original instrument uninspected, and here trunk was rc=0 at `ce089b609` too, so the claim was already false when it was written. 🚨 **The item's `run` could never have worked and its own exit code says so**: ship-land's rc 6 is by contract *"a named `not ok` in a direct suite is a VERDICT about your diff: fix it, do not retry unchanged"*, while the stored command was a bare re-land — **a work item whose remedy contradicts the exit code it records is a re-dispatch loop**, so read the rc's CONTRACT before running the remedy it ships with. Three companions, each separable: **(a) a line-pinned inventory converts ANY line-count change into a land-blocking red, by design** — `tests/fixtures/validate-bash-sites.tsv` pins every grep site in `hooks/validate-bash.sh` by LINE, and its own header says *"a grep site added to, removed from, or MOVED IN the hook ⇒ UNTESTED, which is a failure"*; the permit inserts 94 net lines, moving three sites and adding one, and the cure is to RE-PIN and record the population change (the practice that file's own 2026-09-09 note establishes) — never to disable the check, and never to guess the new verdict, which is read back from the harness's own MEASURED column. **(b) Clearing the named red does not mean the gate is green** — this branch had TWO independent reds and the suite was merely the one someone had already looked at; the FIRST gate arm, shellcheck, was RED on the permit's own new code (SC2016 ×3, deliberate single quotes needing the repo's targeted-disable convention), and `scripts/ship-land.sh --precheck` runs THE SAME `run_gate()` with no lock, no push and no ref write, so it is the cheap way to learn that before spending a contended land. **(c) `$?` after a pipe is the LAST stage's status, and it acquits twice in a row** — `shellcheck <file> | head -20` and `validate-bash-differential.sh | tail -40` each printed their findings and each reported "exit 0", which is exactly what let a genuinely RED file read as clean and made the gate look wrong; capture to a file and read the PRODUCER's rc, and read a verdict at the TOP of its output (both causes here were in the first 45 lines, unreachable through `tail`).
