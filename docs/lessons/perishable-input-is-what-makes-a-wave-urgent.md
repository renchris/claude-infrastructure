# Perishable INPUT is what makes a wave urgent

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Perishable INPUT is what makes a wave urgent](.) — 2026-09-16, kitty-drag phase 3: the box rebooted nine minutes into the first implementation wave and reaped all of `/private/tmp` — both built kitty trees, every phase-1 and phase-2 research artifact, and one wave's entire in-flight patch. **What survived is exactly what had been written into the repo worktree, and nothing else.** The plan had ALREADY warned that the scratchpad artifacts "will not survive a reboot" and had ALREADY scheduled the recovery wave (W8) with the note *"off the critical path, but run it EARLY rather than last"* — and that instruction is the only reason the `draghold` driver, its build line and all four invocation-carrying harnesses exist today: they were recovered into `tools/draghold/` at 15:41-15:43 and their source was reaped at 15:50, a margin of about two minutes. ⇒ **An item's POSITION in a schedule is part of its risk, not a detail of its priority — and the thing that makes a wave urgent can be the perishability of its INPUT rather than the value of its OUTPUT.** "Off the critical path" answers *how much does the output matter*, which is a different question from *how long will the input still exist*, and ranking by the first silently schedules the second last. Three separable companions, each paid for the same hour: **(a) a constraint that drives a siting decision can crowd out a dimension nobody ever weighed.** The trees sat in `/private/tmp` because of a measured ~80-char build-path ceiling; `~/kitty-dev` is 25 chars and survives a reboot, so there was never a trade here at all — only an unexamined default that looked like a decision because a real constraint was standing next to it. When a placement cites a constraint, ask which OTHER properties were silently sacrificed to it, because a cited reason reads as a considered one. **(b) A deliverable with no natural home in the repo needs a deliberate one.** Deliverable A (a kitten) lived in `scripts/` and survived; deliverable B (a patch against SOMEONE ELSE'S tree) had nowhere obvious to live, so it lived only in the build tree and died — the artifacts most likely to be lost are exactly the ones the repo layout has no slot for, which is a reason to MAKE a slot (`docs/patches/`), not a reason to leave them outside. **(c) A full `git clone` can be stalled on history negotiation rather than bandwidth, and the two look identical from outside**: the full clone moved ~3 MB/min (80+ min projected) while a `--depth=1` clone of the same repo over the same link took 37 MB in 20 seconds. Before waiting out a slow clone, race a shallow one — it costs nothing and settles which of the two you are looking at.
