[Fixture shape hides address bugs](.) — 2026-09-08, `bin/cc-notify`: `target_live()` matched a target against the registry's `.paneUUID` and then against `it2 session list --json | .[].id` — **both numeric pane ids** — while the address every consumer prints (the inbox banner's "reply to a peer with cc-notify <uuid>", the key `mailbox-drain.sh` reads its box under, the id in every forwarded mail line) is the **36-char session uuid**. Measured A/B, same pane same minute, one variable — pane 678 by session uuid ⇒ `mailbox-only reason=target-not-live`, by name ⇒ `verdict=delivered … (live session)`. **108 passing tests could not see it, and the FIXTURE is why**: `tests/cc-notify.bats` gives every row a UUID-SHAPED `paneUUID` (`AAAAAAAA-1111-…`) where production's 69 rows are all numeric, so the pane key and a session uuid are indistinguishable and the one axis the bug lives on is held constant at a value that cannot express it. ⇒ **when a subsystem resolves an ADDRESS, the fixture must reproduce the SHAPE of every identifier space in play, and those shapes must DIFFER wherever production's differ** — ask "could this fixture tell the two spaces apart if the code confused them?", and if both keys share a shape the suite is decorative on that axis.
