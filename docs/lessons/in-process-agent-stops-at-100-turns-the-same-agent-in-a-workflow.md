# In-process agent stops at 100 turns; the same agent in a workflow does not

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[In-process agent stops at 100 turns; the same agent in a workflow does not](.) — 2026-09-16, measured while integrating late findings into a 59K-word document: an in-process `Agent` spawn of `deep-research` stopped at its frontmatter `maxTurns: 100` **mid-pass**, having applied ~3.3K words of edits and written NO changelog (its brief put the log last), while the SAME agent definition running inside a Dynamic Workflow reached **162-209 assistant turns** in the same session (A10 research 209/134 tools, A01 205, A05 verify 183) — so the cap is a property of the in-process spawn path, not of the definition or the model. The failure is quiet in the worst way: the harness reports a normal completion carrying PARTIAL text, the edits are already on disk, and nothing says which of them landed. ⇒ (a) size an in-process editing brief to what fits in ~100 turns, or split it; (b) demand the artifact and its changelog be written INCREMENTALLY as sections complete, never "at the end" — the same rule that saved a 25KB draft when A11's research agent died three times; (c) resume with `SendMessage` to the agent id, which continues from its transcript and costs nothing re-read, rather than re-firing the brief (a re-fire re-does the applied edits); and (d) when you resume a context-deep agent, narrow the remaining scope explicitly and forbid risky work at depth — a 425K-context agent asked to "also trim prose" will cut the wrong paragraphs.
