# Size refuted ≠ decision flipped

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[Size refuted ≠ decision flipped](.) — 2026-09-09, cc-backlog `ac13c22fe291` closed by disproof `79fa7f87b722`, landed 4bef0f1af: a work item prices a trade using a MAGNITUDE ("collecting a dead member's last 3 refs trades a real recovery guarantee for ~3% of a ref store"), and the natural move on re-measuring is to check whether the number still holds. It did not — 28 days on it was **848 dead members holding 2,097 refs = 65.7%** of the store, not 65 / ~180 / 3.2%, understated ~12x — and the tempting inference, *"so now it IS worth fixing"*, is **wrong**. The decision criterion was never SIZE, it was COST, and the cost side was never measured by anyone: a full `git for-each-ref` over all 8,715 refs in that repo runs **0.01-0.02 s** and `git status --porcelain` 0.02-0.03 s, so the parent lane's "a measurable git cost on every ref walk" does not reproduce at any of these sizes. Refuting a residual's size UPWARD cannot improve a trade whose other side is zero. ⇒ **when an item argues from a proportion, re-measure the proportion AND the thing it is a proportion of — then ask which side the decision actually turns on.** Three companions found in the same pass, each generalizable: (a) an item's "this is the ONLY uncollected term left" is a claim about a POPULATION and is cheap to falsify — `refs/wip` held 967 refs, 484 of them >30 d, with no collector anywhere (the sole `refs/wip` delete in the tree was a test cleaning its own fixture), so the named term was 36.6% of the store, not all of it; (b) a collector's residual being *most* of a store is compatible with the collector being perfectly healthy — the per-member histogram (150 at 1, 147 at 2, 551 at 3, **none above** the floor of 3) is positive proof the age rule reaches everything the floor does not protect, and a share statistic alone cannot tell "leaking" from "bounded by design"; (c) the deliverable was neither the fix nor the refutation but a STALE JUSTIFICATION — the code recorded its own reason not to build the remedy as a perishable fact ("no ref in the live store is older than 30 days, so a hard ceiling above the newest-N floor would collect nothing today"), true when written 2026-08-06 and false 34 days later (oldest ref 59.7 d; a 30-day ceiling would have collected 1,426 of 3,189). A negative decision record whose premise expires silently converts a *deferral* into a *permanent block*, because the next reader concludes the remedy is a no-op and stops — so replace the number with the criterion plus the command that re-measures it, exactly as the ship-policy table delegates rather than naming a repo.
