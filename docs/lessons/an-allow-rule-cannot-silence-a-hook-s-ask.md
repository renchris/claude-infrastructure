# An allow rule cannot silence a hook's ask

_Relocated VERBATIM from `.claude/rules/agent-operating-lessons.md` (always-loaded tier) — the rules file now carries the hook and links here. Nothing was shortened._

[An allow rule cannot silence a hook's ask](.) — 2026-09-11, the permission-prompt census (`docs/research/permission-prompt-census-2026-09-10.md`): asked to "improve the allowlist so there are fewer permission prompts", the honest answer is that **most of ours are unreachable from `settings.json`**. Replaying all 2,838 archived Bash prompts of the prior 30 days through today's hook chain, **1,038 are hook-emitted** (721 of them one reason, `rm -r on non-build-artifact target`) — and a 3-arm probe on the live binary (2.1.260), one variable, positive control green, settles what the docs only imply: arm C (allow rule `Bash(sh -c:*)`, no probe hook) RAN; arm A (a hook returning `permissionDecision:"ask"`, no allow rule) BLOCKED; arm B (**both**) BLOCKED with the hook's own reason. ⇒ **a `permissions.allow` rule does NOT suppress a PreToolUse hook's `ask`**, so no allowlist edit can remove a hook-emitted prompt — the lever for those is the HOOK, and conversely adding an allow rule is SAFE with respect to a guard hook, because that hook's `ask`/`deny` survive it (this is what makes `Bash(curl:*)` addable without disarming `hooks/curl-gate.py`). The mirror direction is documented and **contradicts a belief written in our own hook headers**: code.claude.com/docs/en/permissions says *"Hook decisions don't bypass permission rules … a matching ask rule still prompts even when the hook returned `allow` or `ask`"*, while `hooks/smart-bash-allowlist.sh`'s header asserts *"a PreToolUse hook emitting 'allow' BYPASSES the permission system"* and justifies retiring its rules 2 and 4 on that basis — the retirement was right for other reasons, but the stated mechanism is false today (it may have been true at the 2.1.114 era it was written in; unmeasured either way, so treat it as UNKNOWN, not as fixed). 🚨 **The instrument half, and the reason this needed a binary at all: the obvious natural experiment was an ARTIFACT.** Asking "did any hook-ask command ALSO match an existing allow rule and prompt anyway?" with a naive prefix matcher returned **562 of 1,038** — every one a `cd …`-prefixed compound command, because Claude Code evaluates each STATEMENT of a compound command and a `Bash(cd:*)` match on the first statement is not an allow of the whole line. Restricted to single-statement commands the overlap is **0 of 16**: the corpus contains no case where both states hold, so it could never settle the question in either direction, and the 562 had to be withdrawn. ⇒ **before quoting a corpus overlap as evidence, check that the two conditions are ever simultaneously TRUE in it** — an overlap computed with a matcher coarser than the system's own evaluation unit measures the matcher.
