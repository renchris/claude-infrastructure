# A gate's surface is not its traffic

[A gate's surface is not its traffic](.) — 2026-09-10, cc-backlog `f5c3cfb86e2e` (landed): the duplicate-worker lease had a consumer on `PreToolUse|Write|Edit|MultiEdit` and a coverage suite asserting it was WIRED and REACHABLE — the suite's whole purpose, written after a correct decision reached a journal and no actuator. It was green for a month while the fleet was ungated, because auto mode's standing session instruction is *"make file changes with sed, heredocs, or short scripts, rather than using the dedicated Read, Edit, or Write tools"*, so the routine edit never crossed that matcher. MEASURED: pane 71 appended two blocks to `hooks/lib/mailbox-pending.sh` in `wt-0366d5cc7b87` via a `python3 - <<'PY'` heredoc under Bash with NO refusal while holder pane 70 was mid-edit on the same file, producing a duplicate `mailbox_peek_from` that shadowed the holder's; `cc_worker_claim_admit` run by hand in that same shell returned REFUSED. ⇒ **a coverage test proves a gate is reachable on the SURFACE it names, never that the traffic still crosses that surface** — so when a suite certifies an enforcement point, separately ask *where does the work actually flow today*, and treat a mode-level instruction that reroutes a tool class as a population change that silently empties every gate keyed on the old class. Third instance of the empty-population shape in this one file (the in-process depth cap, whose population is empty by harness construction; the per-session spawn counter that reset at exactly the edge the cascade crossed; now this). 🚨 **Second half, separable and about REFUTATIONS: a closed row inherits the coverage of the enforcement point it rests on, and inherits it silently.** `b03eb3f28845` was closed REFUTED on *"a PreToolUse deny IS the turn boundary a message lacks"* — the reason this repo deliberately never built a stand-down actuator for a refused worker. Sound where the deny fires; on the Bash write path it never fired, so the stand-down channel was silent on the commonest write path and nothing re-checked the row when the traffic moved to a surface the row never named. ⇒ when a refutation rests on a mechanism, record WHICH surfaces that mechanism covers, and re-read it whenever a new surface appears. Companions, each separable: (a) **a mutant that breaks the subject's syntax attributes nothing** — commenting out the invocation reddened the pane-spawn cases too, because it is the middle line of a multi-line `if ! VAR=… \` continuation and the file stopped parsing; every end-to-end case then failed for one reason unrelated to the gate. The mutant that attributes is the one reproducing the PRE-FIX STATE with the file intact (`_wbw_hit=0` forced), whose red set is two cases rather than five. (b) **a pure-insert into a hook re-pins every line-keyed fixture below it** — `tests/fixtures/validate-bash-sites.tsv` pins 33 grep sites BY LINE, so a 154-line insert at 540 moved 31 of them and reddened 6 of 7 differential cases; the A/B against pristine `origin/main` is what attributed that to the diff instead of to a pre-existing red, and the suite's own drift assertion is what makes an arithmetic re-pin CHECKED rather than asserted. (c) **a cost filter on the hottest hook needs a forkless pre-screen keyed on the payload** — a write is COMMON where a pane spawn is rare, so `case "$INPUT" in *'/wt-'*` skips the whole term at zero forks outside dispatch worktrees; the substring is implied by the shape the library keys on, so it cannot miss. (d) **over-matching a write filter is SAFE in one direction only, and that asymmetry is the design** — `cc_worker_claim_admit` admits whenever the cwd is not a dispatch worktree or the session holds the lease, so a false shape match can only ever reach a session already required to stand down; but the `/dev/null`+fd-dup strip is load-bearing, because without it `grep … 2>/dev/null` is a "write" and the gate degenerates into a refusal of the whole Bash surface, taking the duplicate's ability to inspect, checkpoint and retire.
