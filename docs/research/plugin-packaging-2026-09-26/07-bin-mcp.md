# 07 — bin/ + tools/ + MCP: what is worth shipping in a Claude plugin

Scope: `/Users/chrisren/Development/claude-infrastructure/bin/` (122 entries = 121 tracked files + `__pycache__`), `tools/` (9 subdirs), MCP config. The repo was not modified. The only tools executed were the `--help` runs.

## 0. Platform facts that decide the packaging (verified 2026-09-26)

| Fact | Source |
|---|---|
| Plugin `bin/` files are added to **the Bash tool's PATH** while the plugin is enabled, so they run as bare commands | code.claude.com/docs/en/plugins-reference § Standard layout, "Executables" row |
| **claude.ai chat and Cowork refuse to install any plugin that has a top-level `bin/`** ("Can't be installed"). Org-sync rejects it with `Plugin contains a top-level bin/ directory` | same row; claude.com/docs/plugins/platform-support table; claude.com/docs/plugins/org-sync § Keep executables out of the top-level bin directory |
| The documented workaround is to put executables in `scripts/` and reference them as `${CLAUDE_PLUGIN_ROOT}/scripts/<name>` from skills, hooks or MCP configs | org-sync page, same section |
| `${CLAUDE_PLUGIN_ROOT}` is **not** in the Bash tool's environment. It is substituted inline in skill, command and agent Markdown bodies, and exported to hooks and stdio MCP servers | plugins-reference § Where each variable resolves |
| Local (stdio) MCP servers: chat = **Ignored**. Cowork = loads only "when the Cowork session runs on your computer". Claude Code = loads. Remote http/sse MCP servers work on all three surfaces (in chat, only after the user connects them) | platform-support table |
| Skills load on all three surfaces. Hooks and agents load in Cowork and Claude Code but not in chat | platform-support table |

**Implication.** A plugin meant for all surfaces must ship executables under `scripts/` and never under `bin/`. A plugin with bare-command ergonomics (a `bin/` directory) works only in Claude Code, so it has to be a separate plugin or variant. The repo's own `commands/read-twitter.md` calls `!`cc-read-twitter "$ARGUMENTS" --images`` as a bare command. In a plugin that line must become `"${CLAUDE_PLUGIN_ROOT}/scripts/cc-read-twitter"`. I did not verify whether plugin-`bin/` PATH also applies to `!` preprocessing.

**Licence blocker (all rows).** The repo has no LICENSE file (`ls LICENSE*`: no match), so all rights are reserved by default and a stranger cannot legally reuse the code. `vendor/codex-security/LICENSE` is Apache-2.0 third-party (OpenAI) code with a NOTICE.md. Do not re-ship it.

**Python floor.** Every Python candidate below ran `--help` cleanly under `/opt/homebrew/bin/python3.9`, and macOS `/usr/bin/python3` is 3.9.6. None needs a newer interpreter.

- `git grep` for FastMCP, `mcp.server`, `@modelcontextprotocol/sdk` and `McpServer(` finds only two MCP-speaking files, neither a shippable server:
  - `tests/fixtures/mcp-noinherit/fake-stdio-server.py` (126 lines): a stdlib stdio server that answers `initialize`, `tools/list`, `ping` and `tools/call`. It exists as a spawn-counting test fixture.
  - `scripts/lib/ms365_stdio.py`: an MCP **client** that drives ms-365-mcp-server directly.

**Could a bin tool be wrapped as a small MCP server for surfaces without bash?**
- **Which surface gets what.**
  - **Chat** ignores local MCP servers. Only a *hosted remote* http MCP reaches it.
  - **Cowork** loads local stdio MCP servers only when the session runs on the user's computer. It refuses any plugin that has a `bin/`.
  - **Claude Code** has bash, so an MCP wrapper adds little there.
- **`cc-read-twitter` → `read_x_post` is the one wrap worth doing.**
  - Why it fits: it needs network only, is stdlib-only, and its logic is already split into importable functions (`src_fxtwitter:90`, `src_syndication:182`, `src_jina:251`, `render:415`, `download_images:479`).
  - The tool would take `{url, single?, images?}` and return markdown text plus MCP `image` content blocks, so no file `Read` is needed.
  - Stdio version for Cowork and Claude Code: about 100-150 lines of stdlib Python, reusing the fixture's JSON-RPC loop. Wired in `.mcp.json` as `python3 "${CLAUDE_PLUGIN_ROOT}/mcp/xread.py"`, it needs no pip install.
  - Chat needs a remote http port (for example a Cloudflare Worker: two JSON GETs, plus the syndication-token function at `:162`).
  - Caveats: whoever hosts it pays for egress and carries the third-party-API dependency on fxtwitter, twimg syndication and jina.
- **Plausible but low-yield wraps.**
  - `cc-token-ledger` (`--json`), `cc-agent-harvest` (`--json --dry-run`) and `cc-permission-audit` only make sense where `~/.claude*/projects` transcripts exist, which is a Claude Code host that already has bash.
  - Unverified: whether a Cowork-launched local MCP process can read `~/.claude`.
- **Do not wrap.**
  - `cc-mail-images` and the ms365 scripts: on chat and Cowork the official Microsoft 365 connector plus a skill covers them. Wrapping would put an MCP inside an MCP.
  - `claude-accounts` and `msg`: token and personal-data exposure.

## Adversarial pass (run with tool calls, integrated above)

1. **"bin/ just works everywhere."** Refuted: chat and Cowork refuse any plugin with a top-level `bin/` (platform-support table). Packaging recommendations were changed to `scripts/` + `${CLAUDE_PLUGIN_ROOT}`.
2. **"Stdlib python means any python."** Tested: every Python candidate ran `--help` under python3.9. `motion-probe.py` has undeclared pip deps (opencv, numpy) missing from `requirements.txt`.
3. **"Low-coupling means privacy-clean."** Grepped every bin file for `chrisren` and email. None of the 15 table rows hardcodes the username. Hits are in cc-owner, cc-lid, cc-fleet, dia-cdp-launch.sh, cc-reaper, it2-* and others (all T3). Residual leaks in shippable rows: `ms365-compose-body.py:33-35` (name and signature id) and `permission_matcher.py:1395` (`~/Development` root).
4. **Hidden GNU-isms.** The table rows have no `timeout`/`gdate` use. `cc-memory-rotate` uses BSD `stat -f` (×8), so it is macOS/BSD-bound until ported. `qos-rewrite.sh` uses `timeout`, which macOS lacks by default.

**Open uncertainties:**
- Whether plugin-`bin/` PATH reaches `!` command preprocessing.
- Whether a Cowork local MCP server can read `~/.claude*`.
- Whether chat's code-execution sandbox egress allows fxtwitter, which would decide whether a skill-only X reader can work in chat without a hosted MCP.
