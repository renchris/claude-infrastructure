## Blocker that applies to every row

- **The repo has no LICENSE** (`ls LICENSE*` at the repo root finds nothing). Anything we authored is "all rights reserved" by default. So a plugin with no license of its own gives a stranger no legal right to use or redistribute even the T1 skills. The plugin needs its own LICENSE before any T1 or T2 skill ships.
- **Plugin runtime:** skills run from the plugin cache. Every `~/.claude/...`, `~/bin/...`, `scripts/...` or `bin/...` reference has to become `${CLAUDE_PLUGIN_ROOT}/...`, with the file bundled, or it has to be deleted.

## Actions for the repo itself, whatever the plugin decision

- `skills/account-relogin/SKILL.md:128` publishes a personal email address in a public repo.
- `skills/grok-wiki-cli/` (and probably `grok-wiki-custom/`) redistributes all-rights-reserved upstream text in a public repo. The LOCAL_ONLY criteria already cover this class.
- `skills/dia-agent/SKILL.md:224,289` and `skills/corpus-to-skill/SKILL.md:32` carry personal identifiers (the `com.chrisren` plist label and a private repo name). This is minor.

## Alternatives considered and ruled out

- **Ship agent-browser because Apache-2.0 allows it.** Ruled out: it would be a stale fork of vendor text that the CLI now serves version-matched (`agent-browser skills get core`).
- **Ship the frontier-* suite as one plugin with its hook and agent bundled.** Possible (about 15 KB closure), but the gate reads a personal `frontier_access` window (`frontier-run/SKILL.md:15`, `hooks/frontier-spawn-gate.sh:36,149`) and encodes one operator's budget policy. The value/effort ratio is poor.
- **cc-version-audit as T2.** The portable kernel is about 30 lines. Everything else is fleet verdict history, so it is a rewrite, not a decoupling.

## Adversarial pass (gaps checked)

1. *"Is codex-security already a Claude plugin upstream?"* No. The `openai/codex-security` tree has only `plugins/codex-security/.codex-plugin/plugin.json` and no `.claude-plugin`. License is Apache-2.0 and it is still maintained (pushed 2026-09-25), which means our vendored copy is stale.
2. *"Is grok-wiki-cli ours or theirs?"* Theirs: the body is byte-identical and the upstream license is null. This changed its tier from T2 to T4 and surfaced the existing-exposure issue.
3. *"Is frontend-design-vue derived from a third-party kit?"* No attribution or adapted-from markers, and no Signal/Foundry/Meridian match in `vendor/uidotsh`. The only third-party names are font citations (`references/typography.md:11`).
4. *"Hidden PII?"* An email/identifier sweep over all 20 found only `account-relogin:128`, `dia-agent:224,289` and `corpus-to-skill:32`.
5. *Unverified:* whether Claude Code plugin skills honour `allowed-tools` frontmatter the same way user skills do. This affects agent-browser and dia-agent only.
