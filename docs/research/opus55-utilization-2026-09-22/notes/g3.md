# g3 — At what effort were the SWE-bench / DeepSWE / ProgramBench / multi-agent / large-team runs made?

Source: Claude Opus 5.5 System Card (/tmp/opus55-src/syscard.pdf), pp.3, 174-176, 183-184, 189-199; linked docs effort.txt, prompting.txt, announce.txt.
Charts on pp.190-197 inspected visually (Read tool on the PDF).

## Bottom line (answer to the gap question)
- The ONLY global effort default is the caption of Table 8.1.A (p.174): "Unless otherwise noted, all Claude Opus 5.5 results use the following standard configuration: adaptive thinking at max effort, default sampling settings (temperature, top_p), averaged over five trials. Terminal-Bench 4.0 score is reported at xhigh effort."
- The caption sits under the TABLE. Rows covered directly: SWE-bench Pro 89.9, Multilingual 93.9, Multimodal 61.4, FrontierCode Main 54.4, Terminal-Bench 4.0 66.4 (xhigh exception), HLE, OSWorld, HealthBench, GDPval-AA, AA-Briefcase, AutomationBench.
  - Corroboration the table really is at max: FrontierCode row shows 54.4 = the value p.176 states "At max effort, Opus 5.5 scores 54.4% on Main", although its best score (54.6) is at medium.
- NOT in Table 8.1.A, so the caption reaches them only if read as a chapter-wide default: DeepSWE (74.2%, p.175), single-agent ProgramBench (91.2%, p.183), multi-agent ProgramBench (pp.189-191), large teams (pp.193-197). None of these sections names an effort.
- §1.4 (p.~4): "Unless a section says otherwise, the evaluations in this system card were run on the final snapshot ... Each section states its configuration." — the card promises per-section configuration, yet 8.3, 8.10.1, 8.12.1 and 8.12.3 state none.
- The one explicit statement is p.193, first line after the DRACO discussion (8.12.2): "All of these runs are at max effort." Its scope is written after the DRACO figure and paragraph; it could be read as covering 8.12.2 only, or 8.12.1-8.12.2. Not stated for 8.12.3.
- The multi-agent sections visibly depart from the Table default in other respects: DRACO points are "the mean of two runs" (not five), large-team points "averaged across three distinct attempts" (not five), multi-agent ProgramBench used "an alternate, broadly comparable snapshot", large teams used "a slightly different model version than the released one". So the Table configuration was NOT uniformly applied in 8.12; carrying "max effort" over to 8.12.1 and 8.12.3 is inference.
- Comparison models (Opus 5, Fable 5.1) in large-team figures and ProgramBench single-agent: no effort stated. Table caption says "See the Claude Opus 5 System Card for evaluation details of earlier Claude models."
- Other chapter-8 sections restate max explicitly even where it matches the default (Chartography p.199 "configured with adaptive thinking and max effort enabled in all runs"; BenchCAD; Toolathlon Table 8.14.5.A; HealthBench Fig 8.15.1.A; GMMLU/MILU). HLE (p.184) instead says "thinking was set to auto" with no effort named.

## Section-by-section
### 8.2 SWE-bench (p.175)
"We report three variants, where each score is an average over five trials". No effort. Table 8.1.A: Opus 5.5 89.9/93.9/61.4; Opus 5 79.2/89.5/59.4; Fable 5.1 81.2/89.1/54.7 (Pro/Multilingual/Multimodal).
### 8.3 DeepSWE v1.1 (p.175)
113 long-horizon SWE tasks. "Claude Opus 5.5 scored an average of 74.2% over five trials." No effort, no comparison models, not in Table 8.1.A.
### 8.10.1 ProgramBench single agent (p.183-184)
166 tasks (34 excluded), mini-swe-agent harness, no six-hour limit. Opus 5.5 91.2%, Fable 5.1 87.6%, Opus 5 85.4%. No effort, no trial count. "episodes cover a range of context lengths up to the full 1M token window". §8.12.1 says the 8.10.1 config "used a 1M token budget".
### 8.12.1 Multi-agent ProgramBench (pp.189-191)
- 166 golden tasks (differs by 4 from 8.10.1). Fixed 5-agent team vs async subagents vs single agent. Single-agent baseline uses "context compaction and a 20M token budget". Alternate snapshot. No effort, no trial count.
- Legend (chart): single agent (20M token limit); 5-agent team (4M token limit per agent); async subagents (1M token limit per agent).
- Fig 8.12.1.A (latency): 5-agent team reaches 0.6 "with ~2.7x less latency than the single agent". Approx. from chart: team ~2,200 s, async ~4,000 s, single ~6,000 s to 0.6. All converge ~0.97 by ~100,000+ s.
- Fig 8.12.1.B (tokens): approx. single agent reaches 0.6 at ~0.55M tokens and ~0.85 at ~1M; 5-agent team 0.6 at ~1.1M; async 0.6 at ~2M; async runs to ~60M tokens. Text: teams "reach a given score faster at a higher cost".
### 8.12.2 Multi-agent DRACO (pp.191-193)
- 100 tasks, single-task latencies 13-71 min. Each point mean of two runs. Latency budgets 1.0/0.75/0.5/0.25x single-agent latency.
- "At a latency budget of 0.5x, the five-agent team is capable of more than matching single-agent performance, with a roughly 2.8x speedup."
- Chart approx: single standard ~87.2 @ ~2,200 s; 5-agent standard ~89.7 @ ~2,700 s; async standard ~89.4 @ ~3,300 s; 5-agent 0.5x ~88.0 @ ~780 s; 5-agent 0.25x ~84.6 @ ~400 s; single 0.25x ~79.8 @ ~350 s; async 0.25x ~80.1 @ ~370 s; single 0.5x ~83.3 @ ~720 s.
- p.193: "All of these runs are at max effort. Note that while reducing effort and tightening a latency budget can both bring down task latency, these two dials have a fundamentally different effect ... The former results in less work overall, whereas the latter preserves more of the work".
- Async lead at tight budgets "spawns them at a much lower rate and prefers to act as a single agent".
### 8.12.3 Large agent teams (pp.193-198)
- 1/10/30/100 agents, 24h, "The quantitative results come from a slightly different model version than the released one; performance is comparable." No effort, no token budget stated. Averaged across three attempts.
- Fig 8.12.3.A Knowledge base (1/10/30/100): Opus 5.5 0.53/0.70/0.71/0.74; Fable 5.1 0.53/0.66/0.69/0.68; Opus 5 0.45/0.64/0.65/0.68.
- Fig 8.12.3.B Lean (1/10/30/100): Opus 5.5 0.39/0.66/0.66/0.68; Opus 5 0.19/0.44/0.55/0.58; Fable 5.1 0.16/0.33/0.45/0.53.
- Fig 8.12.3.C KB over time Opus 5.5: 2h 0.37/0.53/0.66/0.69; 6h 0.47/0.64/0.68/0.71; 24h 0.53/0.71/0.71/0.74 (note 24h@10 plotted 0.71 here vs 0.70 in Fig A).
- Fig 8.12.3.D Lean over time Opus 5.5: 2h 0.07/0.15/0.34/0.44; 6h 0.14/0.42/0.58/0.64; 24h 0.39/0.66/0.66/0.68.
- Harness: one lead + N-1 helpers, one shared Linux machine, no network, shell/file editor/Send Message/Wait for Message, shared Git repo; instructed to check time. 100-agent Lean team self-organised 12 sub-leads; KB team flat.
### 8.12.4 / 8.12.5 harness & methodology (pp.198-199)
No effort. Token counting: every token entering a context window counted once per window, summed over agents. Latency derived from fixed reference prefill/decode rates + measured tool time.
### Linked/operator docs
- effort.txt: Opus 5.5 default effort is medium ("The default on Claude Opus 5.5"); other models default high.
- prompting.txt: small-team research evals — "A tighter budget has a different effect from a lower effort setting: lowering effort reduces the work itself, whereas a budget mostly keeps more agents working in parallel." No effort named. Also: "at its default medium effort the model matched or beat Claude Opus 5 at high effort" on agentic coding (no benchmark named).
- announce.txt: no effort info for SWE-bench, DeepSWE, ProgramBench or team results.
- System card p.3: "much of the improvement is available below maximum reasoning effort."
