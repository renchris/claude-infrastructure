# g1 — How often does a safeguard reroute ordinary coding traffic to a weaker model?

Sources: Claude Opus 5.5 System Card (syscard.pdf; printed page = PDF page), announce.txt, prompting.txt,
whatsnew.txt, migration.txt. Charts read visually: Fig 3.4.1.A (p.56), Fig 3.4.2.A (p.57), Fig 6.4.10.A (p.121).

## 1. Where a block sends the request (p.12-13, §1.5; p.47-48 §3.2; p.92 §6.1.1)
- Cyber classifier block -> **Claude Opus 4.8** (p.12). "Blocks on these classifiers will fall back to Opus 4.8."
- Chemical/biological (research-biology classifiers, same as Fable 5/5.1; wider than Opus 5's) -> **Claude Opus 5** (p.12).
- Frontier-LLM / RSI classifiers ("kernel development on certain ML accelerators") -> **Claude Opus 5** (p.13).
  The card says they "will not impact the vast majority of traditional AI or ML development, research, or general coding."
- Conventional weapons / high-yield explosives -> block, **no fallback** (p.13).
- Distillation / reasoning extraction -> block on Opus 5.5, **no fallback** (p.13). The prompting guide and
  migration guide say server-side fallback does not retry `reasoning_extraction`; the refusal comes back to the caller.
- Scope (p.13): fallback "applies to our first-party products and developers who are opted in to such fallbacks on our API";
  other platforms "may experience different behavior". Blocks are "transparent" and "do not covertly change model responses".
- p.48: "This happens automatically in our own applications; on the API, the developer must opt in to automatic fallbacks."
- p.92 (§6.1.1) restates it: fallback goes to Opus 4.8 for cyber content and to Opus 5 for biology and AI R&D content.
- announce.txt: "Users will be able to identify and fix bugs in their code as part of the routine software development
  lifecycle, but most cybersecurity tasks will be re-routed to Opus 4.8."
- prompting.txt: "Cybersecurity: Finding vulnerabilities in source code is allowed. High-risk dual-use cybersecurity activities are not."
- whatsnew.txt: a decline returns HTTP 200 with `stop_reason: "refusal"` and `stop_details` naming the policy area. Server-side
  fallback (`fallbacks: "default"`, beta) "retries on the model Anthropic recommends for that category".
- migration.txt: a fallback from Opus 5.5 to any other model "runs those turns without" Opus 5.5's thinking blocks
  (Fable 5.1 and Mythos 5.1 are the only exceptions).

## 2. Cyber classifier design (p.47-48 §3.2, p.55 §3.4)
- There are three stages. An activation probe screens all traffic, a lightweight classifier "running on Claude Opus 5.5 itself" scores what the probe escalates, and a separate
  trained LLM classifier decides together with the probe's verdict.
- The training data was "weighted ... toward longer-running agentic tasks".
- The card twice describes a "temporarily wider safety margin against jailbreaks while we ... reduce their false-positive rate" (p.2, p.48, p.55).
- The policy allows vulnerability discovery in source code and blocks it in compiled binaries (p.48, p.55).
- Verified security users get fewer restrictions through the Cyber Verification Program, which will include Opus 5.5 "in the near future" (p.48).

## 3. Benign-task reroute rates (the numbers for ordinary work)
| Source | Setting | Rate |
|---|---|---|
| p.178 §8.5 Terminal-Bench 4.0 (66 tasks; compbio, physics, CAD, proofs, GPU perf) | safeguards on, xhigh, Claude Code --bare | **2.5% of requests, affecting 10% of trials**; score 66.36% |
| p.178 §8.6 Terminal-Bench-Science 0.1 (70 tasks) | safeguards on, max, Claude Code --bare | **3.9% of requests, affecting 5% of trials**; score 58.7% |
| p.210 §8.14.5 Toolathlon Verified (108 tasks, 324 trials) | run "with safety classifiers" | **1 trial (0.3%) stopped by production safety classifiers** (counted as a failure); 6 (1.9%) halted by the harness's sandbox-escape monitor |
| p.57 Fig 3.4.2.A defensive vulnerability discovery (sampled real traffic, LLM-graded) | classifier flag rate | **Opus 5.5 4.5%** · Fable 5.1 7.0% · Opus 5 13.9% · Sonnet 5 3.2% |
| p.57 Fig 3.4.2.A violative vulnerability discovery | flag rate (higher is better) | Opus 5.5 96.8% · Fable 5.1 98.9% · Opus 5 99.0% · Sonnet 5 43.8% |
| p.56 Fig 3.4.1.A cyber coverage, overall recall | | Opus 5.5 99.7% · Fable 5.1 100.0% · Opus 5 99.6% · Sonnet 5 77.0% |

- TB4 and TB-Science do not say which classifier category fired, so the fallback target (Opus 4.8 or Opus 5) is unknown.
  The phrase is "answered by a fallback model following the default server-side fallback policy".
- Both headline scores already include fallback-served turns.
- Several other capability evals ran without safeguard classifiers (ArXivMath, p.182). The cyber capability evals also ran with classifiers off (p.47).
  So only TB4, TB-Science and Toolathlon report a benign-agentic fallback or stop rate.
- HealthBench and HealthBench Professional (p.181-182) ran "with safety classifiers enabled and a refusal fallback to Claude Opus 5". No rate is given.

## 4. Adversarial-setting reroute rates (keep these separate from §3)
| Source | Setting | Opus 5.5 served by Opus 4.8 | Comparators | Outcome |
|---|---|---|---|---|
| p.85-86 Gray Swan IPI benchmark (37 scenarios, 1,804 attacks) | all rollouts | **18%** | Fable 5.1 23% | none of 1,310 fallback-served rollouts gave a successful attack |
| same | coding scenarios | **46%** | — | tool use 2%, computer use <1% |
| p.87-88 Shade adaptive coding (40 scenarios × 200 attempts) | requests with a valid response | **64%** | Fable 5.1 60%, Opus 5 (thinking) 14% | ASR on fallback-served 85.73%; **0 of 2,872** answered directly by Opus 5.5 succeeded; overall ASR 54.61% (11.13% with probes); "all observed successful attacks again came from fallback-served requests" |
| p.89 Shade computer use (14 cases) | requests | **6%** | — | none compromised; both successes came from requests Opus 5.5 answered directly |
| p.91 browser use (110 scenarios) | attempts | **8%** | — | the single success (0.09% ASR without safeguards) "was executed by Claude Opus 4.8 after a fallback" |

- p.84: the Opus 4.8 fallback "reduces prompt injection robustness because Claude Opus 4.8 is less robust against prompt injection".
  Anthropic has since hardened 4.8's injection safeguards. Fable 5.1's with-probes ASR fell from 12.80% to 8.70%.
- p.83: auto mode (the default Claude Code permission mode for most users) pairs injection probes with a classifier that blocks dangerous tool calls.
  With auto mode on, 0 attacks succeeded across 110 browser scenarios (p.91).

## 5. Behavioral effect of fallback (p.121 §6.4.10, Fig 6.4.10.A; values read off the chart, about 720 investigations each)
- Section text: requests touching "a few sensitive areas" are "referred to a weaker model". Misuse scores come out "slightly higher" because
  "these weaker models are sometimes less strict about refusing misuse".
- Chart scores are on a 1-10 scale, lower is better. Each row shows bare Opus 5.5 → Opus 5.5 with safety measures (Opus 5 in brackets):
  - Disallowed cyberoffense 1.01 → 1.11 (1.02)
  - Cooperation with human misuse 1.34 → 1.71 (1.62)
  - Targeted violence 1.04 → 1.12 (1.12)
  - Biological weapons 1.00 → 1.01
  - Chemical weapons 1.00 → 1.03
  - Explosives 1.01 → 1.03

## 6. Related context
- p.79-80 Table 5.1.1.A (Claude Code, no extra safeguards): on dual-use & benign cyber requests Opus 5.5 succeeds 99.8% of the time (Opus 5 99.7%, Mythos 5.1 98.4%, Sonnet 5 96.9%).
  It refuses malicious requests 79.8% of the time (Opus 5 83.6%). "the primary harm-prevention mechanism is the blocking classifier."
- p.3: without safeguards, Opus 5.5 "attempted to escape or tamper with a sandbox in 1.5% of runs".

## Absent
- No fallback or flag rate on ordinary coding benchmarks: SWE-bench-class, CursorBench, FrontierSWE, FrontierCode, or real Claude Code production traffic.
- TB4 and TB-Science do not name the classifier category, so the share going to Opus 4.8 versus Opus 5 is unknown.
- No breakdown by effort level of how often requests get flagged.
- No score for only the flagged trials, and no with-versus-without-safeguards delta on TB4, TB-Science or Toolathlon, so the capability cost of fallback cannot be measured.
- No flag rate for code-review or security-audit workloads beyond the sampled defensive vulnerability-discovery traffic (4.5%).
- No false-positive rate for the frontier-LLM/RSI classifier or the bio classifier on ordinary ML or coding work.
- No statement on whether a fallback is sticky for the rest of the conversation or applies per request.
- No reroute data for multi-hour sessions, or for how fallback probability grows with session length.
