The row text is operator data and is not rewritten here. This audits what the renderer chooses to make resident.

## Intent the board serves

Every session sees the stale customer deliverables, knows they outrank infra, chore and docs work, and either works the top row or says in one line why not. Four supporting rules ride with it: `cc-mission next` prints the top row's action; an agent may advance a row to `awaiting-signoff` and no further (`cc-mission touch` refuses `signed`/`live` with exit 3, so this is mechanically enforced); only the operator's `cc-signoff` marks a row done; a NEEDS-SOURCE row's only action is drafting the ask.

The board is also one session stale by design (the SessionStart hook rewrites it after instructions are read), which is fine for day-scale clocks and unaffected by this change.

## Compact render

Behind a flag. One line per stale row: `lead · venue · artifact — clock age · flags — headline \`id\``, where headline is the row's optional `headline` field (at most 200 chars, set with `cc-mission touch <id> --headline "<text>"`), or, when absent, `next` whitespace-folded and cut at 200 chars with `…`. One intro paragraph restates the four rules without emphasis and points to `cc-mission next` (top row in full) and a new `cc-mission show <id>` (any row in full). The no-stale branch is already one line and is unchanged. With the flag off, output is byte-identical to today's (verified with `cmp` against the unmodified renderer on the same rows).

Flag: the file `~/.claude/autonomy/customer/render-compact` turns it on; `CC_MISSION_COMPACT=1|0` overrides either way. A file rather than an env var alone, because three processes render (session start, `touch`, `seed`) and must agree on the format; an env var set in one would flip the board back and forth.

Method: each text written to `<scratch>/CLAUDE.md`, then `cd <scratch> && /Users/chrisren/.claude-280/node_modules/.bin/claude -p "/context"` (Claude Code 2.1.280, claude-opus-5-5), reading the Project memory row. | Full (today) | 13,998 | 5.5k | — |
| Compact, fallback (A) | 2,418 | about 970 (939 measured at 2,336 B) | about −4.53k (−82%) |

The saving applies to every context on every account (main sessions, subagents, workflow agents, headless runs) as long as rows are stale, and it grows with the rows: the full render's size is the sum of the `next` essays, which rows only ever append to (two rows already carry "prior note, preserved verbatim" blocks), while the compact render is bounded at about 250 chars a row.

It also shrinks the mid-session cost ab903ba4e measured (546 diff injections, 3.79M chars into live contexts over 14 days): in compact mode an edit to a row's `next` changes the board only if it touches the first 200 characters (or the row has a headline, in which case never), so most row updates stop re-notifying live sessions at all. Flipping the flag rewrites the board once, which is one injection into each live session.

## Rollout, A/B and rollback

- Precondition for enabling: set a `headline` on every stale row (`cc-mission touch <id> --headline "<the action, <=200 chars>"`; sample B shows candidates taken verbatim from each row). The fallback headline is the first 200 characters of `next`, which on three of today's five rows is capitalised history ("RESOLVED BY AUTHENTICATED READ", "BLOCKER REFUTED", "THE BLOCKING FIELD IS NOW NAMED…"), so without headlines that emphasis still reaches every context. Choosing the headlines belongs to whoever maintains the rows.
- Enable: `touch ~/.claude/autonomy/customer/render-compact`; the next session start (or any `cc-mission touch`) renders compact. Disable: remove the file; the next render restores the full format.
- The board is one file shared by every account (the account dirs symlink `rules/`), so the per-account CLAUDE.md A/B cannot vary it. Test it by time window: alternate the flag by day, and compare, per session, whether the session works a mission row or states why not (the behaviour the board exists for), plus the number of `cc-mission next` / `show` calls (the cost of reading on demand).
- Quality risk: low for the top row (one command away, and the rule already names that command); moderate for rows two to five under the fallback, whose first 200 characters can be history. Setting `headline` on each row removes that. No other consumer parses the board: `bin/cc-signoff` recomputes state through `cc-mission render` and reads rows, not the board text.
