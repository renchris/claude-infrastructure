## Findings from this chunk

1. The loader strips HTML comments from memory files (measured with `/context` on 2.1.280: a 2,897-byte comment-only `CLAUDE.md` produced no memory row; the same text uncommented read 1.1k tokens). Comments in resident files are free, and a sentinel inside one is invisible, which is what broke the rules-essay probe (see `C6.rules-essay.md` Finding 1).
2. `.claude/CLAUDE.md` cites `hooks/validate-bash.sh:1352` for the ff-only deny; in this worktree the deny is at line 1432 (the FF-GATE block begins at 1252). The slim text names the hook, not a line. `scripts/deploy-live.sh:14` repeats the stale citation.
3. `hooks/memory-nudge.sh:511-521` still says `~/.claude/rules/` is dark under `claude -p`, which the rules essay and `bin/cc-mission:18-20` refute.
4. The per-account A/B for the slim global file cannot cover `~/.claude/rules/` (one directory, symlinked from every account dir) or this repo's `.claude/CLAUDE.md` (loaded by repo path). Parts 2-4 therefore test by time window, not by account.
