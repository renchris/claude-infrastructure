# claude-infrastructure — Project Memory

## Never commit or land in the shared checkout

`~/Development/claude-infrastructure` is the symlink source for `~/.claude` and often sits on another session's branch. Work in a dedicated worktree, commit on your own branch, and land via the project-local `/ship`. Verify a landing by content (`git ls-tree origin/main -- <paths>`), never by commit count.

## Standing-land authorization (this repo only)

Complete, gate-green work committed on your own branch lands via the project-local `/ship` without a fresh ask; never a bare `git push`.

## Standing-converge authorization (this repo only)

`~/.claude` is a per-file symlink farm over this checkout (most of `skills/ hooks/ bin/ scripts/ commands/`), so a landed commit runs nothing until the shared checkout advances. Converge your own just-landed, content-verified work without a fresh ask, on the degraded tier:

```
CC_DEPLOY_MAX_LAG_COMMITS=0 bash scripts/deploy-live.sh
```

`.claude/settings.json` allows this command in two exact spellings (relative and absolute script path); an agent may not otherwise alter the gating and then deploy. If the call is refused, run the bare `bash scripts/deploy-live.sh`, which waits out the lag budget, or surface it as `⛔`. The degraded tier relaxes the lag budget and keeps the evidence checks: it takes the newest not-RED commit, refuses a trunk that is red all the way down, runs `install.sh` so new tracked files get their symlinks, and pages the unverified advance.

- Never pass `--force`: it takes trunk's tip regardless of RED stamps and bypasses the T1/T1H/T2/T3 ladder. It is the operator's escape hatch.
- Not covered: a bare `git merge --ff-only` or `git pull --ff-only` in the shared checkout (denied by `hooks/validate-bash.sh`; it advances files without creating symlinks), `--bootstrap`, and any advance while the ladder reports T3/BLOCKED. A refusal about evidence is a `⛔` to surface, not a setting to change.
- Some live files are copies, not symlinks, written by `install.sh` only when a converge advances: `CLAUDE.global.md` → `~/.claude/CLAUDE.md`, `githooks/`, `launchd/*.plist`, `statusline.sh`, `bin/it2-wrapper` → `bin/it2`. After a land that changes one, check the live copy once the converge finishes; if the converge did not advance to your commit (refused, "already deployed", or an older not-RED target), apply the same edit to the live copy.
- Rationale and the permission measurements, for when you change these rules: the header of `scripts/deploy-live.sh` and `_why_converge` in `.claude/settings.json`.

## The global instructions live at `CLAUDE.global.md`, never at a root `CLAUDE.md`

`CLAUDE.global.md` is the source of `~/.claude/CLAUDE.md`; `install.sh` copies it out. Do not create or restore a root `CLAUDE.md`: it would load as project memory on top of the user copy, duplicating about 20.7K tokens per session. `tests/deploy-parity.bats` pins its absence. `.claude/CLAUDE.md` (this file) is project-only memory, not a duplicate; keep it.
