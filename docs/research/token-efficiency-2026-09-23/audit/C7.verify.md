- Emphasis: the slim has no bold, CRITICAL/MUST/NEVER or emoji. The capitals that remain (`UNGATED`, `RED`) are identifiers.

## Cross-cutting findings

F1. The slim header contradicts four live hook and script messages (major). The slim says: "Every other lesson is one line in `docs/lessons/INDEX.md` … add a bullet here instead only if it meets the bar above." Four tools still direct every durable rule into this file:
- `hooks/memory-nudge.sh:521-536`: the periodic UserPromptSubmit nudge says "a DURABLE, GENERALIZABLE RULE … belongs in <project>/.claude/rules/agent-operating-lessons.md … put ONE hook line in the rules file".
- `hooks/lib/memory-index-budget.sh:313-346`: a PreToolUse deny text says "WRITE THE RULE TO THE RULES FILE … Append it to ${dest}".
- `bin/cc-memory-rotate:521` and `hooks/memory-index-drain.sh:250`: evicted MEMORY.md lines are routed VERBATIM into this file under `<!-- routed … Both surfaces load unprompted … -->`.
- `scripts/jev/promote-memory.sh:50`: promotes memory into this file.

What happens: an agent that learns a lesson gets opposite instructions from the static file and from the hook. The tools also keep re-inflating the resident file, and the rotor's "nothing was demoted" claim becomes false as soon as an agent follows the slim header and moves routed lines into INDEX.md. Fix: change these messages in the same change, or state the rotor/nudge behaviour in the slim header.

F2. The index hides 47 memory topic files from /compact-memory's reachability check (major). The orphan sweep in `commands/compact-memory.md` §4 excludes three sets: E1 (MEMORY.md), E2 (demotion records) and E3 (citations in `CLAUDE.md`, `CLAUDE.global.md`, `.claude/CLAUDE.md`, `.claude/rules/**`). `docs/lessons/` is not an E3 surface. I ran the command's own E1+E2 harvest over `~/.claude/projects/-Users-chrisren-Development-claude-infrastructure/memory`, then checked the remaining E3 files. 47 topic files that the original rules file keeps reachable would become ORPHAN, and the sweep's step 4 re-indexes orphans into MEMORY.md. That adds about 47 lines to an index at 22,787 of 25,000 chars. The breach then makes cc-memory-rotate route the lines back into this rules file, undoing the slim. Fix: add `docs/lessons/INDEX.md` to the E3 list in commands/compact-memory.md, or move those 47 bodies into `docs/lessons/`. The table below tags the affected lessons "(F2)".

F3. The pointer's trigger does not cover whole classes of moved lessons (major). The slim's only pointer is: "Before diagnosing a failing test, gate, hook, land or fired session, and before designing a detector, fixture, gate or measurement, grep docs/lessons/INDEX.md". The original applied every lesson unprompted, and many of them are preventive: they fire while the agent is acting, not diagnosing. These triggers are not named:
- killing processes or running a kill loop (L100, L159, L166)
- deleting a worktree or directory (L50, and the general half of L72)
- bulk-retiring rows (L114)
- working, filing, closing or re-landing a backlog row (the whole Backlog section: L168, L173, L204, L67, L108 …)
- firing a session (L194)
- resolving a merge conflict (L201)
- writing shell that parses command output (L122, L123, L224, L230, L171, L58, L237 …)
- editing documents that carry file:line citations or integrating review findings (L157, L235)

What happens: a session writes an unguarded kill loop, lands a partly contradicted stranded branch verbatim, or cold-fires under load. The lesson that prevents it now sits in a file the session has no reason to open. Fix: widen the trigger sentence, for example "…and before killing processes, deleting worktrees or branches, resolving a merge conflict, firing a session, filing, closing or re-landing a backlog row, or writing shell that parses command output". Alternatively, promote the destructive ones (L100, L50, L114) to resident under the slim's own "costly mistake" bar.

F4. A standing operator ruling was moved off the resident surface (major). L165 ("Draggable pane title is primary — OPERATOR RULING, do not re-litigate … FORBIDDEN") is now one index line. Its body records that this was the third time the regression reached the operator. The repo ships `scripts/kitty-pane-title-overlay.py`, `scripts/kitty-pane-title-toggle.sh` and `scripts/kitty-title-band-*`, and no hook enforces the ruling. The F3 trigger does not fire for title-bar work, so a session changing those scripts would never read it. Under the slim's own bar ("prevent a costly mistake nobody would think to look up") it belongs resident. Fix: keep it as a resident bullet.

F5. The A/B flag cannot reach this file (minor, deployment gap). The brief says the slim ships behind a per-account CLAUDE.md symlink. `.claude/rules/agent-operating-lessons.md` is a tracked project file that loads for every account from the checkout, and `scripts/loaded-untracked-lint.sh` requires loaded rules files to be tracked. So a per-account flag cannot switch it. C7.labels.md does not say how C7 ships behind a flag. Fix: name the flag mechanism for C7, or state that C7 lands un-flagged.

F6. The rotor keeps routing into the resident file (minor, a facet of F1). The slim header does not mention that `bin/cc-memory-rotate` appends routed lines here. A future reader will see `<!-- routed … -->` blocks with no rule for them.
