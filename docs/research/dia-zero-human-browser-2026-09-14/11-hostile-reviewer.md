# 11 — Hostile reviewer: what the ten axes structurally cannot see

All ten axes are about *getting a socket*. None is about what happens above, after, or around it. Ranked:

1. **Zero-human is defeated at the Claude layer, not the browser.** Every Claude session spawns its own chrome-devtools-mcp → its own CDP connect → its own consent dialog; tool calls then hit auto-mode's classifier and `settings.json`, which allows only `Bash(agent-browser …)` and has **zero** `mcp__chrome-devtools__*` rules — on a fleet of 17–39 concurrent sessions. Changes the rec: the mux is necessary, but "prompt-free" must be proven from a headless `-p` session end-to-end. Check: `grep -c mcp__ ~/.claude/settings.json` (0); `docs/research/permission-prompt-census-2026-09-10.md`; headless loads project `.mcp.json` unconditionally, and reso's ships `chrome-devtools --isolated` → a throwaway Chrome that *reads healthy*.

2. **The browser at 3 a.m. is not the browser at 3 p.m.** Occluded/locked display ⇒ tabs `hidden`, timers frozen, SPAs stop polling; Memory Saver discards background tabs; Dia auto-archives tabs per profile (`~/Library/Application Support/Dia/StorableAutoArchive.json` is populated). App Nap is already off (`NSAppSleepDisabled=1`); nothing else is. Check: `Emulation.setFocusEmulationEnabled`, `Page.setWebLifecycleState`, `Target.createTarget({newWindow:true,background:true})`, Dia's archive-after setting, `caffeinate -dimsu` under launchd.

3. **Dia is Sparkle-updated and has already changed the contract once** (1.37 ephemeral port → 1.48 fixed 9222). The toggle persists (`User Data/Local State` → `devtools.remote_debugging.user-enabled:true`, verified), so 9222 returns after relaunch — but every WS dies, the mux must re-consent into a fresh app, and macOS updates can reset Hammerspoon's TCC grant. Check: `Dia.app/Contents/Frameworks/Sparkle.framework`; a smoke test keyed on `CFBundleShortVersionString` change; `hs.accessibilityState()` in the same probe.

4. **Nobody owns the rail's liveness.** No axis says how the operator learns the mux/consent/socket died; the repo's own rules: a detector with no owner is not an actuator, and a verdict goes where the operator looks. Check: synthetic `Browser.getVersion` through the mux + `lsof -nP -iTCP:9222 -sTCP:LISTEN` + `DevToolsActivePort` mtime, paged via `cc-notify` / the `hooks/lead-crash-watchdog.sh` pane-paint pattern.

5. **Anti-bot blast radius is the operator's real identity.** `Runtime.enable` is the #1 CDP tell (memory `dia-agent-browser-cdp-entrypoint.md:229-233`; rebrowser.net/docs/sensitive-cdp-methods); Puppeteer, Playwright (agent-browser) and chrome-devtools-mcp all issue it, and a Cloudflare/DataDome flag lands on his personal accounts. Check: github.com/rebrowser/rebrowser-patches, bot-detector.rebrowser.net; the mux is the one place to rewrite it.

6. **Governance and contention share one missing boundary.** The browser session enumerates every Space's targets; `Network.getAllCookies`/`Storage.*` are browser-wide; a prompt-injected page can steer into `Personaly`. Meanwhile agent tabs land in the human's window, `Page.bringToFront` steals focus, and one human Cancel on the chrome.debugger infobar detaches every tab (anthropics/claude-code#69287). The operator rejected a separate *profile*, not a separate *window*: pin the mux to `newWindow:true` and deny `Storage.*`/`getAllCookies`/cross-`browserContextId` attach at the mux (enforce at the chokepoint). Prior art: Claude in Chrome's per-site permissions.

**Most likely WRONG axis: 5 (Hammerspoon pid-gated auto-approve).** The dialog is stock Chromium M144 per-connection consent (ChromeDevTools/chrome-devtools-mcp#825, #1794) rendered in TBC Swift. A localhost TCP connect carries no peer pid into the dialog, and dialogs stack (≤3) with no client identity, so "gated on the connecting pid" is a mapping the approver cannot observe — it approves whichever connection heads the queue. Sound rule: approve only inside the mux's own connect window; deny everything else.
