## Verdict first

All 11 cases concern completeness of research, a plan or an implementation (case 22 only marginally: it is a directive, but it follows a "validated" claim). Across them, the same thing happened every time: **the session defined "done" with a check it could satisfy (a grep over plan fields, exit 0 from a sandbox, a structural design gate, "every quote exists in the source", a green suite in the developer shell). The operator's re-ask then triggered a check of a different kind: reachability, the deployment environment, contradiction rather than provenance, omission, the right instance, or the operator's own eye.** The new pass nearly always found something. Where the session measured the yield of repeated passes (case 28: 10 → 7 → 2 new defects; case 30: 7 → 1 → 0 fatal), the loop converged in 3–4 passes. It measured that yield only after the operator pushed, never before claiming complete.

Only 3 of the ~30 holes below are genuinely new operator requirements. Most were findable by desk research using an acceptance check the session already knew about but did not run before claiming. A distinct residue, about a quarter of the holes, was findable only by building or probing: the deployment interpreter, compiler-class errors, unsigned binaries, launchd PATH, and in-app measurement. No amount of upfront reading closes that class.

## Patterns (for synthesis)

1. **Proxy DoD.** Every premature "done" was true against a check the session wrote (a plan-field grep, sandbox exit 0, a ban-list gate, quote provenance, a local green suite). The hole then sat in the gap between that check and the operator's intent (22, 23, 24, 27, 29, 30, 32). Fix: the DoD must carry the *kind* of check the operator's re-ask will apply (reachability, contradiction, omission, deployment env), not only the kind the author can pass.
2. **The re-ask is a new pass, and an unsaturated pass always yields.** When the yield was measured it converged fast: 10→7→2 (T27 19:28:54) and 7→1→0 (T30 22:32:30). It was measured only after operator pressure. A pre-committed stopping rule (independent passes until new-finding yield falls below a threshold, reported with the curve) would have answered "are we 100%?" before it was asked.
3. **Rewrites and fixes reset verification.** In case 30, 2 of 5 defects came from the agent's own last-hour prose; in case 27/28, each pass corrected about 2 of the previous pass's fixes. Verification has to follow every edit, or the claim applies only to the text that was reviewed.
4. **Synthesis is the lossiest step.** Research existed on disk but was dropped at integration: a headline-only read (23b), a truncated read (28c), and /tmp-only artifacts (28b). A mechanical coverage check (every artifact's findings are either integrated or explicitly rejected) closes this class.
5. **Harness ≠ production.** The benchmark config did not match the app payload (25a/25e); the jail did not simulate absence (29c); the dev shell was not launchd (32a/b). "Measured" findings were measurements of the wrong system.
6. **Census failures.** The candidate set was truncated to installed models (25c), the fix went to one of two checkouts (31a), the callers of a command were never enumerated (31c), and the source of truth (the laptop) was never diffed against the repo (29a). Exhaustiveness needs an explicit enumeration of the population, not a sample.
7. **The operator's question is silently substituted.** Examples: "best local model" became "does local beat cloud" (25c); "what calls it" was never in the diagnosis frame (31c); "all tools I use here" became "installer works" (29a).
8. **Subjective acceptance cannot be closed by desk research.** In design cases 23 and 24, ban-list gates and averaging never converge; only an external positive reference plus the operator's eye settles them. That is a different methodology from technical research.
9. **Build-only residue is real and bounded.** About a quarter of the holes (bash 3.2, unsigned binaries, `CLAUDE_CONFIG_DIR` in real modules, compiler-class errors, in-app measurement) were unreachable by reading. The best-behaved session (T27 21:28:23) named that residue explicitly as the reason 100.00 was not claimable. It should be planned as a phase with its own gate, not treated as a failure of research.
10. **Genuinely new operator requirements are a minority.** 30b, 29b and 24b add scope (3 of ~36). Everything else was the session's own frame being narrower than the stated ask.
11. **The self-diagnosis is usually accurate but reactive.** Sessions gave honest answers ("No. I don't deem it 100.00/100.00", T27 19:25:52), but only after a ✅ had already been asserted at a prior close. Stop hooks gate facts (git state), not completeness against intent, so ✅ could render over open holes (T32 18:00:31, T31 03:46:55, T23 04:41:35).
