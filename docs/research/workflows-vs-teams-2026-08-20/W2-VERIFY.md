## 4. The decision this verification changes

**The finder's routing rule survives, but its stated ground does not — and the correction cuts toward
workflows, not away from them.**

- The finder's rule was: route on *"needs CORRECTING mid-flight"* vs *"only CHECKED afterwards"*,
  because a workflow agent **cannot be messaged**. That premise is **false**. It can, while it runs,
  2/2, in-band, and it keeps its context.
- What is actually true is narrower and more actionable: **a workflow agent's address is never
  published, and dies when the agent exits.** Correction is possible but requires the lead to read
  `journal.jsonl` off disk and to catch the agent *while it is still running*.
- So the honest scoring is **three cells, not two**: ✅ emit upward · ✅ receive a redirect **while
  running, if you can find its id** · ❌ be resumed after it exits, ❌ be stopped individually
  (unproven), ❌ block for approval.

**Consequences for the CLAUDE.md question:**

1. **Do not restate the rule on "unaddressability".** That is the ground the finder proposed, and it
   would be a *newly minted false reason* replacing an old one — the same defect the finder correctly
   diagnosed in the current rule ("because they don't write code"). A rule justified by a refuted
   mechanism gets re-litigated the first time someone runs the probe I just ran.
2. **The defensible grounds that survive verification are:** (i) **write attribution** — a workflow
   agent's dirty tree convicts the lead's session, breaking mechanical-🔧, ship-floor and custody;
   (ii) **no post-exit resume**, so a completed agent's context is unrecoverable; (iii) **no blocking
   approval gate**; (iv) **no Stop-hook participation**, so the entire close-integrity system never
   runs. (i) and (iv) are the load-bearing ones for *this* repo, and neither is about addressability.
3. **Supervision needs a brief line, not a build.** I proposed a `journal.jsonl` id-reader here;
   **C1-bis makes even that unnecessary as the primary path.** An agent that sends one line to `main`
   at startup publishes its own agentId to the lead as the message's `from` address (measured 7 and 5
   occurrences; **0** for the silent agents). So the supervision channel costs **one sentence in the
   agent brief** — *"`SendMessage({to:"main"})` once when you begin, and again before anything
   destructive"* — and is portable to any 2.1.220 box. The `journal.jsonl` reader remains the useful
   **fallback** for agents that never spoke. The wave should not conclude "workflows cannot be
   supervised" when the channel is a briefing convention away from working.
4. **Stop selling `resumeFromRunId` as crash recovery.** Same-session only. It earns its place as an
   iteration primitive and nothing more.

everything except write attribution.
