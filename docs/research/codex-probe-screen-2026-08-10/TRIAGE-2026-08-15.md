# TRIAGE — the 7 DEFECTIVE screens, independently re-verified (2026-08-15)

**This discharges the corpus README's `Status: UNTRIAGED`.** Every finding in all 7 DEFECTIVE
screens was re-verified against `origin/main` at `2d7b125d`, by a verifier that had not written the
screen, working from the trunk file rather than the screen's quoted excerpt.

**Bottom line: 1 screen of 7 is discharged by a landed fix; the other 6 are live, and 20 of the 21
named findings still reproduce on trunk.** The one discharge is the screen the README nominated as
highest blast-radius — `screen-session-writes` #1 — which `6509abd2` fixed on 2026-08-11, twelve
hours after the triage item was filed, citing this screen by name. Its own secondary finding was
deliberately left unfixed and is still live.

## Method, and what it is worth

Each screen got its own verifier with no knowledge of the others' results. Each was required to
return, per finding, one of **STILL-HOLDS** (reproduced, executed) · **ALREADY-FIXED** (current
trunk code quoted + the commit that fixed it) · **REFUTED** (executed disproof), and to say
**UNVERIFIABLE-HERE** rather than guess.

Three limits, stated because they bound the claim:

- **This is a Linux container, not the box the screens were written on.** No kitty/iTerm2, no panes,
  no `~/.claude` fleet state. Where that mattered it is marked per finding.
- **The clone arrived shallow (depth 50).** `git log -S` over a shallow clone attributes file
  content to the graft commit, which produced one wrong provenance answer before the clone was
  unshallowed (`26dc3ab9` named as the origin of files it does not touch). Every provenance claim
  below was re-derived after `git fetch --unshallow`. **If you re-run this triage in a fresh cloud
  container, unshallow first** — this is a repeatable trap, not a one-off.
- **`bats` and `shellcheck` are absent from the base image** (`apt-get install bats shellcheck`
  fixes both). Two verifiers ran before that and returned static + hand-executed proofs; their
  findings were re-confirmed by running the suites afterwards.

## 1. `screen-session-writes` — #1 DISCHARGED, #2 live

**Subject:** `hooks/lib/session-writes.sh`. This is the one the README told the reader to start with.

### #1 — ALREADY-FIXED by `6509abd2` (2026-08-11)

The screen convicted `session_unlanded_mine` of returning **rc 1 ("not mine")** where the truthful
answer is **rc 2 ("cannot-tell")**, because the `git diff` sat inside a heredoc'd command
substitution whose exit status is structurally unobservable. rc 1 *exonerates* — it is what
`completion-assert.sh` turns into `_ca_exon="unlanded-not-mine"` and what `session-continue.sh`'s
ship floor turns into `return 0` — so a git read that merely timed out let a session close ✅ over
its own unlanded work. Fail-GREEN, in the arm that decides exactly that.

`6509abd2 fix(liveness): the negative verdict was the fall-through, not the time window` fixed it as
one of three sites sharing the shape, and **names this screen file in both the code comment and the
test comment**. The read now goes through a tempfile (`hooks/lib/session-writes.sh:337-341`) with an
explicit conversion at `:339-340`:

```sh
if ! ( cd "$top" 2>/dev/null && _sw_bounded 5 git diff --name-only "$trunk"..HEAD ) >"$difff" 2>/dev/null; then
  rm -f "$difff" 2>/dev/null; return 2
```

Five tests were added (`tests/session-writes.bats:387-479`) where there had been none — two positive
controls, an unresolvable-ref negative control, a timeout regression pin, and a **mutation control**
that reverts the one line and asserts both controls go red. Re-run here: **29/29 green.**

**One honesty note is preserved in the repo and should not be lost in the close.** The commit's own
test comment records that the screen's *timeout* reproduction (`git` shimmed to sleep 30 s → rc 1)
did **not** reproduce in the repo's harness — pre-fix code answered 2 there — and the author did not
find the cause, attributing it most likely to the shim rather than the subject. The fix rests on the
**unresolvable-ref** trigger, which is independently confirmed and goes red pre-fix. So one of the
screen's three executed data points is unreproduced; the conviction does not depend on it.

### #2 — STILL-HOLDS at `hooks/lib/session-writes.sh:278`

The sibling `session_dirty_mine` still matches with `printf '%s\n' "$mine" | grep -qxF "$abs"`. Under
a consumer that sets `-o pipefail` — `completion-assert.sh:96`, `operator-readout.sh:121`,
`teammate-auto-shutdown.sh:45` all do — `grep -q` short-circuiting on an early match SIGPIPEs the
`printf`, and pipefail returns **141 for a match that did occur**. The hit is dropped: same
fail-negative direction, reached from the other end.

Reproduced here (match on the first line, so `grep -q` exits immediately):

```
lines=101      bytes=2693      rc=0
lines=1001     bytes=27893     rc=0
lines=2401     bytes=68493     rc=0
lines=5001     bytes=143893    rc=141
lines=20001    bytes=588893    rc=141
```

The threshold differs from the screen's macOS measurement (rc 0 up to 42,093 B, rc 141 at 85,293 B)
— pipe-buffer behaviour is platform-specific — but the direction and the mechanism are identical.
It needs a very large session either way.

**This one is already on the record as a deliberate deferral**, at
`docs/plans/LIVENESS_DETECTOR_FAILNEG.md:286-289`: *"Named here and left unchanged so this diff stays
attributable to the read it fixes; the line I did rewrite uses a herestring."* That is a sound
reason, and it means the fix shape is already landed three lines below the defect, at
`session-writes.sh:352`. Note the deferral note cites `session_dirty_mine:269`; the line is now
**:278**.

### The screen's weakest evidence turned out to be its strongest finding

The screen inferred Claude Code's project-dir encoding from `~/.claude/projects` *directory names* on
the operator's Mac — an inference from output, which is why this triage expected to mark it
UNVERIFIABLE-HERE (this container has exactly one project dir, and its path contains no discriminating
character). Instead the verifier found the **encoder itself**, in the shipped CLI at
`/opt/node22/lib/node_modules/@anthropic-ai/claude-code/cli.js` (v2.1.42):

```js
function _b(A){ return A.replace(/[^a-zA-Z0-9]/g, "-") }   // the project-dir encoder
function I_1(){ return join(join(rg(),"projects"), _b(dr8()), "memory") + SEP }
```

Confirmed independently at the top level of this triage: `grep -o 'replace(/\[^a-zA-Z0-9\]/g,"[^"]*")'`
returns `replace(/[^a-zA-Z0-9]/g,"-")`. **Every non-alphanumeric character becomes `-`** — so the
script's `encode()` (`:51`), which maps only `/` and `.`, is narrower than the class it names, and the
header's *"Verified 2026-07-31 against ground truth … not inferred"* (`:44-45`) certifies a check whose
span was two characters wide. Divergence is wider than `_`: space, `+`, `~`, `@`, `#` all diverge.

| path | Claude Code `_b()` | script `encode()` | |
|---|---|---|---|
| `/Users/chrisren/Development/doc_classifier` | `-Users-…-doc-classifier` | `-Users-…-doc_classifier` | **diverge** |
| `/home/user/a b/repo` | `-home-user-a-b-repo` | `-home-user-a b-repo` | **diverge** |

Row 1 reproduces the screen's claimed real directory name character-for-character — so the screen's
inference was *correct*, it was merely weakly evidenced. **Caveat:** this pins the rule for CLI
**2.1.42**, the build in this container; the fleet runs 2.1.183/2.1.220.

**No correct-class encoder exists anywhere in the repo**, and the same lossy two-char rule appears in

## What this changes about the corpus itself

The README's framing — *"a screen is a first look, and this repo's own history is mostly defects that
survived a first look"* — was right to demand re-verification, and re-verification paid for itself in a
direction the README did not predict. **It did not overturn a single verdict.** What it produced instead:

1. **One discharge** — `screen-session-writes` #1, fixed 12 hours after this triage item was filed, by
   a commit that found the same defect down a different search axis and cited the screen by name.
2. **One finding the screen missed** — `cc-config-slot` #2b, an uncaught traceback out of the error
   path itself.
3. **One inference upgraded to proof** — the project-dir encoding, from the shipped encoder rather than
   from its output, which also exposed two more files carrying the same wrong rule.
4. **Citation drift in four places** — two sibling line numbers off in `screen-mailbox-forward`
   (and its `! grep -q` count understated by ~100), `ship-land.sh:1664` → `:2110` in `screen-gate-memo`,
   three `handoff-fire.sh` line numbers in `screen-cc-recover-safeguard`. Line numbers in a screen rot
   within days; the quoted text does not. **Cite by text, verify by line.**

The corpus's own load-bearing conclusion is reinforced rather than weakened: *absence of subsequent
commits is not evidence of correctness.* Four of the seven subjects have **exactly one commit in their
entire history** — `bin/cc-config-slot`, `bin/cc-recover-safeguard`, `tests/mailbox-forward.bats`,
`scripts/worktree-memory-link.sh` — and every finding against all four is still live. `branch-reaper.sh`
is byte-identical to what was screened. Nobody had looked.

**And every suite that covers a convicted file is green on trunk while its defects are live** —
measured here for `branch-reaper` (11/11), `cc-config-slot` (20/20), `land-gate-memo` (10/10),
`mailbox-forward` (13/13), `worktree-memory-link` (13/13). These are not untested files; they are files
whose tests do not discriminate. `worktree-memory-link` is the sharpest case — its suite recomputes the
subject's own bug — and `mailbox-forward:78` is the same shape one line wide.
