## Refuted (do not chase)

- **GitHub-side limits.** REST secondary limits (100 concurrent requests, 900 points/min, 90s CPU/60s) apply to the REST API only (docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api); the git docs publish only a 2 GiB per-push cap (docs.github.com/en/get-started/using-git/troubleshooting-the-2-gb-push-limit) — no push rate, concurrency or SSH limits. "cannot lock ref … is at X but expected Y" is receive-pack's ordinary compare-and-swap on the value the client advertised, i.e. the lane's own race (row 1), not throttling. `git ls-remote origin main` ×3: 0.79 / 0.84 / 0.95s. 0 kex/ssh/RPC/"Could not read"/rate-limit strings in 1,878 reso rows and 11,896 infra rows. No ControlMaster (~/.ssh/config has no github block) — harmless at this scale.
- **Repository size (1.47 GiB in 28 packs, 282k objects).** Hookless pushes p50 4s; fetch/ls-remote <1s. Transfer is not on the critical path.
- **Shared-.git lock contention across 40 worktrees** (refs/remotes/origin/main.lock from 3-5 fetches per land, packed-refs 1,064 lines, `.git/config` lock from the per-land hooksPath re-assert at land-tools.sh:205-216): 0 exit-2 and 0 exit-24 rows in 7d; `gc.auto=0`, `maintenance.auto=false`, `git maintenance` runs from launchd (prefetch/loose-objects hourly, pack-refs daily) without blocking. One 16 KB `tmp_obj` garbage file from a killed writer.
- **Session death mid-land / orphaned vitest pools.** 0 `killed` rows (v3 traps INT/TERM, ship-land.sh:247-251); the 12 `backup/*` refs are STOP leftovers (4 preship this week); mem-leash forwards TERM to the child pgid (scripts/mem-leash.sh:176-189) and cc-sem releases on TERM; live process census found no vitest without a live ancestor; slots are identity-reaped (cc-sem.sh:122-157).
- **Process table / fds.** 1,796 procs of kern.maxprocperuid 10,666; 610 zombies are kitty's (607 of them), not the lane's; 13k of 491k files.
- **Clock / timezone skew.** Every writer uses `date -u` (ship-land.sh:125,235; land-lock.sh:59; postland-verify.sh:122; load sampler); lstart pinned `TZ=UTC LC_ALL=C` (cc-sem.sh:105, land-lock.sh:69). Only the re-exec truncation (row 10) is real.
- **Operator's own pushes.** All 141 first-parent commits on origin/main in 7d are inside a landed row's range (0 uncovered); `release` is a separate ref moved by deploy-release.sh (last 09-20T09:12Z).
- **Drizzle TTL steal.** Removed (land-lock.sh:23-35); journal at idx 94, contiguous.
- **land-tools.d snapshot churn as a cost.** Content-addressed, atomic rename, GC after 1 day unused (land-tools.sh:196-199) vs max land 4,938s; cost is one `git archive | tar` (~13 MB) per new scripts tree.
- **`pnpm install` reverting core.hooksPath.** scripts/prepare-cached.sh:51 writes the canonical path when `reso.landtools` is on.
- **Lane tests mutating the real repo** ("Preparing worktree (new branch 'pool/slot-2')" seen in a push tail): fixtures are mkdtemp + `git init` with a clean env (scripts/__tests__/worktree-pool-ownership.test.ts:48-61, ship-land.test.ts:53-56). They are load-flaky, not destructive (row 4).
- **docs:gate / audit-ci / bottle tripwire as push cost.** Hookless-suite pushes p50 4s; the 2 docs-gate and 1 audit-ci rejections were genuine verdicts.
- **Auto-revert on a red tip.** Does not exist; a RED pins the deploy gate until a new tip (row 7).
- **Index.lock collisions between a session's own git calls and the rebase.** Documented at ship-reconcile.sh:216-235; 0 exit-7 rows in 7d; per-worktree, does not scale with N.
- **Amplify build per land.** amplify.yml exists but ship.md:8-12 records reso-deploy v21 filtering `refs/heads/release`; 0 `[skip-cd]` in 7d messages; cloud-side only, no landing-latency effect (console not checked).

## Blockers / uncertainties

- The hook-starts-before-the-non-ff-filter claim rests on git's transport ordering plus the push_s evidence (114-299s on rc=1 non-ff rounds vs 4s hookless); the githooks page does not state it either way.
- tsc memory is one live observation (2,281 MB); the load sampler's `top3.cmd` records argv[0] (`node`), so tsc cannot be separated from vitest/next in history.
- Session-side retry behaviour (whether sessions background the land, how long they wait) is not visible from logs; inferred from 21-43 min in-flight lands under the Bash tool.
