# H — hostile reviewer: what the plan missed

**Verdict (answer first).** Three dimensions none of A1-C3 owns: (1) the account router (`claude-accounts --rank`) sits on every recovery's hot path, is a network/keychain call with a 3 s budget, and over 294 timed calls hit its ceiling 34% of the time and failed 18%; 15 recoveries were PARKED purely because the router did not answer. (2) The state store has no garbage collector at all: 705 MB / 16,122 files, 221 MB of it transplant "evidence" copies of whole sessions that nothing ever reads or prunes, plus 42 MB of per-attempt audit.json. (3) The only same-session mutex (`runs/by-sid/*.active`) is held by a pid that is dead in 75 of 76 claims because the detached `--one` driver never releases it, so three independent lanes (hook request, cc-lr request, REROUTE) can each re-drive one session minutes apart. Checked and ruled out: timezone handling, teammate handling, capacity-token leaks, auth-cliff detection (exists in the router, see Uncertain). Trunk code == live code (diff -rq of `~/.claude/scripts/limit-recover` vs checkout: identical; `~/.claude/bin/cc-lr` symlinks into the main checkout at 110ea9a64).

## H-1 — The account router is a slow, failing network call on every recovery's critical path

- **Symptom:** a recovery parks with "no routable target: router: claude-accounts: --max-wait expired mid-sweep; no answer" although accounts had quota.
- **Frequency (MEASURED, `cat fleet/*/rank.timing`, 294 lines 2026-09-30..10-11):** 242 rc=0, 36 rc=3 (window expired), 16 rc=2; 101/294 at the `max_wait` ceiling (271 at 3 s, 23 at the 15 s retry); mean wall 5,783 ms. Worst days: 2026-10-01 15/30 rc!=0, 2026-10-04 34/49 at ceiling. Of the runs whose first rank call failed: 27 PARKED, 4 RECOVERED, 3 FAILED; 12 PARKED say "--max-wait expired mid-sweep; no answer", 3 say "poll throttled (cached usage)" — 15 parks caused by the router, not by quota. Tonight's run: `rank.timing` "max_wait=3 rc=0 wall_ms=3001" (at the ceiling).
- **Root cause (INFERRED):** `scripts/limit-recover/lr-fleet.sh:735-752` (`lf_rank_timed`) calls `claude-accounts --rank --max-wait 3`, retries once at 15 s only on rc 3, and an empty ranking falls through to PARKED unless a soft reason matches (`lr-fleet.sh:800-817`). The router's quota read is the oauth/usage endpoint (`~/.claude/bin/claude-accounts:1573-1579`), so under loadavg 80-260 a 3 s budget is routinely exceeded. Secondary: `lr-handoff.sh:1297` `[[ -x "$ab" ]] || return 0` and `:1304` `ranked=$(… --rank) || return 0` make the target-routability re-check fail OPEN; `:716` `--route … || true`.
- **Fix (M):** rank once per tick (poller), cache `{ranking, ts}` in `$STATE/route-cache.json` with a 120 s TTL, and have `lf_rank_timed` read the cache first and only call the router on a miss; on rc 3 with a non-empty cache, use the cache and log `RANK-CACHED`. bats: stub `claude-accounts` to sleep 5 and exit 3; assert the run proceeds from a seeded cache and `rank.timing` records `src=cache`.
- **Conviction:** 70. **Receipt:** `awk` over `fleet/*/rank.timing` → `runs=294 at_ceiling=101 rc!=0=52 mean_ms=5783`; `fleet/one-20261011T031606Z-58d3640a/rank.timing`.

## H-2 — The state store has no garbage collector; growth is unbounded and the biggest item is unread

- **Symptom:** `~/.reso/limit-recover` is 705 MB / 16,122 files (MEASURED `du -sh`, `find -type f | wc -l`); `locks/` alone is 221 MB.
- **Frequency (MEASURED):** 17 `locks/<sid>.{aborted,unconfirmed}-<ts>` dirs (10 aborted, 7 unconfirmed), one 99 MB, three above 25 MB; each holds the target-side `<sid>.jsonl` plus the whole `<sid>/` session dir. 664 `audit*.json` = 42.4 MB (one 436 KB audit per attempt; 118 bundles for 46bc0436 = 31 MB). poller.log 24 MB / 131,246 lines growing 1.8-2.7 MB/day (2026-10-08/09/10) with no rotation anywhere in the repo. 163 MB `lr-research-2026-09-19/` and 90 MB `recon/` live inside the store. 328 results files, 76 run claims, 424 bundles.
- **Root cause:** `scripts/limit-recover/lr-transplant.sh:385-394` (`lrt_file_evidence`) moves the target copy into `locks/` on every abort/unconfirm; `grep -rn 'aborted-\|unconfirmed-' bin scripts hooks` finds zero readers and zero pruners. The only pruner in the rail is `lr-upgrade.sh:2380` (`lru_st_prune`, upgrade state only). No code references `poller.log` for rotation.
- **Fix (S):** a `lrp_gc` step at poller start: delete `locks/*.{aborted,unconfirmed}-*` older than 7 d, bundles with a terminal verdict older than 30 d, and rotate poller.log at 10 MB (`mv` + fresh file, keep 3). bats: seed an evidence dir with `touch -t` 8 d old and a fresh one; run `lrp_gc`; assert only the old one is gone and a `GC` log line names the byte count.
- **Conviction:** 85. **Receipt:** `du -sk locks/* | sort -rn | head -3` → 99680 `c28362b6….aborted-20261002T041748Z`, 26832, 25848; `find . -name 'audit*.json' | wc -l` → 664.

## H-3 — The same-session mutex is dead after every detached run, so three lanes can re-drive one session

- **Symptom:** one session gets several drivers minutes apart; tonight 186452ed had runs at 01:08, 01:20, 01:33, 01:45, 01:58Z (first four "verdict is on disk only", fifth RECOVERED); 58d3640a's hook request was re-filed at 03:33:23Z while its 03:20Z bundle was `admitted`, and a `.cc-lr.json` request for the same sid sat beside it.
- **Frequency (MEASURED):** `runs/by-sid`: 76 `.active` claims, 75 with a dead holder (`kill -0`), 0 alive, 15 with no results file at all. 61 same-sid `fleet/one-*` runs started <15 min apart across 20 sids (509 runs, 67 sids). At 03:52Z three sids (58d3640a, 5507881f, 6defb493) had both `<sid>.json` and `<sid>.cc-lr.json` in `requests/`. poller.log: 339 `RUN-CLAIM-DEAD-HOLDER` lines.
- **Root cause (INFERRED):** the poller restamps the claim onto the detached driver pid (`lr-reset-poller.sh` `run_claim_handoff`, 1035-1045 region), but `lr-fleet.sh --one` never releases it: the only release is the pool path `lr-fleet.sh:1547`; `lr_claim_release` (`lr-lib.sh:751`) requires the holder pid. Every later actor therefore sees `stolen-dead-holder` (`lr-lib.sh:714`) and proceeds. Three lanes feed the same sid: hook `<sid>.json` (re-filed per death, `rq_stale_reason` only checks LIMITED-ness, `lr-reset-poller.sh:1247-1262`), `<sid>.cc-lr.json` (reconciler, `lr_recon/store.py:576`), and REROUTE (`lr-reset-poller.sh:2036-2082`, paced 15 min by `REROUTE_EVERY_MIN`, no verdict memory).
- **Fix (M):** `lr-fleet.sh --one` traps EXIT to `lf_run_claim_release`, and the claim file gains `last_verdict`/`last_ts`; `run_claim_take` refuses a sid whose last verdict is FAILED/HELD within `LR_SAME_VERDICT_BACKOFF_S` (default 3600) and logs `RUN-BACKOFF`. bats: run `--one` against a stub that FAILs; assert the claim is gone, then that a second `--one` within the window exits with `RUN-BACKOFF` and no bundle.
- **Conviction:** 75. **Receipt:** claim census loop → `claims=76 dead_holder=75 alive=0 no_result_file=15`; `ls requests | sed … | uniq -d`.
