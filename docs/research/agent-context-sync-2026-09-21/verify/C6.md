# C6-delegated-admin-consent — REFUTED (reference values), with the operative gate elsewhere

Fetched 2026-09-21. `curl -sL` of the rendered Learn pages (WebFetch truncates the
846 KB permissions reference before the F/S entries); tables parsed locally.

## 1. The reference values — the claim has them backwards

https://learn.microsoft.com/en-us/graph/permissions-reference, per-permission tables.
Each table's columns are **Application | Delegated**; the `AdminConsentRequired` row:

- **Files.Read** — Delegated: `No`. Plus: "The Files.Read delegated permission is
  available for consent in personal Microsoft accounts."
- **Files.Read.All** — "AdminConsentRequired | **Yes** | **No**" (Application Yes,
  **Delegated No**). Delegated DisplayText "Read all files that user can access".
  Plus: "The Files.Read.All delegated permission is available for consent in personal
  Microsoft accounts."
- **Sites.Read.All** — "AdminConsentRequired | **Yes** | **No**". Delegated
  description: "Allows the application to read documents and list items in all site
  collections on behalf of the signed-in user".
- **Sites.Selected** — "AdminConsentRequired | **Yes** | **No**". Delegated
  description: "Allow the application to access a subset of site collections on behalf
  of the signed-in user. The specific site collections and the permissions granted will
  be configured in SharePoint Online."

So all three delegated permissions read **No**, not Yes. The abraunegg
`docs/application-security.md` tabulation is correct; the claim's premise is false, and
its conclusion ("a non-admin device-code sign-in can reach only the user's own
OneDrive") does not follow from the reference.

## 2. What the DEFAULT tenant setting implies even though the flag says No

https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/manage-app-consent-policies,
§ "Microsoft recommended user consent policy":

> "The setting labeled "Let Microsoft manage your consent settings," the Microsoft
> managed policy, will update with Microsoft's latest recommended default consent
> settings. **This is also the default for a new tenant.** The setting's rules are
> currently: End users can consent for any user consentable delegated permissions
> EXCEPT: For Microsoft Graph: **Files.Read.All**, Files.ReadWrite.All,
> **Sites.Read.All**, Sites.ReadWrite.All, Mail.Read, … People.Read."

`Sites.Selected` does **not** appear in that exclusion list (0 occurrences on the page).

Also relevant, https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-user-consent:
`microsoft-user-default-low` = "Allow limited user consent only for apps from verified
publishers and apps that are registered in your tenant, and only for permissions that
you classify as low impact"; and configure-permission-classifications: "Currently, only
delegated permissions that don't require admin consent can be classified", with the
minimum classified set being `openid, profile, email, offline_access`.

**Net:** in a default work/school tenant a non-admin user *is* blocked from consenting
to delegated Files.Read.All / Sites.Read.All — by the tenant **user-consent policy**,
not by the reference's `Admin consent required` column. The claim reaches a roughly
correct operational outcome via a false mechanism, and gets Sites.Selected wrong in
both respects.

## Scope limits

- Values above are the v1.0 reference as rendered 2026-09-21; the exclusion list is a
  **Microsoft-managed, auto-updating** policy — re-read it, never quote it.
- **OneDrive personal (MSA):** no tenant, no admin, no consent policy. Files.Read and
  Files.Read.All are explicitly consentable there; Sites.* / SharePoint libraries do
  not exist on that account type.
- **OneDrive for Business / SharePoint library:** the policy paragraph applies. An
  existing tenant whose admin picked `microsoft-user-default-legacy` ("any permission
  that doesn't require admin consent") would let a non-admin consent to Files.Read.All
  and Sites.Read.All.
- Delegated **Sites.Selected** additionally requires a per-site permission grant
  configured in SharePoint Online; consentability ≠ access.
- macOS/tool versions immaterial (no local tool under test).
