# C7-claude-code-glob-grep-caps — verdict: partially_confirmed

Scope of every measurement: local bundles `~/.claude-versions/{2.1.114,current→2.1.114,2.1.183}/node_modules/@anthropic-ai/claude-code/`
(`sdk-tools.d.ts` + `bin/claude.exe`, Mach-O arm64, strings-extracted); docs page
`https://code.claude.com/docs/en/tools-reference` (fetched 2026-09-21, also as `.md`, 200/110008 B);
ripgrep 15.2.0 (`/opt/homebrew/bin/rg`) for the symlink experiment. macOS 24.6.0 / Darwin arm64.
Nothing outside the scratchpad was touched.

## (a) Glob: 100 results, sorted by mtime — CONFIRMED, but 100 is a *default*, not the cap

Docs, verbatim: "Results are sorted by modification time and capped at 100 files. If the cap is hit,
Claude sees a truncation flag in the result and can narrow the pattern."
`sdk-tools.d.ts` (both versions), `GlobOutput.truncated`: "Whether results were truncated (limited to 100 files)".
Tool description in the binary: "- Returns matching file paths sorted by modification time".

Binary, Glob `call`: `let $=K?.maxResults??100` where `K` = `globLimits`. Two producers of `globLimits` exist.
The ordinary tool-use path passes none (⇒ 100). The REPL / code-mode tool bridge passes
`globLimits:{maxResults:25000}` (same expression carries `fileReadingLimits:{maxTokens:1/0,…}`, in the
function that emits `type:"repl_tool_call"`). So on that path Glob returns up to 25,000.
`GlobInput` has **no** limit/offset/head_limit parameter — the model cannot raise it.

## (b) rg arg vector — CONFIRMED verbatim; the symlink conclusion is TRUE ONLY for the walk

Glob (binary, `RK7`): `f=["--files","--glob",A,"--sort=modified",...w?["--no-ignore"]:[],...Y?["--hidden"]:[]]`
(`w`/`Y` from `CLAUDE_CODE_GLOB_NO_IGNORE`/`CLAUDE_CODE_GLOB_HIDDEN`, both defaulting `"true"`), then
`--glob !<deny>` entries, then `nc(f,$,O)`. Grep: `X=["--hidden"]` + `--glob !.git|.svn|.hg|.bzr|.jj|.sl`
+ `--max-columns 500` + `-l` (files_with_matches) / `-c` (count) / `-n` (content), then `nc(X,P,…)`.
`nc`→`R39` builds `w=[...$,...z,...H,_]` — the path is appended as rg's **positional PATH argument**.
Neither vector contains `--follow`, and no `follow` field exists in `GlobInput`/`GrepInput`.

Experiment (`$V/fx`, root/real/a.txt, root/linkdir→../target, root/linkfile.txt→target/deep/b.txt):
- Glob vector, path `.`: `./real/a.txt` only. Add `--follow`: `./real/a.txt ./linkfile.txt ./linkdir/deep/b.txt`.
- Grep `-l` vector: `./real/a.txt` only. Add `--follow`: all three.
- **Symlinked dir as the explicit PATH: `…/root/linkdir` ⇒ `…/linkdir/deep/b.txt`, rc 0.** Same via cwd.

So: a symlink met *during the walk* is skipped — and symlinked **files** are skipped too, not just
directories. But a symlinked directory handed in as `path` IS searched, because `path` becomes rg's
root argument. A blanket "neither traverses a symlinked directory" is false.

## (c) Grep cap — RESOLVED: there is one, 250 by default, all modes

`GrepInput.head_limit`: "Limit output to first N lines/entries… Works across all output modes: content
(limits output lines), **files_with_matches (limits file paths)**, count (limits count entries).
**Defaults to 250 when unspecified. Pass 0 for unlimited**…". Binary: `Fa1=250`;
`Lq8(H,_,q=0){if(_===0)return{items:H.slice(q),appliedLimit:void 0};let K=_??Fa1;…}`, called on all three
mode branches; truncation surfaces as `GrepOutput.appliedLimit`. files_with_matches additionally sorts by
`stat().mtimeMs` descending, tie-broken by path — undocumented.

The docs page states no numeric Grep cap (no "250"; only `head_limit` named as a parameter) and says
nothing about symlinks for either tool.
