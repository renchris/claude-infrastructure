# C3-rclone-delta-full-listing — CONFIRMED

Primary sources: `backend/onedrive/onedrive.go` and `backend/onedrive/api/types.go` at rclone **master**, commit `4e7a21bead987ff19a4b9f36648512326c3619b5`, `VERSION` = **v1.76.0** (fetched 2026-09-21 from raw.githubusercontent.com); plus https://rclone.org/onedrive/ (generated from the same backend help text).

## 1. ListR uses /root/delta with the token parameter commented out

`onedrive.go:1506` `func (f *Fs) ListR(...)`. Its request options, lines 1591-1598:

```go
	opts := rest.Opts{
		Method: "GET",
		Path:   "/root/delta",
		Parameters: map[string][]string{
			// "token": {token},
			"$top": {fmt.Sprintf("%d", f.opt.ListChunk)},
		},
	}
```

The literal `// "token": {token},` is the only token reference on this path. With no `token`, Graph's `/root/delta` returns the full current state of the drive — so every `ListR` run is a complete enumeration, not O(changes). Confirmed.

## 2. No deltaLink is persisted across invocations

`_listAll` (line 1352) paginates on `@odata.nextLink` only: `if *pNextLink == "" { break }` / `opts.RootURL = *pNextLink`. `ListR` passes `&result.NextLink` as `pNextLink` (line 1607) and never reads `result.DeltaLink`, although the struct has it (`api/types.go:330`: `DeltaLink  string \`json:"@odata.deltaLink"\` // A URL returned instead of @odata.nextLink after all current changes have been returned.`).

The only `m.Set` writes to the config file in the whole backend are `onedrive.go:811-812` (`configDriveID`, `configDriveType`). No delta token or deltaLink is written anywhere. Confirmed.

## 3. The only delta-token loop is ChangeNotify, starting at `latest`

`onedrive.go:3083` inside `ChangeNotify`: `nextDeltaToken, err := f.changeNotifyStartPageToken(ctx)`, and

```go
func (f *Fs) changeNotifyStartPageToken(ctx context.Context) (nextDeltaToken string, err error) {
	delta, err := f.changeNotifyNextChange(ctx, "latest")
```

(lines 3118-3119). The token then advances in memory only, inside the goroutine: `nextDeltaToken = parsedURL.Query().Get("token")` (line 3164, `changeNotifyRunner`), driven by the poll ticker (line 3112). `buildDriveDeltaOpts` (line 3138) is the one place that actually sends `Parameters: map[string][]string{"token": {token}}` — and it is called only from `changeNotifyNextChange`. The token dies with the process. Confirmed.

## 4. Docs: delta only works at the drive root

Backend help, `onedrive.go:427-440`, rendered identically at rclone.org/onedrive/ under `--onedrive-delta`:

> "If set rclone will use delta listing to implement recursive listings."
> "**However** the delta listing API **only** works at the root of the drive."
> "If you use it not at the root then it recurses from the root and discards all the data that is not under the directory you asked for. So it will be correct but may not be very efficient."
> "This is why this flag is not set as the default."

Corroborating code comment at `ListR`, lines 1513-1515: `// ListR only works at the root of a onedrive, not on a folder // So we have to filter things outside of the root which is // inefficient.` And `onedrive.go:1219-1222`: `// ListR only supported if delta set` / `if !f.opt.Delta { f.features.ListR = nil }`. Confirmed.
