## C1 — CRITICAL — §4.5, `awk -F'\t' 'NR>1'` drops the first data row, and no header is specified

The snippet skips line 1. Nothing in the document says `DEPENDS.tsv` carries a header row: §4.5
defines it as "`page \t source \t pinned_sha \t role` … **generated by parsing every page's
`sources:`**", §4.6 lists it as "`DEPENDS.tsv` generated", and the reverse-query one-liner **in the
same paragraph** — `awk -F'\t' '$2=="<mirror path>"{print $1}'` — has no `NR>1`. So the two commands
in one paragraph disagree about whether row 1 is data, and the generator is unspecified.

Measured (`fixture`, 3-row TSV, no header): I set row 1's pinned sha to a value that does not match
the mirror page's `rendered_sha256`. The snippet printed `STALE` for row 2 and
`TOMBSTONE-OR-MISSING` for row 3 and **said nothing about row 1**, rc 0. One curated page per sync
is structurally exempt from staleness checking, and which one depends on the generator's sort order.

**Fix** — state the header in the definition and assert it in the consumer. Amend the §4.5 sentence to:

> `docs/DEPENDS.tsv` is **generated by parsing every page's `sources:`** on each sync, with a literal
> first line `page<TAB>source<TAB>pinned_sha<TAB>role`; column 2 is **repo-relative** (`docs/mirror/…`).
> A consumer that cannot see that header must exit non-zero rather than assume one — a map maintained
> separately drifts, and so does a reader that guesses its own schema.

and use the C6 replacement command, which refuses a headerless file with rc 2 (measured).

## C2 — CRITICAL — an empty or truncated `pinned_sha` reads as FRESH: `case "$cur" in "$sha"*)`

`"$sha"*` is a glob. When field 3 is empty the pattern is `*`, which matches every current sha, so
the row is silently classified fresh. Measured (`fixture`, TEST A): a row whose `pinned_sha` is empty
produced **no output at all** against a mirror page with a real, different `rendered_sha256`.

This is not hypothetical: `DEPENDS.tsv` is generated by parsing agent-written `sources:` blocks, so a
`sources:` entry written without `at_rendered_sha256` — the single easiest omission in a hand-written
YAML list — yields an empty field 3 and a page that can never go stale. It defeats failure mode #10
(*"Curated page drifts after its sources change and nothing goes red"*) by exactly the mechanism the
row claims closes it.

The prefix match is wrong in the other direction too: measured, a 6-character pin `71c0aa` matched a
64-character current sha and reported FRESH. Pins are compared for identity, so a prefix is never right.

**Fix** — replace the comparison with an exact one and make an unpinned row its own loud verdict
(both are in the C6 command):

```
if (pin == "")               { print "UNPINNED\t" page "\t" src; n++; next }
if (pin !~ /^[0-9a-f]{64}$/) { print "BAD-PIN\t"  page "\t" src; n++; next }
if (cur != pin)              { print "STALE\t"    page "\t" src; n++; next }
```

and add to the §4.5 rules list:

> - **An unpinned or short-pinned citation is a lint failure, never a fresh page.** `at_rendered_sha256`
>   is a full 64-hex sha or the row is rejected; a prefix comparison cannot distinguish "pinned to an
>   abbreviation" from "not pinned", and the glob form `case $cur in "$sha"*)` reads an empty pin as a
>   match on everything.

## C3 — CRITICAL — `aliases:` cannot live in the mirror frontmatter, and the whole no-embeddings plan rests on it

Three statements in the document are jointly unsatisfiable:

- §4.4: "**Frontmatter — content-derived fields only**" — and the block it introduces ends with
  `aliases: [FY26 budget, FY-26 budget, PO forecast, purchase order forecast]`.
- §4.6: "`mirror/` TIER 1 — generated … CLAUDE.md (~10 lines: '**GENERATED — DO NOT EDIT**; edits are
  overwritten each sync')".
- §4.6: "**`aliases:` before embeddings.** Grep's real failure is vocabulary mismatch ('PO' vs
  'purchase order'); an aliases line plus a synonym block in the index fixes it with no infrastructure."

"PO forecast" → "purchase order forecast" is a synonym judgment; no converter derives it from bytes.
So the field is not content-derived, cannot be written by the agent (the directory forbids it), and is
overwritten on the next sync if it is. The cited evidence for skipping embeddings (Cursor's +0.3 %,
Sourcegraph retiring theirs) is about whether vectors are worth the freshness burden — it is not
evidence that *this* substitute exists. As written, the vocabulary-mismatch case has **no** mechanism.

It also self-pollutes grep. Measured (`grepfix`, 100 workbooks × 12 sheets): searching the alias term
`PO forecast` returned **all 1,200 mirror pages**, because each page matches its own `aliases:` line
regardless of content — sheet 7 of workbook 0 matched at line 18, its frontmatter, with nothing about
PO forecasts in its body. A per-source alias set replicated onto every unit of that source (12
identical lines per workbook, measured) is a term that selects a whole family and discriminates
nothing inside it.

**Fix** — move aliases to the layer that may hold judgment, and say where the synonyms live:

> **`aliases:` belongs to the curated layer and to one generated synonym file, never to a mirror page.**
> A mirror page's frontmatter is content-derived, so it carries no synonym judgment: `aliases:` is
> removed from the §4.4 contract. Vocabulary mismatch is closed in two places instead — `aliases:` on
> the curated page (agent-owned, §4.5, already in that contract), and `docs/SYNONYMS.tsv`
> (`term<TAB>expansion<TAB>owner`), hand-maintained, linked from `INDEX.md`, which the agent greps
> first and expands its query with. A per-source alias replicated onto every unit of that source is
> worse than absent: measured over 100 twelve-sheet workbooks, the alias term matched 1,200 of 1,200
> pages via their own frontmatter, i.e. it selected the corpus.

## C4 — MAJOR — tombstones-in-place serve deleted content to grep, and `[DELETED UPSTREAM]` appears in no grep result

§4.6 keeps the page at its path with "`status: deleted, deleted_at, last_seen_sha256, source_id,
superseded_by?`, a `[DELETED UPSTREAM]` title and the `git show` command that recovers the last
content", and invariant 6 says "Tombstone the mirror page in place (**keeps citations resolvable**)".
Whether the *body* survives is never stated, and the two readings differ by whether the agent gets a
wrong answer.

Measured (`tomb`), body retained, one live page and one tombstone:

```
$ rg -n 'unit price' docs/mirror
docs/mirror/current-pricing.md:6:Acme unit price is $55.00 per seat, 10% volume discount above 500 seats.
docs/mirror/old-pricing.md:10:Acme unit price is $42.00 per seat, 15% volume discount above 500 seats.
$ rg -l 'unit price' docs/mirror
docs/mirror/current-pricing.md
docs/mirror/old-pricing.md
```

Two contradictory prices, ranked by nothing. The `[DELETED UPSTREAM]` title mitigates **nothing**: it
is on line 7, and neither Grep output mode shows it — `content` returns the matching line, and
`files_with_matches` returns a bare path. The filename carries no marker either. At the doc's own
180-day reap policy a tombstone is grep-live for six months.

**Fix** — replace the §4.6 tombstone bullet's first clause:

> - **Tombstones in place, with the body replaced, never retained.** The page stays at its path so
>   citations resolve, and its whole body becomes one stub: `[DELETED UPSTREAM] <title>` · `status:
>   deleted, deleted_at, last_seen_sha256, source_id, superseded_by?` · the literal
>   `git show <sha>:<path>` that recovers the last content, plus a `git log -S'<term>' -- <path>`
>   pointer for content search. **Retaining the body is a wrong-answer path, not a convenience:**
>   measured, a live page and a tombstone both matched `rg -n 'unit price'` with contradicting prices,
>   and `[DELETED UPSTREAM]` — a line-7 H1 — appears in neither `content` nor `files_with_matches`
>   output, so no grep mode can tell the agent which line is dead. `docs/` in git is the only
>   guaranteed copy of a deleted revision's text (§5) and that is where it stays.

                      "what changed since <date>" git command, ## groups of `- [name](path): one

                      mirror tree.  <= 200 lines / <= 25 KB, enforced by a land-gate lint.

and amend the "Index first, discovery-by-Glob never" bullet's last sentence:

## C6 — MAJOR — the refresh queue exits 0 whatever it finds, and costs 18.8 s where 0.05 s does the job

Two defects in one command. **(a)** rc is `sort`'s, so it is always 0 (measured: rc 0 while printing
one STALE and one TOMBSTONE-OR-MISSING row). Nothing can gate on it — not the STALE linter of the
next bullet, not the land gate, not a `&&` in `docs/README.md`. **(b)** It forks four processes per
row (`printf|awk` ×3, `sed|head`). Measured at 400 topics × 4 sources = 1,600 rows over 200 real
mirror pages, with every read succeeding: **18.79 s** wall (6.8 s user + 11.4 s system) versus
**0.051 s** for one awk pass — 368×. At session start, inside a subagent, 19 s of shell fork is the
whole latency budget.

**Fix** — replace the §4.5 code block in full. This version asserts the header (C1), treats an empty
or short pin as its own verdict (C2), separates missing from deleted (C10), and exits 1 when anything
needs action. Verified on the fixture: rc 1 with four correctly-classified rows, rc 0 and silent when
every row is fresh, rc 2 on a headerless TSV.

```bash
#!/bin/sh
# docs/ refresh queue — which curated pages are stale against docs/mirror/.
# Run from the repo root.  DEPENDS.tsv column 2 is REPO-RELATIVE (docs/mirror/...).
# rc 0 = every row fresh · 1 = rows need action (printed) · 2 = DEPENDS.tsv unusable.
TSV=${1:-docs/DEPENDS.tsv}
awk -F'\t' 'NR==1 && $1!="page"{exit 2} {exit 0}' "$TSV" || {
  echo "DEPENDS.tsv: missing header (page/source/pinned_sha/role)" >&2; exit 2; }
OUT=$(awk -F'\t' '
  NR==1 { next }
  NF < 3 { printf "MALFORMED\t%s\t(fields=%d)\n", $1, NF; n++; next }
  {
    page=$1; src=$2; pin=$3; cur=""; st=""; ok=0; dash=0
    if (pin == "")               { printf "UNPINNED\t%s\t%s\n", page, src; n++; next }
    if (pin !~ /^[0-9a-f]{64}$/) { printf "BAD-PIN\t%s\t%s\t(len=%d)\n", page, src, length(pin); n++; next }
    while ((getline line < src) > 0) {            # frontmatter only: stop at the closing ---
      if (line == "---") { if (++dash == 2) break; else continue }
      if (line ~ /^rendered_sha256: /) { cur = substr(line, 18); ok = 1 }
      else if (line ~ /^status: /)     { st  = substr(line, 9) }
    }
    close(src)
    if (!ok && st == "deleted") { printf "SOURCE-DELETED\t%s\t%s\n", page, src; n++; next }
    if (!ok)                    { printf "MISSING-OR-UNPARSEABLE\t%s\t%s\n", page, src; n++; next }
    if (cur != pin)             { printf "STALE\t%s\t%s\n", page, src; n++; next }
  }' "$TSV" | sort -u)
[ -n "$OUT" ] && { printf '%s\n' "$OUT"; exit 1; }
exit 0
```

(One awk pass, no per-row forks: 0.051 s at 1,600 rows against the original's 18.79 s, measured.
Bounding the scan to the frontmatter also removes a second fail-open the original has — the original
`sed -n 's/^rendered_sha256: //p'` matches anywhere in the file, so a mirror page whose *body* quotes
that key can supply the "current" sha.)

## C7 — MAJOR — three incompatible path conventions for one edge, inside one section

§4.5's curated frontmatter writes the source **page-relative**:
`{path: ../../mirror/sharepoint/acme/finance/…, at_rendered_sha256: …}`. `DEPENDS.tsv` is declared
"generated by parsing every page's `sources:`", i.e. verbatim from that field. The refresh queue then
resolves `"docs/$s"` — **docs-relative**. The reverse query in between says
`$2=="<mirror path>"` — a third, unspecified form.

Measured (`fixture`, TEST D): a genuinely fresh row whose column 2 was the verbatim `../../../mirror/…`
resolved to `docs/../../../mirror/…` and was reported `TOMBSTONE-OR-MISSING`. With column 2
repo-relative (`docs/mirror/…`) the same command double-prefixed and reported all 1,600 rows of the
scale fixture as missing. Only the undocumented docs-relative spelling works.

**Fix** — state the normalization once, in the §4.5 sentence that defines the file (folded into C1's
replacement above), and add it to the §4.4/§4.5 contract:

> The `sources:` `path` stays page-relative so a human opening the page can follow the link; the
> generator **normalizes it to repo-relative** (`docs/mirror/…`) when writing `DEPENDS.tsv`, and every
> consumer of that file — refresh queue, reverse query, STALE linter — uses the repo-relative form
> from the repo root. One spelling per store.

## C8 — MAJOR — per-sheet split loses corpus recall against the doc's own measured `head_limit = 250`

§4.4 splits a workbook into one file per sheet; §4.6 measures Grep's `head_limit` default as **250 in
every output mode, including `files_with_matches`, sorted by mtime descending**. Those two facts are
150 lines apart and never meet.

Measured (`grepfix`), a body-only term present on 4 sheets of each of 100 workbooks:

| layout | files matching | distinct source workbooks visible under head_limit 250 |
|---|---|---|
| one page per sheet (1,200 pages) | 400 | **64 / 100** |
| one page per workbook (100 pages) | 100 | **100 / 100** |

A third of the corpus is invisible to the search, at exit 0, on a key `git clone` resets. Splitting is
still right — per-Read cost measured 286 tokens for a sheet against 364 for the whole small workbook,
and the gap grows with sheet count — but the recall cost has to be paid somewhere, and §4.4 already
names the place without specifying it: `00-index.md`.

**Fix** — amend the "One file per addressable citation unit" paragraph:

> Per sheet (`<Name>.xlsx.d/00-index.md`, `01-<sheet>.md` …), where **`00-index.md` is the workbook's
> grep-recall surface and carries what the split takes away**: the workbook's title and path, every
> sheet's name, used range and column headers, and the union of the sheets' distinctive terms — so one
> hit resolves the whole workbook. Splitting multiplies the file count against Grep's `head_limit` of
> 250 (§4.6): measured, a term on 4 sheets of each of 100 workbooks was visible in 64 of 100 workbooks
> when split per sheet and 100 of 100 when kept whole. For any completeness-critical search over the
> mirror, glob `**/00-index.md` first and descend only into the workbooks it names, or run `rg` via
> Bash where no cap applies.

## C9 — MAJOR — `DEPENDS.tsv` cannot see a curated page that cites nothing

The refresh queue iterates `DEPENDS.tsv`, which is generated from `sources:` blocks. A curated page
written without a `sources:` block appears in no row and is therefore permanently fresh. Measured
(`fixture`): 3 pages on disk, 1 page in column 1, refresh queue silent, rc 0 — and the uncited page
was an ordinary-looking topic page asserting a seat count.

The curated layer is agent-written, so an uncited page is the *likeliest* failure, not an exotic one,
and it is the one failure #10's whole apparatus cannot see.

**Fix** — add a §4.5 rule:

> - **Every curated page must appear in `DEPENDS.tsv`, and the lint is separate from the refresh queue.**
>   A page with no `sources:` is in no row and is therefore never stale — the one drift the pinned-hash
>   mechanism is structurally blind to. Land gate:
>   `comm -23 <(find docs/topics -name '*.md' ! -name CLAUDE.md | sed 's|^docs/||' | sort) <(awk -F'\t' 'NR>1{print $1}' docs/DEPENDS.tsv | sort -u)`
>   must be empty; each line it prints is a page making claims from nothing.

## C10 — MAJOR — `TOMBSTONE-OR-MISSING` fuses two states that demand opposite actions

The snippet's one verdict for an empty `cur` covers (a) the source was deleted upstream — re-curate
the page, and (b) `DEPENDS.tsv` points at a path that does not exist — a generator or normalization
bug, i.e. a code fix. Measured (`fixture`, TEST E): `mirror/does/not/exist.md` and a real tombstone
produced byte-identical verdicts. This is the document's own recurring lesson (§4.6 argues it for
tombstones: "Removal alone leaves three states indistinguishable … which demand opposite actions")
applied everywhere except its own tooling.

**Fix** — the C6 command already splits them (`SOURCE-DELETED` from `status: deleted` in frontmatter
vs `MISSING-OR-UNPARSEABLE` when the file cannot be read at all). Add the verdict vocabulary beside
the command in §4.5 and in `docs/README.md`:

> Verdicts: `STALE` (re-synthesize the page) · `SOURCE-DELETED` (the mirror page is a tombstone —
> re-curate or retire the claim) · `MISSING-OR-UNPARSEABLE` (**a bug in the generator or in path
> normalization, not a content problem**) · `UNPINNED` / `BAD-PIN` / `MALFORMED` (lint failures).
> rc 1 if any row printed.

## C11 — MINOR — the frontmatter contract promises a field it omits, and omits the three the agent wants

§4.4's prose and failure #16 both require `tokens_estimate` in frontmatter; the contract block 20
lines below does not contain it (`grep -c tokens_estimate` over the block = 0). Measured cost of the
block filled in realistically (full 64-hex shas, real Graph id, real web URL): **19 lines, 981 chars,
~272 tokens**, of which **370 chars / ~103 tokens (38 %)** are `source_id`, `source_etag`,
`source_version`, `content_sha256`, `canonical_sha256`, `options_hash` — opaque values the consuming
agent can neither interpret nor act on. At 9,000 mirror pages that is ~2.4 M tokens of frontmatter in
the corpus. They are all load-bearing for the *pipeline*, so the answer is not to cut them; it is that
the agent pays 272 tokens per page and gets no answer to "is this page worth reading".

**Fix** — add three fields and the one already promised, to the §4.4 block:

```yaml
summary: One-line statement of what this page contains, generated by the converter from the
         document's own title, heading set and used range — never a model caption.
source_title: "FY26 Budget — Q3"     # the document's own human title, not the slug
tokens_estimate: 4200                # promised by §4.4 prose and failure #16; the agent's read/skip gate
unit_index: 1                        # already in `part:`; hoisted so a grep can sort units
```

> The agent's decision at a grep hit is read-or-skip, and `summary` + `tokens_estimate` are the only
> two fields that answer it. The ids and hashes (38 % of the block, measured) are for the pipeline and
> are never expected to mean anything to a reader — say so in `mirror/CLAUDE.md` so the agent does not
> spend turns trying.

## C12 — MINOR — entity-first is right, but only under a closed aspect vocabulary the doc never states

Traced three queries through Grep on a 360-page entity-first tree (`topics`):

1. *"What did we agree with client07 on pricing?"* — entity known. `Glob docs/topics/clients/client07/*.md`
   → 4 files, one Read. **Entity-first wins**; type-first needs the user's type word to match the
   directory name.
2. *"Which clients have a renewal in Q4?"* — entity unknown, type known. The tree answers nothing;
   what saves it is the filename suffix: `ls docs/topics/clients/*/*-renewal.md` → 80 files. **But it
   depends on a closed vocabulary that is nowhere specified.** Measured: renaming three pages to
   `-renewals`, `-renewal-terms`, `-contract-renewal` — the spellings an agent writing free-hand
   produces — dropped the glob to 78 at exit 0, and `*renewal*` recovered only two of the three.
3. *"Who owns the client07 integration?"* — `rg -l client07 docs/topics` → 5 hits including
   `decisions/2026-08-08-decision-7.md`. Works, and shows the second gap: **"everything about
   client07" is not one Glob**, because level 1 of the tree (`clients/ workstreams/ decisions/
   people/`) mixes entities with types — §4.5 calls all four "entity" and two of them are not.

**Fix** — amend the §4.6 naming bullet:

> **Names are retrieval signal**, and an entity-first name is only as good as a **closed aspect
> vocabulary**: `<entity>-<aspect>.md` where `<aspect>` comes from a published list in
> `docs/topics/CLAUDE.md` (`commercial · integration-scope · renewal · support-history · …`), extended
> only by editing that list, and enforced by a land-gate lint. Measured, three free-hand aspect
> spellings (`-renewals`, `-renewal-terms`, `-contract-renewal`) dropped `clients/*/*-renewal.md` from
> 80 files to 78 at exit 0, and a widened `*renewal*` glob recovered two of the three — a type-shaped
> query fails silently and partially, which is worse than failing loudly.
>
> Level 1 of `topics/` is **not** one axis: `clients/` and `people/` are entities, `workstreams/` and
> `decisions/` are types, so an entity's record is spread across both and "everything about `<entity>`"
> is a Grep on the `entity:` frontmatter field, never a Glob. Carry `entity:` on **every** curated page
> including decisions and workstreams, state that query in `INDEX.md`
> (`rg -l '^entity: acme' docs/topics`), and generate `docs/_index/by-entity.tsv`
> (`entity<TAB>page`) beside `DEPENDS.tsv` from the same parse so the cross-cutting query is one lookup.
