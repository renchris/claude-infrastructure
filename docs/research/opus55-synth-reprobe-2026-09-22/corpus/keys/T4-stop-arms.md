## Traps (non-obvious points the key-builder identified)
- The mechanical uncommitted-writes arm never emits a block itself: mechanical_arm() WRITES the sentinel file (hooks/session-continue.sh:1070) and returns 0, then control falls through to the shared armed path which emits the block (:1334). A lazy answer calls it a fourth emitter, or misses that it therefore inherits the kill-switch (:1228), SID-BIND (:1246) and the CLAUDE_CONTINUE_MAX cap (:1255) rather than having its own.
- CC_MECH_MAX has TWO different literal defaults inside one file: the reader uses ${CC_MECH_MAX:-2} (:1053) while the `clear` verb writes ${CC_MECH_MAX:-3} into the .mech sidecar (:261) — and that write is UNCONDITIONAL, so `clear` SPENDS the mechanical budget rather than deleting it (an off switch, not a snooze button).
- All three floors are reachable only when NO sentinel file exists (`if [ ! -f "$f" ]` at :1205). A Stop on an already-armed sentinel skips mechanical/ship/wake entirely and goes straight to the kill-switch → SID-BIND → cap → block chain.
- Within the floor branch the arms short-circuit: if mechanical_arm arms (:1207) the ship floor and wake floor are never called on that Stop, and ship_floor blocking (:1208) means wake_floor never runs. At most ONE JSON object is ever printed per Stop invocation.
- The hook's OWN comments carry stale self-citations: :943-945 cites "ship_floor :969, wake_floor :732-736" (real kill-switch sites are :1101 and :850), :952-953 cites ":865-869"/":587-608" for the peer exemptions (real: :1103-1109 and :778-785), :724-725 says $_opane is "captured at :197" (real: :425), :434 cites mailbox_promote_acked "(:213)" (real: :467), :178 cites ":145" for the .sid write (real: :146), :1327 cites "precedent at :502". Docs are worse: docs/research/exhaustive-drive-2026-09-08/A07-caps-and-latches.md:89-90 cites :149/:921 and docs/research/jcode-due-diligence-2026-08-11/coupling-census.md cites :816/:637 for the same two constants. NOT every citation is stale, though — the ":322-326" claim that session-continue sits at Stop position 4 and completion-assert at position 6 checks out against settings-templates/settings.example.json:466 and :476, so the discipline is to verify, not to assume rot.
- The three arms do NOT share one exemption policy, and the code says so at :963-966: the mechanical arm and the ship floor exempt a team assignee when agent_team_member_confirms returns 0 (confirmed) OR 2 (cannot tell) (:970, :1105), whereas the wake floor additionally stands down on argv-only evidence and treats rc 1 (REFUTED) as non-exempt (:778-785).
- Unread peer mail does not block by itself through the mail FOLD at :1284-1299 — that fold only decorates a block that is already happening on the armed path, and it peeks/commits rather than taking (emit-then-commit, :1337-1339). Mail causes a block only through the wake floor's fire predicate (:805).
- The wake floor's custody term is pane-ATTRIBUTED via originatorPane / notifyBack (:748-754), not a bare `cc-custody count --open --cwd` — a sibling's row in a shared checkout cannot fire it; an unattributable row still counts but the wording hedges (:881-882). The cwd-only count survives only as the no-pane-identity fallback (:762).
- A live /goal does NOT generally suppress the wake floor: it only swaps the instructed command to the `--idle-scoped` form (:827-833), still budgeted, TTL'd and kill-switched. The goal causes an ABSTAIN only in the conjunction goal-live AND pending mail (:697).
- The headless abstain keys on the WRITER's environment — CC_PANE_ID set AND ITERM_SESSION_ID empty (:656) — deliberately NOT on an empty pane id nor on the `hdl-` id shape, because cc-pane-headless mints a perfectly ordinary non-empty address that sails past the id-shape guard at :607.
- rc 2 ("cannot tell") never buys a block anywhere: the mechanical arm requires session_dirty_mine rc 0 exactly (:1023), and the ship floor treats ANY non-zero from session_unlanded_mine / session_writes_paths as an abstain (:1150-1156), so rc 1 and rc 2 are the same disposition there — a point the session-writes.sh header calls out at :404-408.
- Hitting the cap does NOT block: at n >= CLAUDE_CONTINUE_MAX the hook deletes the sentinel, prints a systemMessage naming the re-arm lever, and exits 0 (:1258-1267). Likewise the wake-floor budget exhaustion (:836-843) and the ship-floor budget/sha latch (:1172-1178) all ALLOW the stop.
- session-writes.sh names its own coverage residue at :39-44: a file written only through Bash (sed -i, a heredoc, git checkout) is invisible to the transcript oracle, so the mechanical arm silently misses it — the miss is fail-green, never a false block.
- `clear` refuses a foreign sentinel only when the caller passes --if-mine (:212-217, :235); the bare `clear` still removes whatever is armed in that cwd, and the guard demands POSITIVE proof of ownership, so a caller with --if-mine and no session id is refused too.
- The wake floor has two silent pre-exits that are easy to miss as exemptions: an invalid/absent inbox key (:607) and an already-live watcher, which additionally RESETS the attempt budget by deleting the sidecar (:614) — compliance clearing the cap is the documented reason the teardown state gate had to exist at all.
