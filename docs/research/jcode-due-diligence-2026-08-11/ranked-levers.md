# Rank ALL the levers to 150+ resident, with jcode as one candidate among them

*Axis `ranked-levers` of the jcode due-diligence wave `wf_363ad50b-f2b`. Synthesis: [`../jcode-due-diligence-2026-08-11.md`](../jcode-due-diligence-2026-08-11.md).*

**Verdict.** Ranked by (gain × reversibility) / effort the order is L7 context-ceiling cap > L2 burst-bound/admission > L1 MCP consolidation > L6 idle eviction (blocked on one 0.5-day measurement) > L3 cloud lane (unblocked TODAY) > L4 headless (already landed, remaining capacity gain 0) > L5 jcode migration > L8 hardware (excluded by frozen scope, not by evidence) — jcode ranks 7th of 8 because its entire measured advantage lands on the per-session memory axis, and this repo's own phys_footprint measurements show memory is not what binds.

**Load-bearing claim.** Per-session resident memory is NOT the binding constraint on this box, so jcode's ~20× marginal-memory advantage buys capacity on an axis that already has headroom — the next increment of effort is worth 15-100× more spent on the context-ceiling cap (L7), the burst bound (L2), or MCP consolidation (L1).

**Why it matters.** Everything about the migrate/do-not-migrate call turns on this. If memory IS binding, jcode's 10.4 MB vs 212.7 MB marginal moves the ceiling from ~132 to effectively unbounded and jumps to #1 on any ranking. If memory is NOT binding — as three independent in-repo instruments say (residency saturates at ~450 MB with 139-session headroom against total RAM; 127/127 historic admission refusals were LOAD, 0 memory; all 5 box deaths in 11 days were compressor-segment fragmentation at ~20 GB free) — then a whole-harness replacement costing 60-120 agent-days across 294 CC-coupled files buys sessions the box was never refusing, while the three actual walls (burst ignition, ~4-8 active on 10 cores, ~3.9 sustained active on 4 Max plans) are untouched by it. The refutation is cheap and specific: re-run `scripts/pool-floor.sh` and the capacity-admit refusal log and show a memory-basis refusal exists. There has never been one.

## Unknowns
