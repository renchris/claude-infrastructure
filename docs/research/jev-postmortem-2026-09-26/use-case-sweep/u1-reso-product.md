## Rejected candidates

**Existing LLM calls. All are generators or agents, so Jev cannot replace any of them.**
- Gemini image generation: `scripts/bottle-gen-production.ts:89`, `scripts/floor-plan-upscale.ts:27`, `scripts/bottle-gen-validate.ts:60`. The output is an image.
- Headless `claude -p` agents: `scripts/qa-commits-nightly.ts:14` (browser QA) and `scripts/wiki/regen_page.py:176` (page writer). The `.claude/workflows/*.js` and `scripts/venue-research/workflows/*.js` jobs are also agentic and need web or file tools. Their `refuted`/`real` verdicts come only after tool-driven investigation.

**Prior 09-19 rejections, re-checked.**
- **`parseGuestEntry.ts`: the rejection holds, but the reason needs correcting.** The output is not prose. It is extracted strings `{name,count,note}`, which Jev still cannot emit. It runs on Enter (`src/components/ItemInput.tsx:173`) and on a 200 ms-debounced paste preview (`src/components/AddManyDialog.tsx:30-39`). The logic is 101 lines of deterministic regex, and I found no recorded misses. Its sibling `AddManyTable.tsx:16-30` (a "not a name" warning) is boolean-shaped, but a 60-line paste would be 60 calls, about 4 min at 14.8/min, against a preview that is synchronous today. There is no miss data for it either.
- **Bottle image review: holds.** The state is an image. The text-bearing stages (neck-ring glyphs, label copy) reduce to an exact compare against known ground truth once transcribed, e.g. `DEPUIS`/`1811` (`.claude/rules/bottle-generation-ledger.md:162-200`). The environment stage says outright "do NOT build a scorer" (`:291`).
- **Deck ruling: holds.** It is a per-venue geometric decision that only the operator makes, e.g. D3, "which blocks exist" (`docs/floor-plan/chapter-bake-pipeline.md:1844,1862`). Volume is about one per venue.
- **Bottle-menu match: holds.** The open `heist-2026` quarantine needs Heist's own menu document and a read of production (`.claude/rules/bottle-menu-data.md:296-308`), not a classifier. A Jev `choice` over the 115 catalog slugs could name-join the rows T2 skips (`scripts/__tests__/menu-preset-parity.test.ts:126,257-269`). But T1 already covers every row by price membership, and a test gate must stay deterministic and offline.
- **Runbook-link relevance: holds, and it is now measured instead of NONE-MEASURED.** I ran python over `scripts/cloudwatch-*.sh`. There are 37 alarm→runbook references: 16 distinct, pointing at 4 runbooks. 12 of the 16 carry per-alarm `#anchors`, and all 12 resolve to headings (using my approximate heading-slug rule). So relevance is already encoded in the anchors, and only about 4 references would ever need a Jev call. The one historical defect (`7968d9442`) was a dead path, which the script catches deterministically. The cheaper improvement is to have `scripts/audit-runbook-links.sh` check anchors (it strips them today).

**Other heuristics and review steps found.**
- `lib/alerts/lead-classify.pure.ts:67` registrant classifier: signup is invite-only (`databaseActions.ts:1611`), and this is a security exact-match that must stay deterministic.
- `categorizeError` (`src/app/api/logs/route.ts:233`): a keyword classifier that runs on every RUM beacon to set a CloudWatch dimension. That is a hot path far above Jev's rate ceiling, and there is no data on how big the `other` bucket is. It does have substring hazards: `'cert'` matches "concert" (`:283`), and `'504'` matches any ID. Those are code fixes, not a Jev job.
- Genre keyword classifier (`data/venue-analysis/harbour_genre_analysis.py:87`): measured 0 of 291 events unclassified, because the rules were fitted to that dataset. The product fields it would feed have no live writer: `event.artistProfileID` is always null on create (`src/components/create-event.contract.ts:251`), and I found nothing that writes `artist_profile.genre`.
- Guest-list approval queue (`replicache/mutators.ts:365`, `notificationDispatch.ts:93`): approval is a promoter-allocation decision over name+count. `flagStatus` already surfaces bans deterministically, and there is no text judgment to make.
- Guest search and suggestions (`guest-book.contract.ts:405-427`, `lib/guestSuggestions.ts:118`): a ranked fold/prefix match that runs per keystroke, with phone as the identity key. Jev would be too slow and adds nothing here.
- `specialRequests`/`internalNotes`: staff write these themselves, there is no queue that consumes them, and `lib/operational-detail.ts:75` deliberately never reads them.
- Guest-message outbox (`lib/messaging/guest-message-outbox.ts`): outbound and templated, with no transport wired yet and no inbound replies to judge.
- Support/intake and venue messages: neither exists in the repo (rg found no such surfaces).
