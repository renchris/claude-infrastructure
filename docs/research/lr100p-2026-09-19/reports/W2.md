### 4.1 A1 (HIGH) — the terminal state repeats, and it paged every time

D5 made an unredeemable token a named terminal state that pages instead of re-deciding in the pane.
It can REPEAT: **the rename claim is the only terminal path that leaves the record on disk** — the
post-claim, clock and expiry paths all discard it first — so an unclaimable token reaches the same
refusal for as long as anyone runs the launcher, and the launcher is durable in the run's bundle
precisely so a human can re-run it hours later.

MEASURED on a QUIET, HEALTHY box (load override 0.01/core, i.e. one a fresh evaluation would
ADMIT): ten redemptions of a token in a chmod-555 directory ⇒ **ten rc-9 refusals and ten
BYTE-IDENTICAL pages**. After: ten rc-9 refusals, ten IDL rows, **one** page.

The occurrence is counted per RECORD (`<sid>.<issued>`, both already validated by
`_cc_admit_token_shape`). Occurrence 1 pages; 2..N carry `REPEAT #N` on the reason and
`occurrence N` on the row and do not page. **The verdict is untouched at every occurrence** —
bounding an ALARM must never widen ADMISSION, and 15aa asserts all ten rcs are still 9 over a box
that would otherwise admit. **The rows are not damped either**: the IDL is the audit surface, and
damping the record would hide the storm rather than bound it.
`CC_ADMIT_TOKEN_TERMINAL_PAGES` (default 1) is the knob; 0 silences the alarm and still records.

**Two garbage inputs fail TOWARD the alarm, each with its own case** (15ab): a corrupt occurrence
counter (a 20-digit value wraps `$(( n + 1 ))` to 7766279631452241921, which is not `-le 1`, so the
first page would be suppressed) and a garbage knob (`[ 1 -le abc ]` exits rc 2, which `if` reads as
a clean false — D2's shape again).

### 4.2 A2 — charset is not range, at four operand sites

`cc_hw_is_int` asks "is every character a digit", which is all a sysctl reading needed. D2 hardened
the TTL RESOLVER and the identical fail-open survived one layer in. Measured, all four
verdict-level:

- **21 digits.** `CC_ADMIT_TOKEN_TTL_S=999999999999999999999` passes the charset test, so the
  hardened resolver accepts it; `[ "$age" -gt "$ttl" ]` then errors rc 2 (`[: …: integer expected`)
  and `if` reads it as a clean false. **A 315,360,000 s token ADMITTED, rc 0, basis=token**, on a
  box at 9.90 load/core.
- **Overflow.** `CC_RECYCLE_DRAFT_WAIT=99999999999999999999` wraps the derived TTL to
  7766279631452242759 (nothing ever expires); the int64 maximum wraps it to **-9223372036854774969**
  — a negative bound under which every token is instantly expired. One operand, both failure
  directions a digit apart.
- **Octal.** `$(( 0600 ))` is 384, so `CC_RECYCLE_DRAFT_WAIT=0600` gives TTL 1224 instead of 1440 —
  silently 216 s short, in the direction that expires tokens mid-recycle. `0900` is not a valid
  octal literal at all: bash aborts with `0900: value too great for base` and, under a caller's
  `set -e` (**lr-fire-resume sources this file**), takes the process with it.
- **The record's own `issued` field** is the other operand of that subtraction. With
  `issued = 2^64 + now - 5` — twenty digits, every one a digit — the age wrapped to **5 seconds**
  and the gate returned rc 0: a token dated 584 years into the future admitted as if minted five
  seconds ago.

`cc_hw_is_int_operand` validates three properties and normalises: digits, a 10-digit magnitude
bound (317 years in seconds; four of them summed stay four orders of magnitude inside int64), and
the leading-zero strip. `cc_hw_is_int` itself is unchanged, so no caller outside this file moves.

**A third site, found by carrying the class forward rather than stopping at the brief** (`efa8ddbee`):
`cc_hw_budget_charge`'s own operands. `CC_ADMIT_BUDGET=999999999999999999999` made

control at budget 3 that released on the fourth — i.e. **§9's law ("no gate on an actuation path may
be unbounded") defeated by a typo, in the gate whose whole justification is that law** and which

### 4.5 A5b — the abandoned claim copy

Reproduced through the real path, not fabricated: with `rm` a silent no-op (15k's premise — an
unwritable directory, an immutable flag, a full inode table, or simply a process that dies between
the rename and the discard), one `<token>.claim.<pid>.<nonce>` file survives at 0600 in the
directory the driver reads, per crashed recovery, forever. Not a replay risk — rename(2) has already
made the original name unreachable — but litter in an admission store is what makes the next reader
distrust the store.

**The mint sweeps, never the redeemer** (the mint is the driver, once per recovery, in the process
that owns the directory). **Age-bounded at the TTL, and that bound is load-bearing rather than
tidy**: a live claim exists for the few statements between rename and discard, so an unbounded sweep
could delete a concurrent redeemer's claim and re-open the hole D1 closed. Own-uid, regular files,
and a `for` glob rather than `find` (BSD find does not walk a symlinked start dir without `-H`).

The symlink mutant **survived twice** before the fixture was right, and the reason generalises:
`-f` and `-O` follow a link while BSD `stat -f %m` does **not** (unlike `stat -L`), so a fresh link
is refused by the age bound and `[ ! -L ]` is never reached. The case now backdates the link with
`touch -h` and the target with plain `touch` — the only arrangement in which the symlink guard is
the guard, and the same "validated the target, acted on the link" shape D3 closed one function over.
