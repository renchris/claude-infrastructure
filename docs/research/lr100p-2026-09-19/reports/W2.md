## 1. What changed, by file:function

### `scripts/lib/capacity-admit.sh` — the admission token and the per-run budget key
- `cc_capacity_token_mint` / `_cc_admit_token_redeem` carry the driver's decision across the
  process boundary without letting a probe WIDEN admission: minted only by a caller whose probe
  admitted, ONE-SHOT (unlinked on read), TTL 300 s, uid-checked (`-O`), SID-ENFORCED, PROBE-INERT.
  `basis:"token"` is an eighth value — adding is the legal direction (coverage case 27 requires
  `capacity_gate`'s vocabulary to stay a SUBSET of this one).
- A token that is missing, expired, foreign or unparseable is never a silent refuse *or* a silent
  admit: the gate falls through to a FRESH evaluation and the reason rides on that row's new
  `token` field. A FOREIGN token is refused WITHOUT being consumed — unlinking it would destroy a
  sibling recovery's admission.
- `_cc_admit_state_file` gains `CC_ADMIT_BUDGET_KEY`. Measured (U05 §3.4): five recoveries shared
  one `lr-fire-resume.refusals` counter; the one that survived did so on two earlier runs' charges,
  and its release then reset the counter for the other four. The budget VALUE is untouched
  (D3-safety R2 refuted lowering it to 1). Unset ⇒ byte-identical, so no existing caller changes.

### `scripts/limit-recover/lr-lib.sh` — one corrected probe for two callers, and the run's state log
- `lr_capacity_probe_corrected` lifts the phantom-active subtraction (`226b73888`) and the
  call-scoped `CC_ADMIT_LOAD_TERM=off` OUT of lr-fleet's `lf_capacity_wait`, because a second
  caller appeared (lr-handoff's pre-transplant check). Two spellings of one probe is how the fleet
  and the launcher came to measure different gates in the first place (U05 §3.3).
  `lf_phantom_actives` stays as a delegating wrapper — its three lr-fleet cases sed-extract it BY
  NAME and are unchanged.
- The WAIT stays in lr-fleet: that is the caller's policy, not the probe's. Its default drops
  600 → 120 s (§11.5) — measured, the 600 s form cost one fire 658 s of the lead's own foreground
  and recovered nothing (run `one-20260919T170450Z`, U14 §1).
- `lf_capacity_wait` stops reading a MISSING FUNCTION as a capacity refusal: `if <missing>; then`
  is false, which the loop repeated to the park — 120 s of waiting and then `parked | capacity`
  with an EMPTY reason. It now names the live-layer skew once and parks immediately.
- `lr_state_append` / `lr_state_current`: append-only ≤1 KB jq-encoded lines in the run's OWN
  bundle dir (no parallel tree — D2-FT #16 refused an unlocked index upsert), a per-run mkdir
  mutex, and NO `|| true` on the write (D3-FT R10). The size cap is what keeps the append atomic;
  the mutex is the belt, bounded at 2 s and stolen past it so a crashed writer cannot silence a run.

### `scripts/limit-recover/lr-handoff.sh` — every refusable read BEFORE the transplant
- **The ordering defect (U02; D1-FT R5, D2-safety R2, D3-safety R3 — no design had it).**
  `--in-place` moved the transcript FIRST and discovered only afterwards what made the recycle
  impossible: an operator draft in the composer (the recycle's own gate, 180 s later), a pane not
  holding a claude, a session that died on a network error rather than a limit, a teammate. By then
  the source is a tombstoned husk whose cheapest exit is a manual relaunch.
- `lrh_precheck()` runs BEFORE `lr-transplant.sh` and moves nothing: it calls handoff-fire's new
  read-only `--probe-recycle-preconditions`, maps REFUSED and HELD alike to exit 6, and records the
  state in the run's `events.jsonl`. On admit it takes ONE capacity reading through
  `lr_capacity_probe_corrected` and MINTS the token — the decision belongs to the process that is
  about to transplant. Kill switch `LRH_PRECHECK=off` restores the previous ordering verbatim (I9).
- The live-layer preflight gains the token half: a live `lr-fire-resume` that never reads
  `LR_ADMIT_TOKEN`, or a live `capacity-admit` with no `_cc_admit_token_redeem`, REFUSES with exit 5
  before anything moves — otherwise the launcher ignores the variable and re-gates inside the pane,
  which is the split that made the four husks.
- The launcher heredoc exports EXACTLY five `%q`-rendered `LR_*` variables and ZERO `CC_ADMIT_*`
  (D1-safety R1 rates the alternative FATAL: anything exported here is inherited by lr-fire-resume,
  by its expect, and — unless explicitly unset on the spawn line — by the recovered claude and
  every hook it ever runs, for that session's whole life. That is why `CC_ADMIT_NET_ZERO` was
  dropped as a design).
- The launcher file moves from the per-uid temp dir into the run's BUNDLE: same uid-owned
  hardening, but durable (this box wipes the temp dir at boot, and the launcher is what a stranded
  recovery is relaunched from by hand hours later), and it makes the run dir derivable FROM the
  launcher path — which is how the watcher learns where to read `relaunch.rc`.

### `scripts/limit-recover/lr-fire-resume.sh` — redeem call-scoped, record the rc, unset the leak
- The gate call becomes CALL-SCOPED — `CC_ADMIT_TOKEN`, `CC_ADMIT_WANT_SID`, `CC_ADMIT_LOAD_TERM`,
  `CC_ADMIT_BUDGET_KEY` as a `VAR=… cmd` prefix, never an export. An absent or expired token still
  yields a FRESH evaluation with those same switches: never a silent admit, never a silent refuse.
- `relaunch.rc` is the watcher's positive discriminator. This script runs inside the pane, in a
  shell the recycle watcher cannot reach, and every pre-expect failure looks identical from outside:
  no claude ever appears. An EXIT trap covers every pre-expect path — not just the gate — and is
  DISARMED immediately before `expect`, because a post-expect exit is the session ending and must
  never be recorded as a relaunch failure. The rc is written ONCE: the first cause is the real one.
- Both spawn lines gain `env -u` for all nine admission-related names (D1-safety R1).

### `scripts/handoff-fire.sh` — a read-only probe verb, and a boot wait on positive discriminators
- `--probe-recycle-preconditions --source-pane P --source-session S` is READ-ONLY: one line per
  refusable precondition, changes nothing. exit 0 all pass · 3 `HELD:<check>` · 5 `REFUSED:<check>`.
  It REUSES the actuator's own predicates — `hf_remote_source_bind`, `pane_cc_state`,
  `composer_content`, `live_subagents_of`, plus lr-lib's `lr_last_api_error` and a teammate head
  test — because a pre-check whose value is "it answers the same question the gate will" cannot
  re-implement them. In-flight subagents are COUNTED, never a refusal: `subagent_gate` owns that.
- **The boot wait** waited 15 × 3 s, RETYPED the identical command, waited another 45 s, and
  reported "no claude process appeared within 90s". Measured (U02 §2d, U05 §3.4): the launcher had
  exited ~2 s in, refused by its own capacity gate, so the 90 s polled a corpse — and the retype
  re-ran the same command against a refusal counter advanced by one, i.e. it could not possibly
  succeed. Now: a date-bounded 60 s loop at 0.5 s on three POSITIVE facts — `relaunch.rc` newer than
  `typed_at` (the file is removed before typing AND the instant recorded, because the unlink alone
  loses to a writer that recreates it), an lr-fire-resume refusal row newer than `typed_at`, and
  claude on the pane. Cheap file reads every tick, the pane read every 6th (`pane_cc_state` is
  0.5–0.6 s under load, D1-latency R2). NO retype (plan §14). At 60 s with no evidence the state is
  `INDETERMINATE:boot` — a state line and an alarm — then MORE READING to 180 s, where `STALE:boot`
  is terminal. `FAILED:relaunch` and `STALE:boot` are the same terminal arm and must not read
  alike: one is re-drivable with a fresh probe, the other needs someone to look.
- `recycle_await_verdict`'s max was 600+180+120 = 900 s over stages that can legitimately take
  180+600+180+180 = 1140 s — the same nested-bound inversion one layer up, reporting a LIVE recycle
  as "no verdict". It now reads all four stage variables BY NAME (so a constant edit moves it), is
  date-bounded at a 0.5 s poll, and recognises the boot arm's terminal states.
