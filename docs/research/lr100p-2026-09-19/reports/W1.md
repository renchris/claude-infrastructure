## 4. Deviations from the spec, and why

1. **`LR_INPLACE_AWAIT` is an ENV var, not a new `lr-handoff` flag.** The spec names the behaviour
   (`--detach` ⇒ no `--await`) and the anchor, not the mechanism. An env var crosses the `detach`
   process boundary for free and keeps the hunk in `lr-handoff.sh` — a file W2 and W3 both own — to
   a single `if`, which is the smallest rebase surface I could leave them.

2. **`--detach` on rc 0 mails `verdict=RECOVERED` with an explicit `engagement=UNAWAITED` qualifier.**
   Suppressing `--await` means `handoff-fire` returns once the `/exit` has landed and the watcher is
   armed, so rc 0 is ARMED, not ENGAGED — the "vacuous proof" § 10 of the plan draft names. The
   spec fixes the token vocabulary at four values, so I did not mint a fifth; instead the mail says
   which question was answered. **This is a real residual for W3**, which is the wave that makes
   RECOVERED mean "submitted, then engaged"; until then a detached RECOVERED must be read as
   "armed", and the watcher's own `recycle-engaged`/`recycle-dead` row in `handoffs.jsonl` is the
   engagement verdict.

3. **The IDL join is implemented twice** — `lf_idl_cause` in `lr-fleet.sh` and `rcy_idl_cause` inside
   the `__recycle` arm of `handoff-fire.sh` — rather than once in a shared lib. W1's file list does
   not include `lr-lib.sh` (W2 and W4 both own hunks there), and adding a `source` of a new lib to
   `handoff-fire.sh` outside the anchored region would have broken the "touch only the anchored
   region" rule. ~14 lines duplicated. If a third consumer appears, this is the moment to lift it.

4. **Two new selftest seams in `handoff-fire.sh`** (`RCY_PROC_TICKS`, `RCY_PROC_IVL_S`) that the
   spec did not ask for. The arm under test sleeps 90 s by construction, so without them the two new
   cases cost 3 real minutes each and rule 4's "run only the suites you touch" becomes unaffordable.
   Their safety argument is the shipped one for `HF_RECYCLE_SHELL_WAIT_S` (which has its own green
   default-pinning test): they move only how long the watcher waits, never what it sends — the
   retype's gate is still an affirmative `at_shell` read from the pane.

5. **The requester pane falls back to `cc-notify --role desk`** when neither
   `LR_FLEET_NOTIFY_PANE`, `ITERM_SESSION_ID` nor `KITTY_WINDOW_ID` is set (the poller's
   `--from-daemon` case is exactly this). `cc-notify`'s own doc calls a frozen uuid a stale address
   and the role the correct form for an automated pager. The verdict is written to
   `<run>/verdict.txt` before either send, so an unreachable notifier degrades to disk truth rather
   than to silence.

6. **The rc-4 test fixture writes its IDL row from inside the `lr-handoff` stub**, not from the test
   body. The join is floored at the attempt's own start precisely so a stale refusal cannot be
   attributed to today's run; a pre-seeded row would be testing the wrong thing and would have to
   defeat the floor to pass.

7. **The full bats suite was NOT run** (rule 4). Suites run: the two I extended, plus the three other
   suites that drive the `__recycle` watcher body I edited.
