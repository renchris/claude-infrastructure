## 5. FOR THE LEAD — deployment, and what a land alone does NOT do

🚨 **`statusline.sh` is a COPY-deployed real file, not a symlink.** `readlink -f ~/.claude/statusline.sh`
resolves to itself; the file documents why at its own telemetry block ("this writer is a
copy-deployed real file while every reader is a symlink"). A landed edit therefore does **not** go
live on the shared checkout's fast-forward the way a `hooks/` or `bin/` file does — it needs
`install.sh`, which `scripts/deploy-live.sh` runs. Until then the live statusline renders the old
line and no pane carries its identity.

🚨 **`bin/cc-find` is NEW.** `install.sh`'s `~/.claude/bin` leg globs `cc-*`, so no `install.sh`
edit is needed — but a new file has **no live symlink at all** until it runs, which is absence, not
staleness (`LIVE_ADDS` > 0 breaches at a lag of 1). The registered `statusLine` command is
`~/.claude/statusline.sh` (`~/.claude/settings.json:1274-1277`) and is unchanged.

👤 **The glyph is an OPERATOR eyes-check**, per the plan (`no visual verification inline`). `⌗`
(U+2317) was chosen because it sits outside the East-Asian-Width Ambiguous set `statusline.sh`
documents kitty downsampling, but that file's own history records four reverted glyph designs at the
operator's eyes. The zero-risk fallback is already implemented and one column cheaper: setting a
non-UTF-8 `LC_ALL`/`LC_CTYPE`/`LANG` renders `#117` instead of `⌗117`, and hard-coding `#` is a
one-line change to `_idmark`. **Check it in a real 30-column pane before this is called done.**

## 6. Deviations from the spec, and why

1. **Each half of the identity segment is omitted independently; the plan draft's `${_pane:-?}`
   placeholder is not implemented.** The plan sketched `ID_SEG="⌗${_pane:-?} ${PAY_SID:0:8} "`, but
   the TASK's acceptance demands "each RED when its source var/field is unset — mutation-checked",
   and a `?` placeholder renders a field that identifies nothing *and* makes its own absence
   unfalsifiable. Independent omission is what the red arms in case 20 actually test.

2. **The pane value is NOT digit-validated.** `hooks/session-register.sh:127` keys the registry
   FILENAME on exactly `${...##*:}` with no digit filter, and under real iTerm2 that tail is a UUID.
   A filter here would make the statusline and the registry disagree about what a pane is called on
   the one terminal where they still must agree.

3. **`lf_report` gained an arm** (a `?` pane_after counts as a gap). Not named in the spec, which
   asked only that `pane_after` differ. Without it the run still printed `RECOVERY COMPLETE — 0
   replaced beside their source` over an unproven pane, which launders the one state the column was
   made able to report. All pre-existing report assertions stay green.

4. **`cc-find`'s tie rule is stated as `secondd − bestd ≤ 12`.** U07 §6c(3) says "the top two are
   within the p90 drift"; the implementable reading is the difference of their distances, which
   fires on the 122/124 incident (0 vs 0) and on every near tie. Tunable at `CC_FIND_PCT_TIE`.

5. **`cc-find` diverges from `bin/cc-sessions:252` / `bin/cc-notify:353` on fail-open.** Those two
   return "same process" when `ps` is unreadable, because for them a hiccup must not read as a
   death. Here the verdict IS the product, so `DEAD` and `STALE` are reported and `UNKNOWN` is
   reserved for a row that carries no recorded `lstart` at all. Stated in the file, at the function.

6. **One `jq` per registry directory, not per row** (`cf_bulk`), added after the first draft
   measured 0.399 s on the live store — over budget. The per-file ladder survives as the fallback
   because `jq` aborts the whole invocation on one malformed document, and a corrupt row must cost
   its own row, never every row.

7. **The suite's latency assertion is load-gated.** See §3. The unconditional half is the fork
   budget, which is mutation-checked.

8. **`scratchpad/lr/payload.json` (cited by U07 §8) does not exist in this tree or in the shared
   checkout** — the whole `scratchpad/lr/` directory is gone. The fixture payload was rebuilt from
   the payload-builder source U07 §3d quotes verbatim out of the 2.1.260 binary. Same for
   `sl-base.sh`: the control arm is `git show 601807233:statusline.sh`, which is stronger than a
   hand-copied file (memory: `control-must-replay-the-real-artifact`).
