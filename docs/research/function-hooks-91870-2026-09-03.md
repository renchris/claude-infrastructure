# Function Hooks (anthropics/claude-code#91870) — provenance, and what it means for claude-infrastructure

**Date:** 2026-09-03 · **Method:** 12-agent workflow `wf_90972f13-399` (4 ground / 4 self-census / 4 adversarial
verifiers, 2.23M subagent tokens) · **Status:** research, no code change

**The finding that matters is not about the issue.** #91870 is a real Anthropic proposal and it is pre-decision.
But the question it prompted — *"do we get more official entrypoints rather than only wrappers?"* — has a better
answer than the issue provides: **we already have far more official entrypoints than we use, and the binding
constraint is our own adoption and version hold, not Anthropic's surface.**

## 2. The premise "we only have wrappers" — REFUTED, and that is the useful part

Adversarial verifier verdict: **REFUTED**. We already run the official surface at scale; where it exists we have
under-adopted it.

### 2a. What we run today

`~/.claude/settings.json`: **84 hook registrations across 12 events**, plus the official `statusLine.command`.
40 files under `hooks/` speak the structured-output contract (`hookSpecificOutput` / `additionalContext` /
`permissionDecision` / `updatedInput`); 26 consume the officially-supplied `transcript_path`. That is a
first-class official extension surface in production, not a wrapper.

Per-event: PreToolUse 16 · SessionStart 15 · PostToolUse 12 · Stop 12 · SessionEnd 7 · UserPromptSubmit 7 ·
Notification 5 · PermissionRequest 4 · PreCompact 3 · TeammateIdle / WorktreeCreate / TaskCompleted 1 each.

### 2b. The three adoption gaps, in cost order

**(i) 21 events unwired — 15 of them present in the binary we run, free today.**
Docs list **33** hook events. `strings -a` on `2.1.114` finds **27** present. We wire **12**.
Present-but-unwired on our own binary: `Setup`, `PermissionDenied`, `PostToolUseFailure`, `SubagentStart`,
`SubagentStop`, `TaskCreated`, `StopFailure`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `FileChanged`,
`WorktreeRemove`, `PostCompact`, `Elicitation`, `ElicitationResult`.

> **The sharpest artifact: `hooks/subagent-stop.sh` exists on disk and `SubagentStop` is registered nowhere** —
> while `SubagentStop` appears 17× in the binary. 10 of 76 files in `hooks/` are unregistered.

Several open repo tasks map straight onto these: `FileChanged` → tasks #58/#74 (waking an idle session);
`SubagentStart`/`SubagentStop` → #192 (agent-report recovery); `ConfigChange` → #70 (config-mirror never heals a
forked settings.json).

⚠️ **Caveat before anyone plans on this:** string presence in the bundle proves the identifier exists, **not that
the dispatcher emits it**. One smoke test per event is the honest gate.

**(ii) One handler type out of five.** All 84 registrations are `type:"command"` — 100%. Four others are
settings.json-usable today and live in `2.1.114` (`prompt` ×156, `http` ×123, `agent` ×69, `mcp_tool` ×2):

- `type:"prompt"` — single-turn LLM evaluation. `type:"agent"` — multi-turn with tool access, 60s default, ≤50
  tool-use turns; CHANGELOG 2.1.118 confirms support on Stop/SubagentStop. Our judgment-in-bash Stop hooks
  (`completion-assert.sh`, `hooks/lib/close-shape.sh`, `operator-readout.sh`) are exactly what these are built for.
- `type:"http"` — **the shipped answer to the spawn tax**, and the top counter-proposal in the thread itself:
  *"the Python becomes a long-lived local service and the hook becomes a request to it… a smaller ask than
  `$.process`."* Zero dependence on #91870.

**(iii) The version hold now costs us a whole subsystem.** Our biggest hand-rolled wrapper class — waking an idle
session (`scripts/handoff-fire.sh` 10,622 LOC, `cc-notify`, `cc-await-ping`, `mailbox-wake-arm`, 10 files doing
keystroke injection) — **has an official entrypoint**: the per-session inbox socket
(`CLAUDE_CODE_MESSAGING_SOCKET` / `_TOKEN`, exported to hooks and Bash *before any hook runs, including
SessionStart*; *"When the receiving session is idle, Claude Code starts a new turn with the message"*).

It needs **2.1.224+**. Binary probe returns 0 hits on both `2.1.114` and `2.1.220`. `MANIFEST.jsonl` holds the
2.1.221–2.1.237 band on subagent-containment grounds (GH #84974, #85015, #85264). **The hold is a real tradeoff,
not an oversight — but its cost is no longer "missing changelog wins", it is keeping an entire hand-built
subsystem alive that the vendor has since shipped.**

### 2c. The one genuinely missing *field* (not entrypoint)

`context_window.context_window_size` / `used_percentage` are delivered **only to the statusline**
(`statusline.sh:63-65` reads them, `:133-137` writes them to `$CC_TELEMETRY_DIR`; 10 repo files read
`/tmp/cc-telemetry`). No hook event's documented input carries it — which is *why* CLAUDE.md § Context Stewardship
says the denominator is unrecordable. **This is a concrete upstream ask on an existing entrypoint**, not evidence
of an absent one.

### 2d. The SDK is not a migration path — on licence, not capability

The Agent SDK **already ships** #91870's headline feature: in-process TypeScript callback hooks (`HookCallback`,
`(input, toolUseID, {signal})`, `permissionDecision` / `updatedInput`, async mode, `canUseTool`). But:

> *"Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate
> limits for their products, including agents built on the Claude Agent SDK."* — agent-sdk/overview

Our economics is 4 Claude Max accounts routed by `bin/claude-accounts`. **An SDK rewrite converts subscription
quota into metered API spend.** Kill that option before it is raised. (Untested reading: the Note targets *third
party developers offering claude.ai login for their products*, which arguably does not describe one operator's
private harness. Do not rely on it without asking Anthropic.)

## 3. What #91870 would actually change for us — little, and it resolves none of our named ceilings

Adversarial verifier on the ceilings claim: **REFUTED**. The decisive structural fact is that the proposal changes
how a hook is **authored and composed** (a Koa fold over a capability object `$`), not what events exist or how the
harness schedules a turn. PDF §1: *"command, prompt, agent and http hooks hooks.json are kept running beside it."*

**Word census of the 10-page architecture PDF: `Stop` 0 · `session` 0 · `turn` 0 · `context` 0 · `close` 0 ·
`goal` 0 · `headless` 0.** The complete event vocabulary is `tool.call`, `ui.render`, `ui.resolve`, `ui.log`,
`ui.press`, `prompt.submit`, `engine.create`, `plugin.register`, `fs.read`. **There is no session-lifecycle noun
anywhere in the design.**

| Our documented ceiling | Would #91870 fix it? |
|---|---|
| **No whisper channel at Stop** (`final-response-shaping-2026-08-08.md`) | **No — wrong layer.** The constraint is the inference loop's re-entry (`additionalContext` = *"the conversation continues"*, capped at 8), not the hook substrate. A TS closure returns the same object into the same scheduler. The stash-and-deliver workaround **already runs here** — `mailbox-drain.sh` on UserPromptSubmit. |
| **Goal Stop-hook deletion** (`goal-in-handoff-2026-08-08.md`) | **No — harness bug at an untouched layer.** The Stop handler evaluates `Tio(taskRegistry.all())` then calls `sessionHooksRegistry.remove()`, re-adding in a `finally`. That is *host dispatch*; §2.3 governs ordering **among plugins** only. The goal hook is `type:"prompt"` — a type the PDF preserves unchanged. |
| **Unreachable renderer** (`CLOSE_INTEGRITY`, `systemMessage` dropped under `-p`) | **No — arguably reproduced.** §3.2.3 scopes rendering to declared surfaces — `"terminal"`, `"desktop"`, or an artifact's. **Headless is not a surface.** Meanwhile the *shipped* `MessageDisplay` hook is measured to reach the headless stream — 0 hits on 2.1.114, present on 2.1.220. **Gated on our pin, not on Anthropic.** |
| **Missing narrative tier** (`STOPHOOK_MESSAGE_TIERING.md`) | **No — not a vendor ceiling at all.** ~1,100 words routed to a `--why <topic>` flag *"that none of them wrote"*. The blocker is an unwritten flag in our own `bin/`. Filed `1031594b6327`, not started. |
| **Shell-fork cost** | **Mechanically yes; by our own measurement, not a ceiling.** `HOOK_CHAIN_COST.md` is `status:complete` — *"the broker is REJECTED and the collapse deferred on measured grounds"*: whole chain 0.054 cores mean, fork term ~8% of it, intervention ceiling ~0.03 cores. The in-process collapse **was built** (`hook-chain.sh`, 331 lines, landed inert) and measured **negative**: 174 ms serial vs ~180 ms dispatcher, and `validate-bash.sh` got **worse** under sourcing, 94→142 ms. ~81% of cost is externals *inside* a hook (24 externals on one `validate-bash.sh` call; one `python3` at 24.45 ms; **7.2 ms of unconditional jq+mkdir+date logging in the file's last four lines**, unfiled). |

Three numbers for the same quantity remain unreconciled: the proposal's self-reported **50 µs p99** (unshipped
prototype, no artifact), a commenter's measured **~90 ms per spawn**, and our own **~3 ms marginal / 3.08 ms
do-nothing floor / 67–677 ms for real hooks**.

### 3a. The fleet layer is structurally out of reach

Adversarial verifier: **SURVIVES**. Measured on disk: `bin` + `scripts` + `hooks` = 451 files / **208,617 LOC**.
Files touching fleet concerns (osascript, `it2-`, `ITERM_SESSION_ID`, `KITTY_WINDOW_ID`, `CLAUDE_CONFIG_DIR`,
`CC_ACCT`, launchctl, `git worktree`, handoff-fire) = **235 files / 147,396 LOC = 71%**.
`hooks/` — the only population #91870 targets — is **15.6%**. Even inside it, **43 of 73** top-level hooks
actuate the fleet.

Three independent grounds it cannot collapse:

1. **The caller changes language; the callee does not move.** `$.process` does not remove `osascript`, it dials it —
   at the same ~90 ms spawn the proposal exists to eliminate. Our 322 `scripts/`+`bin/` callees survive verbatim.
2. **No cross-session primitive.** PDF §4 nouns are *files, network, model, terminal, permissions* — no session
   noun, no session id on the event object, `$` built once at process startup. The stated invariant is the
   opposite of the attack: *"one session cannot authorise another."* Two fleet operators asked; neither got a reply.
   And §3.2.3 excludes pane placement by name: **"Plugins draw into surfaces; they do not provide them."**
3. **26 launchd daemons run with no session at all.** `boot-resume` exists precisely for the zero-sessions-after-
   reboot case. There is no `on('schedule')`.

Account/model/effort remain **launch-time env identity** (`CLAUDE_CONFIG_DIR` at exec; `--model`/`--effort` are
launch flags; `PreModelSwitch`/`PostModelSwitch` absent from both binaries). A hook inside a running process
cannot change its own account.

Note the attack's load-bearing affordance is also the least-evidenced thing in the proposal: **`$.process` appears
nowhere in the 10-page PDF** — only in one hedged forum reply, immediately followed by *"we're still designing what
goes on `$`"*, and a commenter argued against it with no pushback.

## 4. The dominant risk, if it ships and we adopt it

**In-process hooks would place 21,088 lines of our code inside `claude.exe` — the one process our shipped
anti-panic guard is contractually forbidden from touching.**

`scripts/compressor-sentinel.sh` excludes claude-shaped processes at **four independent layers** by design
(`:27`, `:36`, `:484-485`, `:544`, and the SIGKILL rung `:914-936` re-applies it). That exclusion is what makes the
guard safe — and it is exactly what would make a runaway function hook invisible and unactuatable. Today a runaway
hook is a separate shell process the sentinel can SIGSTOP and (since panic #5) SIGKILL.

`claude.exe` **already** has an unexplained self-burst class of exactly this shape: *54 processes exceeded 4 GB in
11 days, max 41 GB, ramping ~8 GB/min, cause unidentified* — invisible to the guard *because* the actuator
correctly exempts claude-shaped procs. Five watchdog panics on this machine trace to memory storms. Adding our own
code to that heap makes the class worse **and** ambiguous between harness and plugin.
*(Figure is from an 11-day window ending 2026-08-11 and was not re-derived; per the published-figure-decay rule,
re-measure before quoting it as current.)*

Secondary risks, ranked:

- **R2 — a rewrite is not on the table at any price.** Of the 66 wired hook scripts, **0 are portable logic**:
  60 use `jq`, 36 shell out, 26 git plumbing, 17 signal/trap, 12 `python3`, 10 `ps`/`pgrep`, 10 terminal control,
  3 sqlite3, 3 keychain, 2 launchctl. Behind them: 8,160 LOC of `hooks/lib`, 92,064 LOC of `scripts/`.
  **The only viable posture is additive adoption** — which makes R3 the load-bearing question.
- **R3 — coexistence is UNANSWERED, and it is the one question the author skipped while answering everything else.**
  Asked twice (*"does the existing shell-hook interface stay supported alongside this, or is this a migration?"*;
  *"how do command hooks and function hooks on the same event interleave?"*). Ten replies covering onion ordering,
  MCP coverage, `$.clock`, prompt-caching, static analysis and Bun p99 — **none on coexistence.**
- **R4 — it would break our version-decoupling.** Six binary silos (`~/.claude-{156,161,170,183,219,220}`) share
  **one** hook estate, possible only because the contract is JSON-on-stdin to an external process:
  `~/.claude/hooks` is 76 symlinks into this repo. A TS API typed against a binary's declarations makes hooks
  version-specific and forks the estate. *(Correction to the working assumption: all 20 live `claude` processes
  measured run from `~/.claude-220`, not the 2.1.114 the launcher reports.)*
- **R5 — the onion introduces a suppression surface shell lacks.** *"the plugin registered first owns all
  subsequent hooks… there is no capability for a plugin further down the chain to inhibit a plugin above it."*
  Our 16 PreToolUse deny guards (`keychain-guard`, `rm-safe-allowlist`, `validate-bash` 1,283 LOC,
  `git-worktree-guard`, `ship-rail-push-allow`, …) become suppressible — and a suppressed guard looks identical to
  one that caught nothing. Today no shell hook can prevent a sibling from running. Concrete vector: we have
  `officialMarketplaceAutoInstalled: true` and 3 installed plugins we chose neither the content nor the position of.
- **R6 — timeouts get weaker.** Our live budgets (PreToolUse 110s, Stop 75s, PostToolUse 95s) are *process* kills.
  On Bun's single-threaded loop a blocking hook cannot be preempted at all; the only recovery becomes killing the
  session. **Whether each plugin gets its own isolate/worker is unstated and is the single highest-value
  clarification available.**

**Dismissed, explicitly:** the `*` wildcard as a surveillance surface costs us nothing (sole admin, sole author,
one marketplace — Anthropic's own; an audit log in one function is a pure win). And *"`$` affordances could be
removed from us"* conflates capability grants with tool-surface churn — the real cited precedents (the injected
do-not-call-Agent line, `TeamCreate` vanishing between 2.1.114 and 2.1.178+, the 2.1.114 `/clear` regression) are a
different mechanism. The one caveat worth raising is that if capability removal ships gated behind enterprise
plans, a solo operator inherits the blast radius and the version coupling **without** the admin controls that
justify them.

## 5. What nobody in the thread has said

37 comments have saturated every argument about hooks that **constrain** — typed failure, structured args,
capability withholding, wildcard audit. Not one has raised hooks that **talk to the model**: the token cost, the
turn cost, or the measured fact that a model can refuse hook-injected context as prompt injection. That is the one
axis where this repo holds evidence nobody else brought
(`docs/research/final-response-shaping-2026-08-08.md`).

The second unsaid thing is §4's own risk: **in-process means the plugin shares the agent's crash and memory
domain**, and the mitigation an operator would need — one isolate per plugin — is unstated.

## 6. Actions this analysis implies

Ordered by cost. None were executed this session.

1. **Free, today, no upgrade:** smoke-test then wire the 15 present-but-unwired events. Start with the three that
   map to open tasks — `FileChanged` (#58/#74), `SubagentStop` (the hook is already written), `ConfigChange` (#70).
2. **Free, today:** move judgment-in-bash Stop hooks to `type:"prompt"`/`type:"agent"`, and collapse the spawn tax
   with `type:"http"` to a long-lived local service rather than waiting on `$.process`.
3. **Free, today:** delete the 7.2 ms unconditional jq+mkdir+date logger in `validate-bash.sh`'s last four lines —
   ~81% of hook cost is externals *inside* hooks, and this one is unconditional and unfiled.
4. **A real tradeoff, not an oversight:** re-price the 2.1.221–2.1.237 MANIFEST hold now that its cost includes
   keeping the whole hand-built wake subsystem alive against a shipped socket entrypoint.
5. **Upstream ask on an existing entrypoint:** add `context_window` to hook input schemas (Stop / PreToolUse).
6. **Operator's call — a public post under his identity:** the coexistence guarantee (R3) is the highest-leverage
   question for us and is the one the author has not answered; the model-facing-cost axis (§5) is the one thing we
   could say that 37 people have not.
