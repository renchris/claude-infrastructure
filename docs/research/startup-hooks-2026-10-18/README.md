# Startup hooks: synthesis of the 9-axis study (2026-10-18)

Scope: the SessionStart hooks (latency, model-token cost, no silent drops) plus the hooks that fire on
every turn. Inputs: the nine axis reports in this directory (A1-census.md … A9-beyond-startup.md),
each with a "Skeptic verdicts" section. Refuted findings are listed only under §6. Where a skeptic
amended a finding, this document uses the corrected version. Every number is tagged **[M]** (measured;
the command or script is named, usually in the cited axis section) or **[E]** (estimated; the method
is named). Read-only synthesis: no hook was run for it.

---

## 1. Answer

1. **Stop walking 18,258 project folders at every start.** On the three accounts whose `projects/` folder is their own (secondary, tertiary, quaternary: 52% of starts [M, A1 §8]), the knowledge-layer mirror (`lib/config-mirror.zsh`) visits every project slug on every start. 17,446 of the 18,258 slugs (95.6%) are throwaway temp-dir slugs from headless runs [M: `ls ~/.claude/projects | rg -c '^-private-(var-folders|tmp)'`, 13:37Z]. Excluding them inside both globs is a one-function change (effort S, no settings edit). A per-slug `case` skip in the loop is not equivalent: it still globs and hashes all ~18.9k entries and keeps 50-86% of the walk [M, gap-G1]. Measured effect of the exclusion: the walk falls from 1.7-7.3 s to 0.3-0.9 s at load ~100-135, and the pending link and adopt forks (all of them in temp slugs) go to 0 [M, A8 replica + gap-G1]. Expected effect [E, an upper bound until the #14 ledger confirms it]: the dispatcher's median on those accounts falls from 7.4-9.2 s to about 3 s. That is 4-5 s less wait for the first response at p50 on those accounts (about 2.3 s across the fleet), and the fleet p95 falls from about 10.4 s toward about 7 s. Up to ~76 of the ~80 real child kills per 2 days go away [E: 80 × 88/93 isolated share of ≥9 s runs], and every shell launch on those accounts gets 1.4-6.4 s faster at load ~130 [M, gap-G1].
2. **Make the dispatcher loud and stop it losing late output.** Seven exits in `hooks/session-start-dispatch.sh` drop output and record nothing. Each should name what was lost in the operator-visible `systemMessage`. Each child's outcome should go to a ledger. The dispatcher should print by a deadline and let late children finish instead of killing them. Cost: 0 model tokens on a healthy start.
3. **Report harness cancels, and put the report where the operator looks.** Claude Code 2.1.293 shows nothing in the terminal when it cancels a SessionStart hook [M: `rg -a` over the live binary], which is exactly the 05:49Z incident. Fix (#8): each own startup hook writes a start/done marker, and the first-prompt hook flags any *possible* loss (no done marker, any non-zero rc, or a finish at the timeout with output owed). The session's own transcript is the authority: a detached reader confirms or clears each possible loss from its `hook_cancelled` records, and it also names foreign project hooks, which have no marker [M, gap-G3]. Each confirmed loss gets a line naming what was lost and a recovery command, usually at the second prompt, because the transcript does not exist yet at the first [M, gap-G3]. About 94% of own-hook startup drops happen in panes no person is shown to watch [M, gap-G4], so #8 also folds them into one 0-token line on the accounts board. That line shows at every start until it is acknowledged. This covers 56-64 invisible cancels per 2 days [M, A1/A5/gap-G3], with no settings edit. Phase 2 covers the 1,618-1,842 invisible per-turn kills per 48 h [M, A9]. For idle panes, an optional c10 FileChanged hook on an alert directory can push a 0-token terminal notice plus a tab bell within about a second (#13a). That rests on a static read of the binary; its scratch probe has not been run [gap-G2].
4. **Tokens.** Startup model context can go from 3,622 to about 700 chars per start (−80%), which is about 730-1,170 tokens per start [E: chars ÷ 2.5-4]. Two changes do most of it: the DoD (definition of done) hook's history body becomes a one-line pointer, and five one-liners stay silent unless they carry news. At about 205 starts a day that is about 150-240k cache-write tokens and 10-16M cache-read tokens per day [E]. On the per-turn side, a stale "goal skipped" crumb and the memory nudge cost another 145-250k tokens a day [E].
5. **Two correctness bugs.** (a) mailbox-drain answers a `PostToolUseFailure` call with the wrong event name, so 12 peer messages in 48 h were marked delivered but never reached the model [M]. (b) pre-session-validate turns load into a false "no working version" alarm on 5.7% of starts and keeps a dormant rollback switch that a timeout could trigger [M].
6. **Operator-only settings edits (class c10).** Raise the dispatcher's registration timeout from 12 to 20 s. Optionally register a FileChanged hook on a startup-alert directory once its scratch probe passes (#13a), raise TeammateIdle from 5 to 20 s, and apply staged migration 0012 after re-probing it. Do not add `statusLine.refreshInterval`: across 46 sessions it would cost about 51 execs/s and 0.26 cores at a 10 s interval [E, gap-G2]. No other change in this document touches `settings.json`. The reso-management-app hook fixes (#14a) are that repo owner's call.

**Terms used below.** *Dispatcher*: `hooks/session-start-dispatch.sh`, one SessionStart registration that runs 10 child hooks in parallel and merges their output. *Isolated accounts*: `~/.claude-secondary`, `-tertiary`, `-quaternary`, which list `projects` in their isolate set (`lib/config-mirror.zsh:46-48`). *Shared accounts*: `~/.claude` and `~/.claude-next`, which share one `projects/` folder. *First response*: the first model reply. The harness holds it until every sync SessionStart hook has ended (0 of 372-383 first replies came earlier [M, A1 §2.4, A6 F2]). *systemMessage*: the top-level hook output key. It renders in the terminal as `<hook> says: …` and maps to nothing for the model [M: `rg -a 'hook_system_message:\(\)=>\[\]'` and the render case, 2.1.293 binary]. *additionalContext*: hook output that goes into model context (billed, and re-read on every later request). *IDL*: the hook disposition ledger `~/.claude/autonomy/idl.jsonl`, written by `hooks/lib/idl-log.sh`. *UPS*: the UserPromptSubmit event. *c10*: a `settings.json` edit, which only the operator may apply. *Score*: impact (1-5) × conviction/100 ÷ effort (S=1, S–M=1.5, M=2, L=3).
