# /handoff self-recycle at the 100th percentile — clear-vs-exit, the injection window, mangle detection

**Date:** 2026-08-22 · **Goal session:** 7121d711 · **Binary under test:** 2.1.220 (the eval track every live session runs; stable `claude-latest` pin is 2.1.114 and — measured today — **2.1.114 has no `/goal` built-in at all**: a typed `/goal` returns `Unknown command: /goal`).

**Question (operator, verbatim intent):** when self-recycling into the same repository/account, are we optimally using `/clear` + initial prompt + `/goal` composer injection instead of `/exit`? Can the user-input-field injection window be shrunk so an actively-typing operator can't mangle it? Can a mangle be detected and retried gracefully instead of waiting for the operator to spot it?

**Answer in one line:** `/exit`+relaunch remains the right spine (measured, below) — but the recycle was NOT 100th-percentile: the injection chain had one ungated keystroke (`/exit` into a possibly-drafted composer, **~1.25 mangles/day, ≥8 operator messages swallowed in 24 days**), one unverified paste (`/goal`, blind CR), blind CR nudges that can submit a merged draft, and two silent failure branches. This land closes those; `/clear`-recycle and goal-at-launch are parked below with their evidence.

## 2. Measured facts

### 2.1 Queue semantics (the catnav asymmetry), re-verified

| Input | Idle session | Mid-turn (turn running) |
|---|---|---|
| plain text + CR | starts a turn | **enqueued** (`queue-operation` transcript records exist on 2.1.114+) and **steered into the running turn** at the next tool boundary — P1b re-confirmed live on 2.1.114: SENTINEL answered mid-turn |
| `/clear` + CR | executes: **new conversation id** (new sid jsonl on disk, P1a@114; `clearConversation` yields `conversation_reset` + rewrites `CLAUDE_CODE_SESSION_ID`, binary read @220) | **enqueued — and on 2.1.114 it then never performed at all** (no rotation, silently dropped). Worse than hold-to-turn-end. |
| `/exit` + CR, **empty composer** | exits | **interrupts in seconds** (E2E 2.1.183/2.1.207; corpus: zero exact-`/exit` enqueues in 60 days ⇒ no observed case of an empty-composer `/exit` queueing) |
| `/exit` + CR, **composer holds a draft** | — | **merges with the draft into one text message** — `/exit` never executes; the hybrid submits/enqueues and steers into the turn. **30 events / 24 days; ≥8 swallowed a real operator message.** |

### 2.2 `/clear` internals (binary read, 2.1.220 `clearConversation`)

Runs `"clear"`-source hooks · wipes messages · new conversation id (old session recorded as PARENT; aliases `/reset` `/new`; optional `[name]` arg) · kills foreground tasks but **preserves backgrounded ones** · keeps MCP clients (ide cache cleared) · **restores the original launch cwd** · resets file-history/task counters · **and resets `activeGoal:void 0` — a live goal DIES at `/clear`** (binary read of the AppState reset object; docs concur). Fast: P1a@114 measured `/clear`→next-reply-complete at 7.5s. Corpus census (39 real `/clear` invocations, 2.1.219/220, four account roots): always a NEW session file, `SessionStart:clear` hook outputs at the top of the new file, old file simply stops; the only mid-turn `/clear`s that executed immediately followed a user interrupt. **Queue hazard measured on 220**: a `/clear` typed mid-turn was enqueued, then folded to the MODEL 5s later as a `queued_command` text attachment — the reset never executed and the session ran on for 548 more lines.

### 2.3 `/goal` internals (2.1.220; wave agents, binary reads + corpus)

- Harness built-in; **the live goal is process memory** (`appState.activeGoal` + session hooks registry). The Stop path never re-reads disk; the transcript's `goal_status` attachments are a write-through trace.
- **A goal dies with its session AND at `/clear`** (measured; `activeGoal:void 0` in the clear-path reset) — and an UNMET goal **survives `--resume` of the same sid** (measured on 220: `seedActiveGoal ← lastActiveGoal`, backward transcript scan; a resumed 1-turn prompt ran 3 turns under the re-seeded goal; achieved/cleared goals are not restored; the `--resume` PICKER route doesn't restore until 2.1.239 per changelog).
- **The CLI parses a leading `/goal` out of the initial prompt itself** — goal armed pre-model (measured, session fdb33b93; re-measured this session: `claude -p "/goal <cond>"` armed headlessly, sentinel `goal_status` at set time, evaluator ran, $0.045). No `--goal` flag or env exists on 2.1.220 (help sweep + binary grep: 0 hits). An under-cap `/goal` returns a query that starts the session working the condition as its directive. Whole submission = the condition (4000-char cap ⇒ pointer form).
- P1a@220 screen: goal-set immediately drove a turn; unmet reply was blocked (`◯ Goal not yet met… continuing`), model self-corrected, `✔ Goal achieved (18s · 3 turns · 528 tokens)`.

### 2.4 Composer mechanics (P2, 2.1.220, screen-level)

1. A draft typed without CR **is readable back** from the screen; a bracketed paste before CR is too — **read-back-verify before CR is feasible** (proven end-to-end: paste `/goal …` → verify on screen → CR → armed).
2. Paste into a non-empty composer **appends to the draft** — the mangle shape.
3. **Neither Ctrl-U nor Esc clears the composer** — there is NO safe programmatic scrub. (Ctrl-C/Esc double as turn-interrupt — forbidden from automation.) The shell path's scrub-and-retype discipline (`cc-type-verified.sh`) does NOT port. Composer protocol must be: **paste only into a proven-empty composer; CR only on exact read-back proof; on any mismatch, touch nothing and escalate.**

### 2.5 Production rates (fire ledger `~/.claude/logs/handoffs.jsonl`, 3.5-day window + 60-day corpus)

- ~45 recycles/day; 160 intents → 158 engaged (98.75%). p50 intent→engaged 31s (p90 41s); `/exit`→shell p50 6s; relaunch-typed→engaged p50 10s.
- **Both failures emitted zero outcome rows** (`:5289` relaunch-failed branch exits without `emit_recycle_event`; a stranded pane is ledger-invisible).
- `/goal` arm: 218 rows — 214 set (98.2%), 2 unverified, 2 unreachable, 0 abstained. Goal-carrying recycles: 86.7% (inheritance working).
- Machinery typed a shell command into a LIVE composer: 3 incidents / 60 days (`hfv-` nonce visible in transcripts).
- Ledger self-trims at 1200→1000 rows (~3.5-day window); older verdict splits are unrecoverable.

## 3. Verdict on the operator's three questions

**Q1 — should same-repo/same-account recycle use `/clear` instead of `/exit`+relaunch? NO (for now).**
The `/clear` path is real and fast (§2.1-2.2: rotation, clear-source hooks, 7.5s) — but it *increases* the composer-injection surface (typed `/clear` + pasted brief + typed `/goal` = 3 composer injections; today the brief rides argv and only `/goal` touches the composer), it requires idle-gating (a mid-turn `/clear` can be silently LOST, §2.1 — and a self-initiated recycle is mid-turn by definition, so a detached idle-waiting watcher is still needed), it cannot re-pick account/model, cannot pick up a deployed binary, keeps process memory high-water, and leaves goal-across-clear semantics unresolved. The latency win (~7s vs p50 31s) buys nothing during an unattended succession, which is when recycles fire. **The 100th-percentile move for the injection window is the opposite direction: fewer composer keystrokes, each proof-gated — not a second recycle mode.** Parked, re-openable if a future binary changes the queue asymmetry (re-measure with the P1 probes; they are version-pinned instruments now).

**Q2 — shrink the injection window. Implemented as gates, not speed.**
The window cannot be made zero-width while keystrokes exist; it CAN be made collision-proof: (a) `/exit` is now typed only into a **proven-empty composer** — a held draft makes the recycle WAIT (bounded, escalating) instead of destroying the draft (~1.25 mangles/day → structurally 0); (b) CR nudges only fire when the composer provably holds exactly the stranded `/exit`; (c) the `/goal` paste pastes only into an empty composer and CRs only on exact read-back proof.

**Q3 — detect + gracefully retry + surface. Implemented.**
Every abstain/mismatch now emits a ledger row (incl. the previously silent `:5289` branch) and escalates via `cc-notify` into the affected session — in-band context, never keystrokes — naming what was seen and the exact one command to run if a human must finish. A merged-draft detection quotes the operator's own text back so nothing they typed is lost.

## 4. Parked options (evidence attached, deliberately not built)

- **Goal-at-launch (`/goal`-headed argv):** arms pre-model, zero composer injection, kills the 45s arm-verify tail — but the whole submission becomes the condition (pointer form only), the rich brief leaves message 1, and `check_slash_head` currently (correctly) refuses `/goal`-headed payloads from users. Re-open if a `--goal` CLI flag appears (none on 2.1.220's `--help`) or arm failures resurface after this hardening.
- **`/clear`-based same-everything recycle:** §3 Q1. The P1 probe harness re-measures its premises in minutes on any new binary.
- **Forged `goal_status` + `--resume` arming:** would work per `restoreGoalFromTranscript` (inferred, unprobed) — rejected: writes into a binary-owned store, fragile across versions.

## 6. Side-findings filed

- `CLAUDE_CODE_CHILD_SESSION` inheritance silently disables transcript persistence on 2.1.220 probe children (§1) — any headless probe/harness spawning `claude` from inside a session must strip it (backlog).
- 2.1.114 (`claude-latest` stable pin) lacks `/goal` entirely — any tooling that assumes goals exist must not run against the stable pin (it doesn't today; recorded so a future stable-track consumer doesn't rediscover it).
- Fire-ledger 3.5-day self-trim makes month-scale rate questions unanswerable from the ledger alone (class-level trim rows survive; verdict splits do not).
