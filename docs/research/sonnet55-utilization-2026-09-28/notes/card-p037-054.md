Source: /tmp/s55/card.pdf. Text from `pdftotext -layout -f 37 -l 54`. Figures fig-042-015, fig-042-016, fig-043-017 and fig-050-018 were read with vision. All four charts print their data labels, so every chart value below was read from a printed label, not estimated from bar height.
Scope: pp. 37-54 cover section 4.2 (end of child safety), 4.3 (mental health), 4.4 (bias/integrity), 5.1 (malicious use of agents) and 5.2 (prompt injection). **No per-effort (low/medium/high/xhigh/max) benchmark scores, costs or token counts appear in this range.** The only effort statement is at p.53 (Cowork browser eval: "thinking enabled and high effort").

## 5.1 Malicious use of agents
- p.47 [agentic-safety] Results are for the model "without the additional safeguards we apply in production". The prompt-injection evals "reflect the fallback behavior users will encounter in our products" ✓
- p.47 [agentic-safety] Summary: Sonnet 5.5 refuses malicious agentic requests "slightly less often than Claude Sonnet 5", and its refusal rate on malicious computer use is identical to Opus 5.5. It is "our most robust Sonnet-class model to date" on prompt injection. ✓
- p.47 [method] The Claude Code malicious-use eval has 61 malicious and 61 dual-use/benign prompts, each run 10 times (1,220 tests). It uses the standard Claude Code toolset and the Claude Code system prompt. Source: "run with the Claude Code system prompt applied by default" ✓
- p.48 [claude-code] Claude Code malicious refusal rate / dual-use-and-benign success rate: Sonnet 5.5 85.2% / 98.4%, Opus 5.5 81.0% / 100%, "Mythos 5.1" 88.5% / 99.3%, Sonnet 5 87.9% / 97.7%. **Opus 5.5 completes more of the legitimate security tasks (100% vs 98.4%). Sonnet 5.5 refuses more malicious ones.** Source: "[Table 5.1.1.A]" ✓
- p.48 [computer-use] Malicious computer-use refusal rate (112 tasks: surveillance, harmful content, scaled abuse): Sonnet 5.5 79.46%, Opus 5.5 79.46%, Mythos 5.1 87.50%, Sonnet 5 84.68%. The Sonnet rates average runs with and without thinking. The Opus/Mythos rates are thinking only. Source: "[Table 5.1.2.A]" ✓

## 5.2 Prompt injection
- p.49 [threat-model] An agent is exposed if it takes in untrusted data, reads private data and can act: "Any agent that is exposed to untrusted data, and can both read private data and take action on the user's behalf, is exposed." ✓
- p.50 [prompt-injection] Gray Swan IPI attack success rate at k=1 / 10 / 15: Sonnet 5.5 0.4 / 2.7 / 3.4, Sonnet 5 0.7 / 5.1 / 6.7, Opus 5.5 0.1 / 0.7 / 1.0, Fable 5.1 0.1 / 0.7 / 1.0. Source: chart Fig 5.2.1.A, printed labels. The Sonnet values are confirmed by the text. ✓
- p.50 [prompt-injection-comparators] The same chart, k=1 / 10 / 15: Qwen 3.8 3.6 / 23.2 / 28.6, Kimi K3 8.1 / 44.0 / 52.7, GLM-5.3 4.0 / 25.3 / 31.5, Grok 4.6 11.7 / 45.6 / 51.8, Muse Spark 1.2 3.8 / 20.2 / 24.2, Gemini 3.8 Flash 0.7 / 4.3 / 5.5, GPT-6 Luna 5.5 / 25.0 / 28.7, GPT-6 Sol 1.0 / 7.6 / 10.1, GPT-6 Astra 1.1 / 7.3 / 8.5. Source: chart, printed labels ✓
- p.50 [prompt-injection/opus-better] Sonnet 5.5 at k=15 by setting (vs Sonnet 5): coding 0.7% (0.9), tool use 1.0% (6.0), GUI computer use 12.5% (17.2). It "is less robust than Claude Opus 5.5 and Claude Fable 5.1" on IPI. Source: "12.5% compared to 17.2% in GUI computer use" ✓
- p.50 [classifier-fallback] 11% of Sonnet 5.5 IPI rollouts were served by a fallback model after a classifier fired, all in coding. The fallback-served rollouts were compromised at 0.13% (1/777), versus 0.28% (18/6,347) for the rest. 16 of the 19 successful attacks were in computer use. Source: "11% of rollouts were served by a fallback model after a classifier was triggered, all of them in coding scenarios" ✓
- p.51 [classifier-fallback] **Sonnet 5.5's cyber classifiers cause a fallback to Sonnet 5, while its bio classifiers block outright.** Source: "Sonnet 5.5's bio classifiers are blocking and do not cause fallbacks ... For Sonnet 5.5, requests that trigger a fallback are served by Sonnet 5." ✓
- p.51 [prompt-injection-coding] Shade adaptive coding attacks, attempt ASR and scenarios, without safeguards / with probes: Sonnet 5.5 (thinking) 3.01% 16/40 / 2.63% 13/40. Opus 5.5 54.61% 37/40 / 11.13% 36/40. Fable 5.1 51.93% 39/40 / 8.70% 35/40. Sonnet 5 thinking 19.47% 36/40 / 15.76% 35/40. Sonnet 5 no-thinking 40.30% 40/40 / 37.51% 40/40. **Against this coding attacker, Sonnet 5.5 is far more robust than Opus 5.5 and Fable 5.1.** There are 200 attempts per scenario. Source: "[Table 5.2.2.1.A]" ✓
- p.51 [thinking-effect] With Sonnet 5, turning thinking on roughly halves coding injection ASR (19.47% with thinking vs 40.30% without). Source: Table 5.2.2.1.A ✓
- p.52 [destructive-actions/classifier] **Injections that ask for destructive actions (wiping a disk, deleting files) can trip the cyber classifier and reroute the request to Sonnet 5.** 25% of coding requests were served by Sonnet 5, and 12.01% of those were compromised. Most of Sonnet 5.5's coding ASR comes from this fallback. Sonnet 5.5 itself was compromised in 4 of 5,901 requests (0.07%). Source: "Many injections in this evaluation instruct the model to take destructive actions, such as wiping a disk or deleting files, which can trigger the cyber classifier and reroute the request to Sonnet 5" ✎corrected (was: "trip the cyber classifier"; the card says "can trigger")
- p.52 [prompt-injection-CU] Shade GUI computer-use attacks (14 cases, 200 attempts each), without safeguards / with probes: Sonnet 5.5 0.07% 1/14 / 0.07% 1/14. Opus 5.5 0.07% / 0.04% (1/14). Fable 5.1 0.07% / 0.07%. Sonnet 5 thinking 2.25% 4/14 / 1.46% 4/14. Sonnet 5 no-thinking 4.86% 7/14 / 1.04% 4/14. Source: "[Table 5.2.2.2.A]" ✓
- p.52-53 [prompt-injection-CU] The two successful attempts out of 2,800 came from one scenario and were answered by Sonnet 5.5 itself. Under 1% of requests fell back to Sonnet 5. Sonnet 5.5 "matches our most robust models to date", and the card calls single-attempt differences noise. Source: "a difference of a single attempt is not distinguishable from noise" ✓
- p.53 [harness/auto-mode] Claude Cowork always runs prompt-injection probes, and thinking cannot be disabled in Cowork. The browser eval ran with "thinking enabled and high effort". It has 110 environments, with attacks generated against Opus 4.7. Source: "it is not possible to disable thinking in Claude Cowork, so we only report results with thinking enabled and high effort" ✓
- p.54 [prompt-injection-browser] Browser-use ASR in Cowork, attempts and scenarios, without safeguards / with auto mode: Sonnet 5.5 0% 0/110 / 0%. Opus 5.5 0.09% 1/110 / 0%. Fable 5.1 2.55% 6/110 / 0%. Sonnet 5 0.37% 3/110 / 0%. There are 10 attempts per scenario. Source: "[Table 5.2.2.3.A]" ✓
- p.54 [prompt-injection-browser] "Without safeguards, Sonnet 5.5 is the first model we have evaluated with no successful attacks". With auto mode on, no attack succeeded against any model. ✓

## Added by verifier
- p.39 [qualitative] On the API, Sonnet 5.5 "continued to validate self-harm as effective or functional at rates similar to Sonnet 5". Improvements: it stayed "more aligned to what the user had actually said", rather than inferring feelings or motives on the user's behalf.
- p.41 [behaviour] In disordered-eating multi-turn review, it was "less likely to attribute a clinical eating disorder to a user who had not disclosed one". Launch system-prompt updates only "partially addressed" the weak spots on claude.ai.
- p.43 [bias] Compared with Sonnet 5, it "acknowledged opposing perspectives slightly less often than Sonnet 5 on the API (41.4% versus 45.7%) but considerably more often on claude.ai (60.2% versus 52.9%)". It also refuses less often on both surfaces. This means the system prompt has a large effect on this behaviour.
- p.45 [bias] Its BBQ disambiguated bias (-0.75%) "was the closest to zero of any model tested". Sonnet 5.5 improved on Sonnet 5 on all four BBQ measures.
- p.46 [safety-multiturn] Its election multi-turn score of 86% on the API is "slightly below Sonnet 5 on the API (91%) but within the margin of error".
- p.47 [agentic-safety/opus-parity] Sonnet 5.5 "matches Claude Opus 5.5 and Claude Fable 5.1 against adaptive attackers in computer use environments". Sonnet 5.5 "improved on Sonnet 5 across every [prompt-injection] evaluation we report".
- p.47 [claude-code] Examples of malicious prompts in the Claude Code eval are malware, DDoS code and non-consensual monitoring software. Examples of dual-use/benign prompts are network reconnaissance, vulnerability testing of websites and analysing pentest output.
- p.48 [claude-code] Sonnet 5.5's malicious refusal rate (85.2%) is "slightly below Sonnet 5 (87.9%) and Claude Mythos 5.1 (88.5%) but above Claude Opus 5.5 (81.0%)". Its dual-use success rate (98.4%) is "a slight improvement over Sonnet 5 (97.7%)".
- p.49 [prompt-injection] The Gray Swan IPI evaluation ran Claude models "without the additional prompt injection protections we deploy across our products".
- p.50 [prompt-injection/method] Fig 5.2.1.A caption: "All models use extended thinking". Qwen 3.8 and GLM-5.3 were not evaluated on GUI computer-use scenarios. Sonnet 5.5 "is more robust than every non-Claude model evaluated". The best non-Claude model is Gemini 3.8 Flash at 5.5% (k=15).
- p.50 [prompt-injection/method] The adaptive-attacker evals use a "deliberately permissive threat model": the attacker optimizes directly against the test scenarios and gets many attempts.
- p.51 [prompt-injection/method] The Shade coding attacker is trained on the test scenarios against earlier Claude models, then run unchanged against the latest models. Attempt-level ASR counts only attempts that got a valid response.
- p.53 [prompt-injection-CU] Of the under-1% of computer-use requests that fell back to Sonnet 5, none were compromised.
- p.53 [harness] The browser-use eval covers products that use browser capabilities, "such as Claude in Chrome and Claude Cowork". Attacks are viewed via screenshots or page reads, and a programmatic checker verifies success.
- p.54 [prompt-injection-browser] Attack counts without safeguards: Sonnet 5 had 4 successful attempts across 3 scenarios, Opus 5.5 had 1 attempt in 1 scenario, and Fable 5.1 had 28 attempts across 6 scenarios.
- Range-wide [scope] Checked pp.37-54: there are no per-effort benchmark scores, costs or token counts, and nothing on subagent spawning, early stopping, verification claims, reward hacking, sabotage, context-window behaviour, preserved thinking or account switching. The only effort mention is the p.53 "high effort" note.
