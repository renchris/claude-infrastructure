# `bench/` — the design-review perception pipeline, and the instrument that grades it

One command runs the whole thing:

```bash
bash bench/run.sh
```

It builds the corpus, captures it, runs both deterministic layers, routes the
abstentions, and exits non-zero if the false-positive budget is breached. On a
machine with a pre-provisioned browser, point it at the binary:

```bash
BENCH_CHROMIUM=/opt/pw-browsers/chromium-1194/chrome-linux/chrome bash bench/run.sh
```

Findings, the route plan and the crops land under `corpus/out/`. Everything there
is derived — `build_corpus.py` plus `manifest.json` are the source of truth, and
regenerating is the one command above.

## The stages, and what each one is for

| | Stage | Reads | Writes |
|---|---|---|---|
| 1 | `corpus/build_corpus.py` | — | `pages/*.html`, `manifest.json` |
| 2 | `capture.py` | the pages | `shots/*.png` + `snapshots/*.json`, **one browser pass** |
| 3 | `detect_dom.py` | the snapshot | `findings_dom.json` — nine rules and an `INDETERMINATE` verdict |
| 4 | `detect_xcheck.py` | the snapshot **and** the shot | `findings_xcheck.json` — three checks that fire only where the two disagree |
| 5 | `route_abstain.py` | both findings files | `route_plan.json` + `crops/` — the vision layer's job queue |
| 6 | `fp_budget.py` | both findings files | the gate: exit 1 on any false positive |

Stage 2 takes the screenshot and the snapshot **in the same pass** on purpose. A
pixel finding and a DOM finding have to be arguing about one frame, or every
disagreement between them has a "maybe the page moved" escape hatch and the
cross-check in stage 4 means nothing.

## Where the current numbers come from

Measured 2026-08-27 on this corpus, at capture scales 1 and 1.5, identical at both:

| Layer | DOM-determined | Pixels-only | False positives on the control |
|---|---|---|---|
| `detect_dom.py` | **9 / 9** | 0 / 3 (2 honest abstentions) | **0** |
| `detect_xcheck.py` | — | **2 / 3** | **0** |
| routed to a model | — | 1 / 3 — `hierarchy-inversion`, and only that | — |

The third pixels-only defect is the one no rule can state: whether the eye lands
on the action the page wanted. It reaches the vision layer through T2, not through
any finding, which is the whole reason T2 is unconditional.

## The four rules this pipeline is built to keep

**If the answer has a number in it, a model does not get the question.** Distances,
gaps, sizes, ratios, contrast — solid *or* gradient — token membership, and every
bounding box. `getBoundingClientRect` returns exactly what a model would estimate,
for free, with no hallucination risk.

**An abstention is an output, not a gap.** `contrast-indeterminate` is the
deterministic layer naming where it stopped being able to see. Every silent pass
that should have been an abstention is a defect shipped, and the abstention set is
exactly what makes the vision spend small enough to afford.

**The subtraction is code, not discipline.** The vision queue is
`INDETERMINATE − resolved_by(xcheck)`, and it is gated on the cross-check file
existing — a missing findings file resolves nothing *and looks exactly like nothing
needing resolution*, so the queue GROWS under a cross-check outage. That is the one
place where a bigger model queue is the right response to a layer failure.

**Zero on the control is the precondition for every other number.** `fp_budget.py`
is the gate, not a habit: a new rule is re-run against `clean.html` before it ships,
and the exit code is what enforces it. Twice the control has turned out not to be
clean — three WCAG failures, then a backwards optical-compensation constant — and
both times the fix was to the CONTROL. Widening a tolerance until the complaint
stops blinds the rule to the defect it exists for.

## Per-app weightings

`profiles.json` holds them, and holds **policy only** — no framework, no version,
no token map, no fact about any app's stack. `PIPELINE_SPEC.md` C11 is a table that
banned prose as a source and then published three unmeasured cells of its own; the
ruling was that stack facts are generated by reading the checkouts, never written
down. So availability is expressed as a *requirement* (`requires: ["token-map"]`)
rather than as a claim, and the router reports those classes `UNVERIFIED` when the
run cannot supply the input. A conformance rule with no token map did not find zero
drift — it did not run, and a silent zero there is indistinguishable from a pass.

```bash
python3 bench/route_abstain.py bench/corpus/out --profile reso-landing-app
python3 bench/route_abstain.py bench/corpus/out --profile reso-management-app
```

On this corpus the two disagree about eight findings. `reso-landing-app` — a
purchased template, judged as marketing — demotes the conformance findings and
keeps all five correctness ones; `reso-management-app` — ours, authored against
tokens we own — surfaces every one. Demoted is **never** deleted: the count prints,
and each demotion carries the profile and weight that caused it, because a
weighting that could hide a finding is a way of tuning a page green.

## What this pipeline does not see

`hierarchy-inversion` is in the corpus precisely because nothing here can find it,
and it is not the only one of its shape. Content-fit, gestalt, semantic coherence
and readability are routed unconditionally for the same reason. The June 2026
ruling stands and this work does not reopen it: **the vision layer is advisory
triage, never a CI gate.** Taste stays human; these rules adjudicate correctness
and coverage only.
